## 0. 요약

### 0.1 한 줄 결론

시장 제품은 크게 두 얼굴이다 — **사무 화면은 밝은 테마 + 왼쪽 메뉴 + (국내는) MDI 탭 + 조회조건·그리드·상세**, **현장 화면은 큰 버튼·큰 숫자·한 화면 한 주동작**. 이 뼈대는 YeonOS 가 이미 같다. 차이는 **"규칙의 마감"**에 있다: ① 설비 상태색의 의미를 한 곳에 고정(MachineMetrics 는 같은 제품 안에서도 대기·준비 색이 화면마다 다르다), ② 알람은 색 + 모양 + 글자, ③ 화면 종류별 밀도를 섞지 않음, ④ 목록 화면 부품(그리드·조회 패널·버튼 위치)을 하나로. YeonOS 는 토큰(12 V1)은 시장 평균보다 앞서 있지만, **12 에서 채택해 놓고 아직 안 들어간 것**(Pretendard·아이콘·POP 회색 바탕·메뉴 현재 위치 표시)과 **화면마다 다른 목록 부품**(hb.grid 와 일반 표 혼용)이 인상을 깎는다.

### 0.2 핵심 제안 5개 (7장에 전체)

## 3. 공통 패턴 (해외·국내 종합)

1. **사무 = 라이트, 관제·HMI = 다크 또는 회색.** iX 만 다크 기본, 업무 MES(Fiori·MESplus)는 라이트. "국내 모니터링 = 다크 네이비"는 공개 자료로 확인 못 함 — 확인된 국내 캡처는 연회색 바탕 흰 카드다. 다크는 대형 전광판·사이니지 쪽 [추정].
2. **셸은 수렴했다**: 짙은 머리띠(국내는 네이비) + 세로 왼쪽 메뉴 + 메뉴 검색. 국내는 **MDI 탭**이 사실상 기본, 해외는 탭 대신 열(Fiori FCL)·페이지 이동.
3. **업무 화면 = 조회조건 → (KPI 숫자 타일) → 그리드 → 상세/실행 버튼.** 국내는 상세를 팝업(겹 팝업까지), 해외는 옆 열·객체 페이지.
4. **밀도는 화면 종류별로 하나**: 사무 32px 안팎(compact), 터치 44~48px, HMI 버튼 40px 이상, 장갑 단말 15~20mm. 한 화면에 섞지 않음(Fiori 명시).
5. **상태색 4~6단을 토큰으로**, 각 단에 진한 전경·연한 배경 짝(iX·Horizon). 상태색을 본문 글자색으로 쓰지 않음(iX).
6. **설비 상태는 3~5단계** — 가동·대기·준비·정지(계획/비계획)·통신 끊김. 국내·Tulip·안돈은 **가동 = 초록**, ISA-101 계열 HMI 는 **정상 = 회색**. 두 관례가 공존한다.
7. **알람은 색만으로 말하지 않는다**: 모양 + 우선순위 숫자/글자 + (미확인이면) 깜빡임.
8. **같은 제품 안의 색 불일치는 실제로 생긴다**(MachineMetrics). 의미 사전을 문서·토큰으로 고정해야 한다.
9. **현장 화면은 한 화면 한 주동작**: 주버튼만 가장 진한 색, 큰 숫자, 짧은 단계, 같은 아이콘 = 같은 뜻(Tulip). 국내는 큰 버튼 + 바코드 스캐너 중심.
10. **화면 조립·테마 교체가 표준 기능**(Critical Manufacturing·Tulip·Apriso·POD 2.0) — 토큰이 있어야 조립해도 일관된다.
11. **회사 글꼴은 그 회사 전용**(Siemens Sans·SAP 72). 산업 가이드는 중립 산세리프 + 숫자 굵게·오른쪽 정렬.
12. 국내 공개 자료는 **시각 규칙(토큰·상태 표시·접근성)을 거의 공개하지 않는다** — 12 1.8 관찰과 같음. 차별화 여지.

## 5. 차이 — 시장 패턴 vs YeonOS (화면 테스트 세션 관찰 포함)

### 5.1 이미 같은 것 / 앞선 것

- 셸 구성(남색 머리띠 + 왼쪽 메뉴 + MDI 탭)은 국내 대표 제품과 같다 → 국내 사용자 익숙함 확보.
- 3단 토큰 + 가드 테스트, "파랑 = 동작 전용", 홈 "정상 회색·이상만 색"은 iX·Fiori·ISA-101 관행과 같고 국내 공개 제품보다 엄격하다.
- POP 크기(48/64px, 착수 140×64, 키패드 약 94×64)는 PlantPAx 40px·Material 48dp 이상 — 충분(mes.md 계측).
- 테스트 세션 계측: 제목 18px·버튼/입력 28px·라벨 12px·저장 파랑이 기준정보·생산·설비·품질 화면에서 같다(master.md) — **토큰 효과는 이미 보인다**.

**관찰 정리**
- 토큰 효과로 **색·글자 크기·버튼 높이는 화면 간 일관**하다 — 시장 제품과 비교해도 정돈된 인상. 흐트러짐은 색이 아니라 **부품 선택**(그리드 vs 표, 조회 패널 유무, 버튼 배치)에서 온다 → 7장 P1 "목록 화면 표준 틀"이 가장 효과가 크다.
- 홈의 모양 + 글자 배지는 이미 시장 기준(AVEVA 3중 부호화)을 만족 → **새로 설계하지 말고 이것을 `hb-status` 공통 부품으로 끌어올리면** 된다(7장 P1 노력 "중 → 하~중").
- 메뉴 113개는 국내 제품 수준의 규모다 — 메뉴 검색이 없으면 화면 찾기가 첫 마찰이 된다.

## 부록 A. 상태 의미 사전 (단계 1 공통 부품, 2026-10-22 — 결정 V-1·V-3·V-6, docs/29 #44)

> 상태 색·모양·글자의 뜻은 **이 표 하나**로 고정한다. 화면은 토큰 이름(`tokens.css`)과 `hb-status` 톤만 쓰고 값(색)은 쓰지 않는다(DesignTokenGuardTest). 값을 바꿀 때는 `tokens.css` 만 고치고 이름은 바꾸지 않는다 — MachineMetrics 처럼 화면마다 같은 상태의 색이 달라지는 일을 막는다. **모든 상태 표시는 모양 + 글자가 필수, 색은 강화**(docs/12 2.6).

### A.1 `hb-status` 톤 (공통 배지 — `hb.status(tone, 글자)`, CSS `.hb-status[data-tone]`)

| 톤 | 모양 | 색 토큰 | 뜻·쓰는 곳 |
|---|---|---|---|
| `neutral` | ○ | 바탕 `--hb-bg-muted`·글자 `--hb-text-subtle` | 할 일 없음·대기·해당 없음 |
| `normal` | ● | (neutral 과 같음) | 정상·진행(색 없이 — "정상 = 초록" 안 씀) |
| `info` | ● | `--hb-status-info-{fg,bg,line}` | 볼 것 있음·안내 |
| `success` | ✓ | `--hb-status-success-{fg,bg,line}` | 완료·합격·성공 |
| `warning` | ▲ | `--hb-status-warning-{fg,bg,line}` | 확인 필요·주의·기한 임박 |
| `danger` | ■ | `--hb-status-danger-{fg,bg,line}` | 지연·불합격·정지 |
| `error` | ✕ | `--hb-status-danger-*` | 처리 실패·불러오기 실패 |
| `alarm-1` | ◆ | `--hb-alarm-1-*`(빨강, 굵게) | 알람 P1 긴급 |
| `alarm-2` | ▲ | `--hb-alarm-2-*`(주황) | 알람 P2 높음 |
| `alarm-3` | ■ | `--hb-alarm-3-*`(호박) | 알람 P3 보통 |
| `alarm-4` | ● | `--hb-alarm-4-*`(자홍) | 알람 P4 낮음 |

- 모양은 CSS `::before` 로 그리고 읽기 프로그램에는 숨긴다(`content: "▲" / ""`) — 글자가 뜻을 전한다. 좁은 칸은 짧은 글자 + `title`.
- 알람 글자에는 우선순위를 함께 쓴다("P1 설비 고장"). 알람 색은 알람 밖에서 쓰지 않는다(ISA-101).
- 예시 적용: 홈 카드 배지(홈 전용 클래스를 걷어 내고 공통 부품으로). 다른 화면은 모듈이 화면을 고칠 때(단계 2·3).

### A.6 목록 그리드 상태 칸·행 클래스·이동 확인 (단계 3 공통 보강, 2026-10-22)

단계 3(목록 틀) 전환이 기다리던 hb.grid 공통 기능. 계약은 `types/hb.d.ts`(GridOptions·TreeOptions·`hb.gate`).

| 기능 | 쓰는 법 | 규칙 |
|---|---|---|
| 상태 칸 | `status: {woStatus: {PLAN: 'neutral', RUN: 'info', DONE: 'success'}}` 또는 `(값, 행) → 톤` | 칸 글자는 다른 칸과 같은 `cellText`(코드 이름 등) → 그 글자로 `hb-status` 배지. textContent 만, 모양 기호는 CSS 라 칸·행 복사와 엑셀(서버)은 글자 그대로. 표에 없는 값은 배지 없이 글자 |
| 행 클래스 | `rowClass: row => row.useYn === 'N' ? 'hb-tree-dim' : null` | `hb-row-*`·`hb-tree-*` 의미 클래스만(흐리게 `hb-tree-dim`, 강조 `hb-tree-flag`, 주의 `hb-row-warn`) — 그 밖 이름은 버린다. 색은 page.css 한 곳 |
| 칸 글자 합치기 | `format: {cycleN: (v, row) => row.cycleN + row.cycleUnit + (row.fixedYn === 'Y' ? ' · 달력 고정' : '')}` | TEXT 열 표시 함수의 두 번째 인자 = 행 전체(2026-10-22 CMS 요청). 한 인자 함수는 그대로, 빈 값은 부르지 않고 빈 글자, 결과는 textContent 로만. 엑셀은 서버 열 그대로(화면 글자와 다를 수 있다 — 서버 열에서 같은 글자를 만들려면 열 정의를 따로) |
| 행 체크박스 | `checkable: true, onCheck: rows => …` · `g.getChecked()` · `g.clearChecked()` | 여러 행 고르기(MES LOT 병합 요청). 맨 앞 고정 칸, 고르기(선택 행·상세)와 따로. 체크는 쪽·정렬을 바꿔도 key 로 남고 새 조회(reload(true))면 비움, 머리 칸 = 이 쪽 모두(일부면 indeterminate), Space = 고른 행 체크, 바닥에 "선택 n건". 엑셀·행 복사에는 안 들어감 |
| 행마다 체크 가능 | `checkableRow: row => boolean` (checkable 과 함께) | 못 고르는 행은 체크칸 비활성, 머리 칸 "모두"·Space 도 건너뛰고 머리 칸 상태도 고를 수 있는 행만 센다(고를 수 있는 행이 없으면 머리 칸 비활성). 체크해 둔 행이 다시 읽었을 때 못 고르는 행이 되면 체크에서 빠지고 onCheck 가 불린다. 화면 표시일 뿐 막는 것은 서버(MES #312 요청, 2026-10-22) |
| 빈 칸 글자 | `emptyText: {field: '만료 없음'}` | 칸 글자를 먼저 만들고(null → 빈 글자, 숫자·날짜 → hb.fmt, TEXT → format — null 이면 format 안 부름, 지금과 같음) 그 결과가 빈 글자일 때만 보인다. 모든 칸 유형, 옵션·필드가 없으면 지금처럼 빈 칸. 화면 표시만 — 칸 복사·행 복사·엑셀(서버)은 빈 글자. null 에 format 을 부르게 바꾸지 않은 이유: 기존 format 들이 null 을 받으면 조용히 다른 글자(예: 사내·회사)를 보이게 됨(2026-10-23 결정) |
| 이동 확인 | `beforeSelect: next => dirty ? hb.dialog.confirm({...}) : true` | boolean(기존 동기 그대로) 또는 Promise. 답을 기다리는 동안 다른 이동·페이지 넘김은 무시, 그 사이 다시 조회(트리는 setRows)됐으면 옮기지 않음, 거부(reject)는 머묾. hb.tree 도 같은 규칙(selectWhere 는 묻지 않음) |

고르지 않은 안: `GridOptions.cell(field, row) → 요소`(화면이 아무 요소나 넣을 수 있어 textContent·의미 사전 규칙을 가드로 지키기 어렵다), 서버 ColumnSpec 에 STATUS 형식(톤은 화면 의미라 서버 열 정의·엑셀과 섞지 않는다 — 서버는 CODE 열 그대로).
