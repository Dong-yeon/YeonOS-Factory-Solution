## 0. 왜 지금(P2·P3·P4 와 병행) 할 수 있나

PMS 는 **생산 실행 데이터에 기대지 않는다.** 필요한 것은 P0(사용자·결재·첨부·채번·정책·코드)과 P1(품목·거래처·설비·물리 자산)뿐이다.
P2 LOT·P3 관리문서/시정조치와 이어지는 곳은 **연결 칸(`ref_type`·`ref_id`)만 미리 두고**, 그 모듈이 main 에 들어온 뒤 연결을 켠다(29 0장의 "자리 먼저" 원칙과 같다).

## 1. 결론 먼저

- PMS 는 **"신규 부품을 고객 SOP(양산 시작)까지 끌고 가는 일"** 을 관리한다. 데모 흐름: APQP 템플릿 → 프로젝트 생성(고객·품목·SOP 일) → WBS·일정(간트) → 기준선 확정 → 진행·실적일 입력 → 산출물 제출·승인 → **단계 게이트 심사(결재)** → 지연·준비율 대시보드.
- **엔진은 일반 프로젝트관리, APQP 는 템플릿·게이트·산출물로 얹는다.** 같은 엔진으로 4M 변경 프로젝트·설비 도입·개선 과제도 돌린다(프로젝트 유형 코드).
- **PMS 는 APQP 의 "일정·관문·제출물 칸"까지, 내용(PFMEA 트리·관리계획서 행·PPAP 18요소)은 P6 APQP, 문서 원본·리비전·배포는 P3 관리문서(29 Q3)** — 산출물 파일을 두 곳에 저장하지 않는다(6장, D5·D6).
- 계획 변경은 **기준선(baseline) 스냅샷**으로 남긴다 — I사의 "WBS 리비전 스냅샷" 경험을, 매일 바뀌는 진행 데이터와 섞이지 않는 형태로 바꾼다(D3).
- 간트는 **모듈 안 자체 제작(조회 전용, 편집은 표·폼)** 을 추천한다 — OSS 두 후보는 CSP·`textContent` 규칙과 부딪히거나 필요한 기능(기준선·WBS 코드·오늘 선)이 유료판에 있다(8장 D1, 근거 표 8.1).
- 사무직 화면이므로 POP 계열이 아니라 셸 화면. 공수는 **"배정된 작업 미리 채움 + 하루 1회 확인"**(11 Top #16), 이슈는 **업무 객체에 붙여서**(11 2.11.6).

## 2. 범위와 단계

순서 원칙(17·25 와 같음): **참조되는 것 먼저**, 매 단계 화면·API·테스트(정상 + 이상 사용 A~K + A사로 B사 + 직접 SQL)까지 끝난 상태로, 끝나면 7장 표에 ✅·날짜·테스트 수.

## 3. PMS 공통 규칙

| 규칙 | 내용 | 근거 |
|---|---|---|
| 테이블 | 회사별 RLS + `row_ver` + `tg_audit` + `sys_retention_table` 등록. 템플릿 = MASTER, 프로젝트·작업·산출물·게이트·이슈·공수 = **`QUALITY_RECORD`**(APQP 승인 근거 — 부품 EOL + 1년, 02 2.3·IATF 7.5.3.2.1) | 17 2장, 01 4장 |
| 날짜 | 계획·실적은 **날짜(`date`)**, 시각 아님 — 회사 시간대 `BizClock.today()` 기준. "지연" = 계획 종료일 < 오늘이고 완료 아님. 실적 종료일은 오늘 이후 거부 | 01 BizClock |
| 트리 | `parent_id` + 형제 순서 `seq`. 같은 프로젝트 안만(트리거로 확인 — RLS 는 회사만 막는다), 순환 금지, 깊이 상한 `PMS_MAX_DEPTH`(기본 6), 프로젝트당 작업 수 상한 `PMS_MAX_TASKS`(기본 2,000) — **넘으면 잘라 보이지 말고 오류**(BOM 전개와 같음). WBS 번호(1.2.3)는 저장하지 않고 조회 때 계산 | 18, SKILL §5 |
| 요약 작업 | 자식이 있는 작업 = 요약. 계획·실적일 = 자식 최소·최대, 진척률 = 자식 기간 가중 평균 — **저장 때 서비스가 다시 계산**(조회 때 계산은 간트 1,000행에서 비쌈), 직접 수정 거부 | MS Project 관례 |
| 상태 | 프로젝트 `DRAFT → ACTIVE → (ON_HOLD ↔ ACTIVE) → CLOSED` + `CANCELLED`, 작업 `NOT_STARTED → IN_PROGRESS → DONE` + `CANCELLED`, 산출물·게이트는 각 단계 표. 전이 표 하나(서비스 + 트리거 55000) | 00 결함 5, 25 3장 |
| 진척률 | 잎 작업만 입력(0~100 정수, 10 단위 권장). DONE = 100 + 실적 종료일 필수, 100 이면서 미완료 금지 | — |
| 편집 권한 | 화면 권한(`@ProgAuth`) 위에 **행 권한**: 프로젝트 머리·WBS 구조·기준선 = PM(또는 회사 관리자), 작업 진행·실적 = 담당자 또는 PM, 공수 = 본인만. 서비스에서 확인(D8) | 26(서비스 계층 권한 재확인) |
| 닫을 때 필수 | 작업 DONE 때 실적 종료일, 프로젝트 CLOSED 때 열린 이슈 0 · 미결 산출물 0(또는 면제), 공수 일 확정 때 분류 | 11 D13 |
| 결재 | 게이트 심사 = `ApprovalDocType("PMS_GATE")`, 정책 `PMS_GATE_APPROVAL`(Y/N, 기본 Y) — N 이면 APPROVE 권한으로 바로 결정(29 D7 과 같은 모양) | 01 P0 7단계 |
| 정책 | `PMS_MAX_DEPTH`·`PMS_MAX_TASKS`·`PMS_GATE_ENFORCE`(OFF/WARN/BLOCK, 기본 WARN)·`PMS_GATE_APPROVAL`·`PMS_DAY_MAX_HOURS`(24)·`PMS_DUE_SOON_DAYS`(7) | P0 정책 |
| 연결 칸 | 다른 모듈 행을 가리키는 칸은 `ref_type`(CHECK 목록) + `ref_id` — FK 대신 **서비스의 연결 확인기**(`PmsRefResolver`: 유형별로 같은 회사·존재·사용 중 확인). 아직 없는 모듈 유형은 CHECK 에 넣지 않는다 → 병합 뒤 새 V 파일로 추가 | 29 0장, 01(FK 는 RLS 무시) |
| 병행 개발 | 29 6장 규칙 그대로: 이 브랜치 다음 Flyway 번호(V039~) 사용·늦게 병합하는 쪽이 번호 재부여, 문구 키 `pms.`·`js.pms.` 접두어, **공통 JS·CSS(`hb.*`) 수정 금지** — 간트·WBS 편집은 `static/js/views/pms/` 안에, 공통화는 병합 뒤 | 29 6장 |
| 테스트 | 25 3장 그대로 + 트리·의존 순환 + 요약 파생 손 검산 + 간트 실측(1,000 작업) + **A사로 B사**(프로젝트·작업·산출물 첨부·이슈 객체 연결·공수) | 24, CLAUDE.md |

### 4.1 템플릿 → 프로젝트 복사 (PM1)

기준(anchor)이 `START` 이면 사용자가 준 시작일 + `offset_days`, `SOP` 이면 **SOP 일 + `offset_days`**(SOP 전 작업은 음수 일수 — "SOP 120일 전 = -120", SOP 마일스톤은 0). 자동차 런칭은 고객 SOP 가 먼저 정해지므로 APQP 템플릿 기본은 `SOP`.
복사는 한 트랜잭션, 템플릿 행 → 작업 행(새 ID, 부모 매핑), 산출물 칸 → `pms_deliverable`(PM3 이후). 템플릿의 이후 변경은 기존 프로젝트에 반영하지 않는다(출처 `tmpl_id` 만 남김).

### 4.2 기본 APQP 템플릿 시드 (데모·출발점)

5단계(계획·제품 설계·공정 설계·제품·공정 검증·양산 + Safe Launch) + 단계마다 게이트 1개 + 일반 산출물 이름(예: DFMEA·PFMEA·공정 흐름도·관리계획서·MSA·초기 공정능력·PPAP 제출). **AIAG 매뉴얼의 체크리스트 문구는 시드하지 않는다**(저작권 — 02 의 AP 표·29 D3 와 같은 판단). 이름·순서는 우리가 쓴 일반 용어이고 회사가 고쳐 쓴다(D7).

시드 방식: Flyway 시드가 아니라 **템플릿 화면의 "기본 APQP 템플릿 만들기"**(`POST /api/pms/templates/default-apqp`, 코드 `APQP-STD`, 이미 있으면 그것) — 회사를 만들 때 끼어드는 훅 없이 모든 회사(데모·신규)가 같은 경로로 받는다. 단계 5 · 작업 19(게이트 5 · SOP 마일스톤 1) = 24행.

### 4.8 PM6 상세 — 병합 뒤 연결 3건 (V098, 2026-10-21 착수)
