## 2. 전수 조사표

`엑셀` 칸: **있음** = 이번 작업 전부터 grid 메뉴 엑셀, **새로 붙임** = 이번에 붙임, **있음(화면 버튼)** = grid 메뉴가 아니라 화면의 엑셀 버튼, **제외** = 붙이지 않음(이유).
목록 API 는 그리드가 읽는 주소이고, 내보내기는 같은 기준 경로의 `POST …/export`(`…/grid` 자리에 `/export`), 열 정의는 `GET …/columns`.

## 3. 공통 도우미 — `platform/excel/GridExcel`

### 3.1 지금까지의 방식과 문제

엑셀이 있던 38곳은 화면마다 ① 내보내기 요청 DTO ② 서비스 `export()`(조건을 다시 검사하고 조건 키 목록을 만들고 `ExcelExportService` 호출) ③ 매퍼 Cursor(또는 쪽 없는 조회)를 따로 썼다. 한 화면에 30~50줄이고, 목록과 내보내기의 조건 해석이 **두 군데**라 어긋날 수 있다(그래서 매퍼는 같은 `<sql>` 조각을 쓰게 했다 — SKILL 2장).
60곳 가까이를 같은 식으로 더 쓰면 그만큼 어긋날 자리가 늘어난다.

### 3.2 새 방식

내보내기 API 가 **목록 API 의 서비스 메서드를 그대로** 부른다. 화면마다 쓰는 것은 컨트롤러 핸들러 하나(8줄)와 화면 JS 한 줄(`exportUrl`)뿐이다.

```java
@PostMapping(DEFECT + "/export")
@ProgAuth(prog = DefectTermService.PROG_DEFECT, action = Action.EXCEL)
public void defectExport(@RequestBody(required = false) Map<String, Object> body, HttpServletResponse response) throws IOException {
    gridExcel.export(response, body, DefectTermService.PROG_DEFECT, defects.defectColumns(), q -> {
        var p = defects.defectGrid(q.str("useYn"), q.str("keyword"), q.page(), q.size(), q.sort(), q.total());
        return GridExcel.Slice.of(p.list(), p.total());
    });
}
```

| 원칙 | 어떻게 지키나 |
|---|---|
| 열 정의는 서버 한 곳 | 화면 `/columns` 가 내려주는 것과 **같은 `ColumnSpec` 목록**을 넘긴다. 요청한 열은 `ColumnSpec.selectExportable` 이 검사(정의에 없는 열·`noExport()` 열·중복 → 400). 머리글·코드명·서식도 여기서 |
| 조회 조건은 목록과 같은 조건 | 같은 서비스 메서드에 같은 이름의 값을 넘긴다(`q.str("keyword")` = 목록의 `?keyword=`). 검사·해석·SQL 이 하나라 화면과 파일의 행이 어긋날 수 없다. 정렬도 목록의 허용 목록(`PageQuery`) 그대로 |
| 파일 생성은 `ExcelExportService` 만 | 동시 자리(회사별)·시간 제한·**건수 상한 먼저**·수식 주입 방지·출력 정보 시트. 도우미는 첫 쪽(건수 포함)을 먼저 읽어 건수·조건 오류가 응답을 쓰기 전에 걸리게 한다 |
| 회사 격리는 RLS 그대로 | `GridExcel.export` 가 요청 스레드에서 회사 트랜잭션을 열고(`@Transactional(readOnly)`), 그 안에서 목록 서비스가 조회한다. 본문의 `compCd` 는 조건 이름이 아니라 쓰이지 않는다 |
| 쪽을 넘겨 읽어도 겹침·빠짐 없음 | 쪽 크기 = 정책 `GRID_PAGE_SIZE_MAX`, 마지막 쪽까지 되풀이. 읽는 동안 행이 늘거나 줄어도 어긋나지 않게 트랜잭션을 **REPEATABLE READ**(한 스냅샷)로 연다. 목록 정렬은 끝에 PK 가 붙어 쪽 경계가 고정된다(SKILL 2장) |
| 본문에서 쪽 정보를 받지 않는다 | `page`·`size`·`total` 은 도우미가 정한다 — 큰 `size` 를 보내 상한을 넘기지 못한다 |

구성(모두 `io.smarthappy.platform.excel`)

| 클래스 | 역할 |
|---|---|
| `GridExcel` | `export`(쪽 단위 목록)·`exportAll`(쪽이 없는 목록 — 한 번만 부른다). 화면 이름 키는 `sys_prog.prog_nm_key` 에서(핸들러가 문구 키를 따로 적지 않는다). 쪽 크기를 지키지 않는 목록을 `export` 로 붙이면 같은 행이 되풀이되므로 예외로 멈춘다 |
| `GridExportQuery` | 요청 본문(`{조건…, sort, columns}`) 읽기 — `str`·`intValue`·`longValue`·`bool`·`date`·`strs`. 글자로 바꾸는 규칙은 `hb.grid` 가 목록 주소를 만드는 규칙과 같다(null·빈 글자 = 없는 조건, 숫자·참거짓 = 글자, 배열 = 쉼표로 이은 글자) — 같은 화면 조건이면 목록 핸들러와 내보내기 핸들러가 서비스에 같은 값을 넘긴다. 형이 안 맞는 값(글자 자리에 객체·겹친 배열)은 400. 조건 **이름**만 로그·출력 정보에 남긴다(값은 남기지 않는다) |
| `RowReader` | 행에서 열 값 읽기 — getter 객체·레코드·Map. 없는 필드는 빈 칸(화면과 같음) |
| `CellValues` | 값 → 셀 값. 목록 행은 화면(JSON)용이라 수량이 글자(`"12.5"`)이거나 일시가 ISO 글자일 수 있다 — 열 유형에 맞게 숫자·날짜 셀로 바꾸고, 못 바꾸는 값은 버리지 않고 글자 그대로(조용히 비우지 않는다) |

`ExcelExportService` 는 셀 값 처리만 `RowReader`·`CellValues` 를 쓰게 바꿨다(공통 변경). 기존 38곳의 내보내기는 그대로 돈다 — 전에는 `Number`·`LocalDate`·`OffsetDateTime` 이 아니면 500 이었던 자리가 이제 타입 셀 또는 글자 셀이 된다.

화면 쪽은 `hb.grid` 를 고치지 않았다. grid 메뉴 "엑셀"은 원래 `exportUrl` 이 있고 페이지 권한에 EXCEL 이 있을 때만 보이며, 조회 조건(`params()`)·지금 정렬·**보이는 열**(내보낼 수 있는 것만, 화면 순서)을 본문으로 보낸다. 버튼을 새로 만들지 않아 툴팁·문구 키도 늘지 않았다.

### 3.3 한계 — 언제 전용 내보내기(Cursor)를 쓰나

쪽 읽기는 `OFFSET` 이라 뒤로 갈수록 느려진다(행 수 n 에 대해 대략 n²/쪽크기). 건수 상한(`EXCEL_EXPORT_MAX_ROWS`, 기본 10만)과 시간 제한(`EXCEL_EXPORT_TIMEOUT_SEC`)이 막아 주지만, **수만 행이 보통인 목록**(재고·수불 원장·LOT·실적 등)은 지금처럼 매퍼 Cursor 로 쓰는 전용 내보내기가 맞다 — 그 화면들은 이미 그렇게 돼 있고 이번에 바꾸지 않았다.
이번에 붙인 56개는 기준정보·문서 머리·설정·로그 목록이다. 이 가운데 행이 많이 쌓이는 것은 접속 로그·변경 이력·아웃박스·인쇄 작업이고, 넷 다 기간 조건이 있다(3.4 ②).

### 3.4 상위 세션이 정할 것

| # | 질문 | 지금 상태 |
|---|---|---|
| ① | 권한 행을 마이그레이션으로 줄 것인가 | 주지 않았다(V152·V177 등 지금까지와 같음). 설치된 회사는 관리자가 권한그룹 화면에서 EXCEL 을 켜야 grid 메뉴에 "엑셀"이 보인다 |

## 4. 새 화면에 붙이는 법 (체크리스트 후보)

1. 서비스: grid 메서드(`PageQuery.parse` + 건수)와 `ColumnSpec` 목록 — 지금 하던 그대로
2. 컨트롤러: `POST {기준}/export` + `@ProgAuth(prog, EXCEL)` + `gridExcel.export(response, body, PROG, 열, q -> 목록 서비스 호출)` — 조건 이름은 grid 핸들러의 `@RequestParam` 이름과 같게
3. 화면 JS: `hb.grid` 옵션에 `exportUrl`, `actions`
4. Flyway: `sys_prog.actions` 에 `EXCEL`
5. 시험: `GridExcelAllScreensTest` 가 새 API 를 저절로 찾아 권한 403·행 수 = 목록 건수를 본다(조건이 필수인 목록은 그 시험의 기본 조건에 이름을 더한다). 조건이 복잡한 화면은 화면 시험에 조건별 행 수를 더한다
