## 0. 요약

### 0.1 한 줄 결론

**현재 결정(Java + Spring Boot 4.1 + PostgreSQL + MyBatis + Thymeleaf/순수 JS)을 유지한다.** Node.js 와 Java 의 차이는 "어느 쪽이 더 좋은가"가 아니라 **"어떤 일을 하는 회사·팀인가"**의 차이이고, SmartHappy 가 하는 일(트랜잭션 무결성·원장·결재·RLS·장기 유지보수·설치형 납품, 1인 개발)은 Java/Spring 이 강한 영역 그대로다. 스마트팩토리 시장은 **업무 계층(MES/QMS/WMS)은 Java 와 C#/.NET 이 양분**, **설비 연동 계층은 C#/.NET·C/C++ 가 강하고**, **분석·AI 는 Python**, **신생 SaaS·노코드는 TypeScript/Node** 로 갈라져 있으며, 국가 사업(스마트공장 보급·확산)은 **언어·프레임워크를 제한하지 않는다**(조사한 공고 범위에서). 바꿀 이유는 없고, **보완할 것 4가지**가 있다:

1. **JDK 배포판을 Temurin(또는 Corretto) 21 로 고정하고 목표 21 을 지금 21 로 올린다** — Oracle JDK 21 무료(NFTC) 기간이 2026-09 에 끝났다 [L3]. 설치형 고객에게 Oracle JDK 를 깔게 하면 라이선스 분쟁 위험.
2. **Spring Boot 마이너 업그레이드를 정기 작업으로** — Boot 는 LTS 가 없고 마이너마다 OSS 지원 약 13개월, 4.1 은 2027-07-31 종료 [L1]. 6개월마다 마이너 1회 올리는 일정을 로드맵에.
3. **프론트엔드는 SPA 로 가지 않고 "순수 JS + JSDoc 타입 검사(`// @ts-check`, `tsc --noEmit`)"로 TypeScript 의 이득만 취한다** — 빌드 단계·CSP·Thymeleaf 구조를 그대로 둔 채 P1(편집 그리드·POP 컴포넌트 전)에 도입.
4. **언어를 늘리는 곳은 두 군데뿐, 둘 다 별도 프로세스·`/ext/**` + `sys_inbox` 경계 뒤에** — `sh-ml`(Python, 2차) / Collector 어댑터(1차는 Java, Windows 전용 PLC 라이브러리가 필요할 때만 C#). 03·00 이 이미 정한 경계와 같다.

### 3.2 해석 [추정]
- **국가 사업은 "무엇으로 만들었나"가 아니라 "무엇을 지원하나(OPC UA·AAS·로그 연동·보안)"를 본다.** 따라서 언어 선택이 지원사업 자격을 좌우하지 않는다.
- 공공 SI(관공서 정보화)로 갈 생각이 없다면 전자정부프레임워크는 신경 쓸 필요가 없다. 반대로 언젠가 공공기관 RFP 를 직접 겨냥한다면 그때는 **Boot 버전이 RFP 에 묶이는** 별도 제품 라인이 필요하다 — 지금 대비하지 않는다.
- Java/Spring 이라는 사실 자체는 국내 평가위원·고객 IT 담당·유지보수 인력에게 **"익숙한 스택"이라는 비공식 가점**이 된다(인력 수급·유지보수 단절 우려 해소 — 06 의 2순위 구매 이유 "끊기지 않는 유지보수"와 직결).

| Go·Kotlin·Rust | 도입하지 않음 | — |

### 11.1 L4 적용 결과 (2026-10-20)

- **범위**: `static/js/common/` hb.\* 11파일(약 3,100줄) 전부 `// @ts-check` 통과, 화면은 본보기 `views/master/cust-mgt.js` 하나(같은 날 나머지 화면 전부 — 아래 "점진 적용 완료"). 검사는 `strict`(null 검사 포함) — 느슨하게 시작하면 나중에 올리기 어렵다.
- **계약 위치**: 공개 API 는 `types/hb.d.ts` 의 `HB.Hb` 인터페이스 하나. 구현은 `/** @type {HB.Hb['grid']} */` 처럼 계약 타입을 달아 **구현이 계약과 어긋나면 tsc 오류**. 모듈(hb.grid·hb.page …)은 화면 템플릿이 넣었을 때만 있지만 계약에서는 항상 있는 것으로 둔다(빠지면 브라우저에서 바로 드러남).
- **화면 JS 관용구(본보기 cust-mgt)**: 템플릿에 항상 있는 요소는 `/** @type {HTMLFormElement} */ (document.getElementById(…))` 형 변환, `th:if` 로 빠질 수 있는 요소(권한 버튼·파일 칸)는 null 확인. 서버 응답 모양은 파일 머리의 `@typedef`. 비동기 콜백 안에서 `current` 같은 바뀌는 변수 대신 **클릭 시점 값을 지역 변수로 잡는다**(타입 검사도 그래야 통과).
- **타입 검사가 찾은 것** (고친 것 — 동작 변경, TESTING.md 기록):
  1. `hb.loadSession` 이 한 번 실패하면 실패한 promise 를 영구 캐시 → 이후 모든 화면 준비 실패. 실패 시 캐시 비움.
  2. `hb.codeList` 가 실패를 빈 목록으로 영구 캐시 → select 가 새로고침 전까지 빈 채로. 실패는 캐시하지 않음.
  3. `hb.importDialog` 행 목록: 필터·페이지를 빨리 바꾸면 늦게 온 이전 응답이 덮어씀, 다른 단계로 넘어간 뒤 응답이 오면 `null.textContent` 예외. 요청 순번 + 요소 참조로.
  4. `hb.tree`: 열 정의를 받기 전에 `setRows`(조회 패널이 먼저 준비돼 Enter)면 펼침 표시 요소가 없어 `null.textContent` 예외 → 표 0행(브라우저 재현). 없으면 건너뛰고, 준비되면 행 요소를 버리고 다시 그림.
  5. `hb.numbers.fixed/format`: 형식 밖 값(예 `1e-7`)이면 예외로 표시가 멈춤 → 글자 그대로. `compare` 는 명시적 TypeError.
  6. 거래처관리: 첨부 목록 늦은 응답이 다른 거래처 목록에 섞임(순번), 저장 중 다른 행을 고르면 저장 후 엉뚱한 거래처를 다시 읽음(클릭 시점 id), 그리드 준비 전 저장이면 `grid.reload` 예외.
  - 정리만(동작 같음): hb.api·download·upload 의 오류 정규화 3벌 → `failure`(401 처리 = main 의 `expired()`)·`networkError`·`deadline` 공용, IE 전용 `window.clipboardData` 제거, 조회 패널 일반 칸은 input·select·textarea 만(이름 있는 fieldset·output 은 `.value.trim()` 예외였음 — 지금 템플릿엔 없음).
  - main 과 합칠 때(같은 날 main 의 docs/24 2.1~2.3 수정): 거래처 첨부 순번은 main 의 `hb.latest('files', …)` 로 통일, 계약에 `hb.latest`·`ApiError.stale`·`fmt.datetime(v, tz)`·`window.hbShell/hbAnyDirty/hbLeaving` 추가, hb.page 폭 조절 막대도 검사 통과.
- **점진 적용 완료 (2026-10-20)**: 화면 JS 전부 — views/master 20개(위 목록 + 같은 날 생긴 shift·qual·worker), views/platform 3개, shell.js, login.js, ops/console.js, ops/login.js. `npm run typecheck` 오류 0(적용 전 약 2,000건). 남은 것은 dev/grid-poc(편집 그리드 PoC — 채택 시)뿐. **새 화면 JS 는 첫 줄 `// @ts-check` 로 시작한다**(skill checklists §2).
  - 계약 추가: `HB.Shell`·`HB.ShellTab`(셸 창 `window.hbShell` — `open(progCd, title)`·`tabs()`). login.js 는 hb.js 를 싣지 않고 밖으로 내놓는 API 도 없어 `hb.login` 계약은 만들지 않았다.
  - **함정 — `@typedef` 이름은 전역**: 화면 JS 가 모듈이 아니라 파일 머리 typedef 가 모든 파일에 공유된다. `Worker`(DOM 내장)·`Proc`·`AttrView` 가 실제로 TS2300(중복)으로 부딪혔다 → **화면 접두를 붙인다**(`MstItem`·`RoutingStep`·`WorkerRow`·`OpsCompany` …). 본보기 cust-mgt 의 `Cust`·`Contact` 는 겹치는 이름이 없어 그대로.
  - **화면에서 찾은 결함**(고침 — TESTING.md "화면 JS 타입 검사 점진 적용" 표): 거의 전부 cust-mgt 6번과 같은 세 유형이었다.
    1. **응답 뒤 바뀐 `current` 를 읽음**(약 20곳 — 품목·설비·자산·BOM·라우팅·공정·공장·계층·특성·클래스 속성·불량·용어·자격·작업자·근무조·외부 시스템의 저장·처리·확정·사용 중지 등): 처리 중 다른 행을 고르면 엉뚱한 행을 다시 읽고, 신규를 누르면 `null.xxxId` 예외로 "저장됨" 없이 끝남 → 클릭 시점 값.
    2. **늦은 응답이 다른 대상 자리에 그려짐**: 품목 클래스 속성(다른 품목 속성 칸을 덮고 그대로 저장될 수 있음), 작업자 자격 판정·근무조 작업일 확인(다른 작업자·공장 자리에), 계층 트리(공장 A 노드로 B 에 하위 추가), 공정·불량 "사용 중지 포함" 목록, 운영자 콘솔 회사 결과 → `hb.latest` 또는 요청 시점 대상과 비교.
    3. **`hb.latest` 의 STALE 을 실패로 처리**: 라우팅 작업장 선택지가 비고, BOM 자품목·특성 품목 조회가 "품목 없음" 으로 덮임(키를 행마다 나누거나 STALE 은 무시). **`hb.latest` 를 쓰는 곳의 실패 처리는 `err.stale` 을 먼저 본다** — 단순히 문구를 지우는 곳(`notify(err.message)`)은 그대로 둬도 된다.
    4. 준비 전 호출(그리드·트리·조회 패널·hb.number 를 만들기 전 클릭) 예외, 계층의 "하위 추가" 거절이 `current` 를 먼저 지워 다음 저장이 수정 대신 신규로 나가던 것.
  - 고치지 않고 남긴 의심: 화면 시작 체인 끝 실패 처리 없음(usage·support·my-info — 문구 없이 빈 화면), 지원 권한 회수 버튼 연타·확인 없음, 운영자 콘솔 기본 기간이 UTC 날짜(회사 시간대 아님), STALE 때 `notify('', true)` 가 떠 있던 안내를 지움(공통 패턴).
- **하지 않은 것**(별도 결정): var→const 일괄 변환, ES 모듈 전환(`<script type="module">` + import 는 CSP 그대로 가능하지만 전역 `hb` 를 쓰는 화면 41개를 함께 바꿔야 함), 번들러·트랜스파일.
