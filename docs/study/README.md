# 스터디 — 설명해 보기 + 퀴즈

> 시작 2026-10-22 (사용자 요청 "AI 로만 하고 있어 공부가 안 된다").
> 근거: 같은 AI 사용자라도 **코드 생성을 맡기면 이해도가 낮고, 개념을 묻고 스스로 설명하면 유지된다**(Anthropic 무작위 대조 실험 2026-01, 퀴즈 65~86% 대 24~39%).
> 이 저장소는 하위 세션이 구현하고 상위 세션이 병합한다. 그래서 **읽고 설명하는 쪽**으로 공부를 붙인다.

## 1. 하루 15분 규칙

1. **고르기**: 병합된 PR 하나 또는 아래 2장 주제 하나.
2. **먼저 예측(3분)**: 코드를 보기 전에 "나라면 어떻게 할까"를 3줄. 맞든 틀리든 그대로 둔다.
3. **읽기(5분)**: 문서의 "볼 곳" 파일·줄만 읽는다. 전체를 다 읽지 않는다.
4. **내 말로 설명(5분)**: 문서의 "설명할 것"에 답한다. **AI 에게 묻기 전에** 쓴다. 모르면 "모름"이라고 쓴다.
5. **채점·퀴즈(2분)**: Claude 에게 `스터디 채점: docs/study/<파일>` 이라고 말한다.
   - Claude 는 틀린 곳·빠진 곳만 짚고 **정답을 통째로 쓰지 않는다**(힌트 → 다시 쓰기).
   - 그다음 퀴즈 3문제(개념 1 · 코드 읽기 1 · "이렇게 바꾸면 무슨 일이?" 1).
   - 퀴즈 답도 내가 먼저 쓰고 채점받는다.
6. **기록**: 문서 끝 표에 점수와 "다시 볼 것" 한 줄.

AI 에게 물어도 되는 것: 용어 뜻, 문서·파일 위치, 힌트("힌트 1단계만").
묻지 않는 것: "설명할 것"의 답 자체.

## 3. 파일 규칙

- 주제마다 `docs/study/<날짜>_<주제>.md`. 틀은 [_template.md](_template.md).
- "내 설명"·"퀴즈 답" 칸은 **사용자만 쓴다**. Claude 는 "채점" 칸에만 쓴다.
- 고객사 코드·실명·비밀번호는 쓰지 않는다(공개 저장소).

## 4. Java/Spring 대응 표 (헷갈릴 때)

| 이 저장소 | 익숙한 것 |
|---|---|
| PostgreSQL RLS 정책 | 모든 SELECT 에 자동으로 붙는 `WHERE comp_cd = ?` (DB 가 강제) |
| `TenantAwareTransactionManager` | `@Transactional` 시작 시점 훅 — SQL Server 의 `SESSION_CONTEXT` 설정과 같은 자리 |
| `SELECT ... FOR UPDATE` + `ORDER BY` | T-SQL `UPDLOCK, ROWLOCK` + 같은 순서로 잡기 |
| 40P01 deadlock | SQL Server 1205 교착 희생자 |
| `*.link` 계약 인터페이스 | 다른 모듈 Service 를 `@Autowired` 하지 않고 인터페이스만 주입 |
