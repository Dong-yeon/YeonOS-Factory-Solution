# 용어집 — MES·QMS·WMS·SRM 와 이 저장소의 설계 용어

> 2026-10-22 시작 · 워크스루를 읽다 막히는 말은 여기에 더한다 · 형식: 용어 | 한 줄 뜻 | 이 저장소 어디 | 고객 앞에서 쓰는 말
> "고객 앞에서" 칸은 현업이 알아듣는 표현 — 컨설팅·면접에서는 영어 약어보다 이 말을 먼저 쓰고 약어를 덧붙인다.

## 1. 재고·원장 (WMS)

| 용어 | 뜻 | 이 저장소 | 고객 앞에서 |
|---|---|---|---|
| 원장(Ledger) | 일어난 일을 **추가만** 하는 기록. 잔액은 원장 합으로 계산 | `inv_trx`, `lot_genealogy` | "재고 이력 장부" |
| 역분개(Reversal entry) | 잘못된 기록을 고치거나 지우지 않고 **반대 부호 행**을 더해 상쇄 | `InventoryService.reverseAll` | "취소 전표" — 누가 언제 왜 취소했는지 남는다 |
| 투영(Projection) | 원장에서 계산해 따로 들고 있는 값(빠른 조회용). 원본이 아님 | `inv_stock`, SRM `recv_qty` | "현재고 집계" |
| 대사(Reconciliation) | 원본과 투영이 맞는지 맞춰 보기 | `inv_reconcile_run` | "장부 맞추기" |
| 발생 시각 / 기록 시각 | 실제 일이 일어난 때(`occurred_at`) / 시스템에 적은 때(`recorded_at`) | 모든 원장 | "실제 입고 시각과 입력 시각은 다를 수 있다" |
| 기본 단위 / 발주 단위 | 재고를 세는 단위(EA) / 사고파는 단위(BOX) | `unit_cd`, `po_qty` | "박스로 사고 낱개로 관리" |
| 피킹(Picking) | 출하할 물건을 창고 칸에서 꺼내 모으기 | WMS B6a | — |
| 실사(Cycle count) | 실제 수량을 세어 장부와 맞추고 차이를 조정 | `CountService` | "재고 조사" |
| 마감(Period close) | 지난 달 원장을 더 못 바꾸게 닫기 | `sys_period_close` | "월 마감" |

## 2. 구매·공급 (SRM)

| 용어 | 뜻 | 이 저장소 | 고객 앞에서 |
|---|---|---|---|
| 발주(PO) | 협력사에 내는 구매 주문 | `srm_po` | — |
| 회신(ACK) | 협력사의 "받았다·이렇게 보내겠다" 답 | `srm_po_ack` | "납기 회신" |
| ASN | 사전 납품 통지 — 출하 전에 "무엇을 얼마나 보낸다" | `srm_asn`, `ASN:` 바코드 | "납품서(사전)" |
| OTD(On-Time Delivery) | **납기 준수율** = 납기까지 다 받은 행 / 대상 행 | SRM 평가 `OTD_RATE` | "납기 준수율 ○○%" |
| PPM | 백만 개당 불량 수(수입 불량률) | SRM `RECV_PPM`(대기) | "수입 불량 PPM" |
| 초과 입고 허용률 | 발주보다 몇 % 더 받아도 되는가 | 정책 `SRM_RECV_OVER_PCT` | — |
| 입고 예정 | 아직 안 들어온 발주 수량 — 계획이 자재로 본다 | `PoSupplyQuery`, APS `mat_po` | — |

## 6. 설계·기술 용어 (이 저장소)

| 용어 | 뜻 | 이 저장소 | 왜 중요 |
|---|---|---|---|
| 멀티테넌트 | 한 시스템을 여러 회사가 따로 쓰는 구조 | `comp_cd` | SaaS 의 기본 |
| RLS | DB 가 행마다 "이 회사 것만" 보이게 강제 | `tenant_isolation` 정책 | 앱 버그가 있어도 다른 회사 데이터가 안 보인다 |
| 멱등(Idempotency) | 같은 요청을 여러 번 보내도 결과는 한 번 | `sys_inbox`, 요청 id | 스캐너 연타·재전송 대비 |
| 아웃박스(Outbox) | 외부로 보낼 일을 DB 에 적고 나중에 보냄 | `sys_outbox` | 프린터·ERP 가 죽어도 업무는 끝난다 |
| 계약(Contract, `*.link`) | 모듈끼리 쓰는 좁은 인터페이스 | `module/*/link` | 모듈 경계를 지킨다 |
| 게이트(Gate) | 다른 모듈이 판정·기록하게 부르는 계약 | `PoReceiptGate`, `OrderShipGate` | 규칙은 주인 모듈 한 곳에 |
| 낙관적 락 | 저장할 때 버전(`row_ver`)이 바뀌었으면 거부 | 대부분의 표 | 동시 수정 덮어쓰기 방지 |
| 교착(Deadlock) | 두 트랜잭션이 서로의 잠금을 기다림 | QB-1 | 잠금 순서 고정으로 막는다 |
| 지연 제약(Deferred) | 커밋할 때 한 번에 검사하는 제약 | `ck_srm_po_receipt_sum` | 여러 행을 바꾸는 중간 상태는 허용 |
| 마이그레이션(Flyway) | DB 구조 변경 스크립트 — 번호 순서로 한 번만 | `V###__*.sql` | 적용된 파일은 고치지 않는다 |
