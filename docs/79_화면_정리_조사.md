### 1.3 가장 효과 큰 제안 5개 (자세한 것은 3장)

1. **M1 현장 진입 4화면 → 1화면** — `prd-pop`·`wms-pda` 는 같은 JS(`production/terminal-entry.js`, 76줄), `sys-mobile-app` 은 API 없음. 현장·모바일 폴더가 5개 → 2개(진입 + 단말 관리).
2. **M2 추적 화면 묶기** — LOT 추적 `prd-lot` 에 역추적 보고서(`prd-lot-report`)·출하 영향(`qms-lot-trace`)을, 시리얼 구성 `prd-serial` 에 부품 역추적(`prd-serial-trace`)을 탭·단추로. 추적 화면 4개 → 2개, "어디서 찾지?"가 사라진다.
3. **M3 설비 모니터링 묶기** — `cms-kpi` → `cms-dashboard` 탭(대시보드가 이미 같은 `KpiService.report` 를 부른다, `DashboardService` 37행), `cms-state-review` → `cms-state` 의 [사유 검토] 모드, `cms-equip-card` → `cms-equip-profile` 탭. 설비 화면 21 → 18.
4. **H1 정리 후보 6개 숨기기** — 표를 읽는 곳이 자기 화면뿐(용어 사전·COPQ·설비 보안 대장·위험성평가) 이거나 실제 장치가 없으면 빈 화면(자동창고·오토라벨러). 메뉴 밖으로(코드·표는 그대로) → 되돌리기 쉬움.
5. **D1 모듈 의존 정리(모듈 끄기 전에 꼭)** — 수주(`sal-order`)를 핵심 쪽으로, 4M 변경(`qms-change`)·초품 확인(`qms-setup`)은 설계 변경(PLM)과, 반품 출고(`wms-rtn-issue`)는 구매(SRM)와 함께 켜고 끄기. 안 하면 모듈 끄기 뒤 **출하가 막히거나 빈 화면이 남는다**.

핵심 4개 모듈(생산·품질·창고·설비 + 늘 켜는 기준정보·시스템)만 켜고 위 제안을 다 하면 메뉴 화면은 **143 → 약 91**(4장).

## 3. 합치기·숨기기·없애기 제안

### 3.0 먼저 정할 방식 — "메뉴만 합치기" vs "화면 합치기"

| 방식 | 하는 일 | 바뀌는 것 | 되돌리기 |
|---|---|---|---|
| **A. 메뉴만 합치기(권장 1단계)** | 빠지는 화면을 `DefaultMenuTree` 에서 빼고 `NOT_IN_MENU` 에 근거("X 화면의 탭")와 함께 넣는다. 남는 화면에 탭·단추를 달아 옛 화면(`/page/{progCd}`)을 연다 | 메뉴 트리 + 남는 화면 JS 몇 줄. **`sys_prog`·`@ProgAuth`·권한그룹 행은 그대로** | 트리 한 줄 되돌리기 |
| B. 화면 합치기 | 두 화면 JS 를 하나로, 빠지는 화면의 `sys_prog` 를 `use_yn = 'N'`(새 V 파일) | 권한 코드가 하나로 줄어 권한그룹(`sys_auth_prog`, 회사별 RLS 표)을 옮겨야 한다 | 어렵다(V 파일·권한 행) |

A 를 권장하는 이유: 화면 코드가 그대로면 권한·API·시험이 거의 안 흔들린다. 탭은 "그 화면 조회 권한이 있을 때만" 보이게 하면 지금 권한 구분도 그대로다.

**A 에도 꼭 필요한 일 한 가지** — `DevCompanySeed.ensureMenuTree`(55~77행)는 트리에 있는 화면을 **만들거나 옮기기만** 하고, 트리에서 빠진 화면의 메뉴 행은 지우지 않는다(지우는 것은 빈 폴더뿐, 72행). 그래서 트리에서 빼도 **이미 시드된 회사(데모·개발 DB)에는 옛 메뉴가 그대로 남는다**. "시드가 만든 뒤 손대지 않은 행(row_ver = 0·created_by = 시드)이고 화면이 트리에도 없고 `NOT_IN_MENU` 에 있으면 지운다(또는 `use_yn = 'N'`)" 한 단계를 더해야 한다 — docs/75 D4 와 같은 규칙. 운영 설치 회사는 회사 관리자가 메뉴 관리에서 정리.

### 3.1 합치기 (겹침)

| # | 남는 화면 ← 빠지는 화면 | 방법(A 기준) | 효과 | 위험 | 되돌리기 | 영향 받는 시험(화면 코드를 쓰는 것) |
