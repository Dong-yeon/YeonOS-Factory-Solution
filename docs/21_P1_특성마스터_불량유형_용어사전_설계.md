## 1. 결론 먼저

- **특성 마스터 `qms_char`** = 검사·SPC·FMEA·관리계획(CP)·PPAP·성적서가 가리킬 **하나의 키(`char_id`)**. P1 은 키와 규격(공칭·하한·상한·자릿수·특별특성)까지, 측정·SPC·CP 는 P3·P6 이 이 키를 참조한다.
- 특성은 **제품 특성**(품목 + 도면 풍선 번호, 예: 64311-DM100 #12 홀 지름) 또는 **공정 특성**(공정 + 번호, 예: SPOT #1 용접 전류). 제품 특성에 공정을 붙이면 "어느 공정에서 만들어지는가" 가 된다(CP 행의 공정).
- **특별특성** = 공통코드 `SPECIAL_CHAR`(NONE·CC·SC) + **회사가 고객 기호를 추가**(현대 ⓢ·Ⓒ 처럼 고객사마다 다르다 — `comp_ext_yn = 'Y'`).
- **불량 유형 2단** = 표준 상위 `DEFECT_CAT`(시스템 코드, 회사 추가 불가 — 외관·치수·기능·재질·용접·조립·이물·포장/표시·기타) + 회사 하위 `qms_defect`(회사 코드, 상위 필수). 실적 폐기·재작업(P2), NCR(P3), 비전 재판정(P5)이 같은 하위 코드를 쓰고, 회사가 달라도 상위로 모아 볼 수 있다(AI 라벨 전제).
- **용어 사전** = 전역 `sys_term`(시스템이 정의하는 지표·용어: 양품수·불량률·OEE·Cpk …, 정의 ko/en) + 회사 `mst_term_alias`(현장 말 동의어: "B급" → 불량, "쇼트" → 사이클 …). P1 은 테이블·시드·화면, 내용 확장·RAG·번역 연결은 P5.
- 화면 3개: **특성 마스터** `mst-char`, **불량 유형** `mst-defect`, **용어 사전** `mst-term`.

## 2. 특성 마스터 규칙

| 규칙 | 내용 | 이유 |
|---|---|---|
| 대상 | 제품 특성 = 품목 필수(공정 선택), 공정 특성 = 공정 필수(품목 선택) | docs/02 "item_cd 또는 …, proc_cd nullable". 공정 특성은 여러 품목에 공통인 경우가 많다 |
| 번호 | `char_no`(도면 풍선 번호, `^[A-Z0-9][A-Z0-9._-]{0,19}$`) — 제품 특성은 품목 안 유일, 공정 특성은 **품목 유무와 관계없이 공정 안 유일**(V029, 6.x 참고) | 도면·CP·성적서가 풍선 번호로 서로를 찾는다 |
| 데이터 유형 | `VARIABLE` 계량(하한·상한 중 하나 이상, 하한 ≤ 공칭 ≤ 상한) / `ATTRIBUTE` 계수(합부 — 수치 칸 없음) | 한쪽 규격(최소 인장강도) 은 하한만. `one_sided` 컬럼은 두지 않고 값에서 판단 |
| 단위·자릿수 | 단위는 공학 단위 글자(docs/20 과 같음), 측정 자릿수 `scale` 0~6 | 측정 화면·그리드가 이 자릿수를 쓴다(docs/09) |
| 출처 | `CHAR_SOURCE`: DRAWING 도면 · CUSTOMER 고객 요구 · FMEA · SPEC 규격서 | PPAP 에서 출처별로 묶는다 |
| 특별특성 | `SPECIAL_CHAR` 시스템(NONE·CC·SC) + 회사 추가 코드, 사용 중인 코드만(트리거) | 고객 기호는 고객사마다 다르다 |
| 도면 | `drawing_no`·`drawing_rev` 글자 | 관리문서(`mst_doc`, P3)가 생기면 연결 |
| 리비전 | **행 리비전 없음** — 규격 변경은 감사 이력 + 도면 리비전 글자. 측정값(P3)은 측정 시점 규격을 스냅샷한다 | 특성마다 리비전을 두면 CP·FMEA·SPC 가 모두 (특성, 리비전) 쌍을 들고 다녀야 한다. 바뀐 규격 전후 구분은 4M 변경(P3 `qms_change`)이 맡는다 [추정 — 상용 QMS 다수가 특성 행은 하나, 이력은 변경 기록] |
| 삭제 | 없음(사용 중지) | 측정·SPC 가 참조할 키 |

공정 파라미터(docs/20 `mst_routing_param`)와의 관계: 파라미터는 "설정값"(목표·허용범위, 라우팅 리비전에 묶임), 공정 특성은 "관리할 특성"(CP·SPC 대상). 같은 전류라도 둘 다 있을 수 있어 P1 은 연결하지 않고, CP(P6)에서 공정 특성 ↔ 파라미터 코드를 잇는다.

## 3. 데이터 모델 (V024 — V023 은 4단계 QA 결함 수정)

```text
sys_code_grp/sys_code   SPECIAL_CHAR(NONE·CC·SC, 회사 추가 Y) · CHAR_SOURCE · CHAR_TYPE(PRODUCT·PROCESS) · CHAR_DATA_TYPE(VARIABLE·ATTRIBUTE)
                        · DEFECT_CAT(9개, 회사 추가 N)
qms_char      char_id, comp_cd, char_type, item_id NULL, proc_id NULL, char_no, char_nm, data_type, unit_nm, scale,
              nominal, lsl, usl, special_cls, source, drawing_no, drawing_rev, sort_no, use_yn, remark, row_ver, 감사
              부분 유일: (comp, item_id, char_no) WHERE char_type='PRODUCT' / (comp, proc_id, char_no) WHERE char_type='PROCESS'  (V029)
              트리거: 품목·공정 같은 회사, 특별특성 코드 사용 가능(시스템 또는 그 회사 코드)
qms_defect    defect_id, comp_cd, defect_cd, defect_nm, cat_cd(DEFECT_CAT), sort_no, use_yn, remark, row_ver, 감사
sys_term      term_cd, term_ko, term_en, def_ko, def_en, category(KPI·QUALITY·PROD·EQUIP) — 전역, Flyway 로만(앱 읽기 전용)
mst_term_alias alias_id, comp_cd, term_cd → sys_term, alias, lang(ko·en·vi), use_yn, row_ver, 감사
              유일 (comp, lower(btrim(alias))) WHERE use_yn='Y' — 사용 중인 말이 두 용어를 가리키지 않게 (V029)
```

## 4. 화면·API

| 화면 | 구성 |
|---|---|
| **특성 마스터** `mst-char` | 조회(품목·공정·특별특성·유형) → 목록 그리드(품목·번호·이름·규격 "하한 ~ 상한"·특별특성 배지) + 상세 폼(유형에 따라 품목/공정, 계량이면 수치 칸). 엑셀 내보내기 |
| **불량 유형** `mst-defect` | 표준 상위별 묶음 표 + 상세 폼 (공정 관리와 같은 단순 화면) |
| **용어 사전** `mst-term` | 전역 용어 표(정의) + 고른 용어의 회사 동의어 추가·사용 중지 |

| QA # | 결정 | 근거·대안 |
|---|---|---|
| 4 번호 공간 | 제품 특성 = 품목 안 유일(도면 풍선 번호), 공정 특성 = **공정 안 유일**(품목을 붙여도 공정 번호 공간) | V024 는 "품목이 있으면 품목 안" 이라 품목 붙은 공정 특성이 풍선 번호와 충돌하고, 품목 없는 공정 특성과는 한 공정에 "#2" 가 둘 생겼다. 기각한 안: (공정, 품목, 번호) 유일 — 품목별 번호를 허용하면 한 공정 화면에서 같은 번호가 여럿 보여 관리계획서 공정 단위 번호와 어긋난다 |
| 7 동의어 유일 | **사용 중인 동의어만** 유일(부분 인덱스). 옛 행을 다시 사용하면 그때 `DUPLICATE` | 삭제·용어 변경 금지(이력) 아래에서 잘못 붙인 말을 바른 용어로 옮길 길이 없었다. 기각한 안: 화면에 "말 고치기" — 옛 행의 말을 바꾸면 감사 이력이 "B급 → B급(폐기)" 같은 가짜 값으로 남는다 |
| 6 정규화 | 동의어는 NFKC + 폭 없는 문자 제거 + 모든 공백(전각·NBSP) 하나로 | 눈에 같은 말이 다른 동의어로 들어가 "한 말이 두 용어" 를 우회했다 |
| 1·3 | 바뀌지 않은 특별특성 코드는 사용 가능 검사 생략(새 참조만), 다시 사용(N→Y)은 품목·공정 사용 여부를 다시 본다 | 4단계 QA 교훈과 같은 규칙 |
