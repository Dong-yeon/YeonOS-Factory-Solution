## 0. 요약

- P0·P1 의 서버 쪽(B 입력값·C 동시성·D 기준정보 변경·E 권한·F 흐름 우회·A사/B사)은 개발 세션 + QA 세션 5회로 **두텁다**. F 는 BOM·라우팅의 "확정본 불변 + 직접 SQL 트리거"로 대부분 구조적으로 막혀 있다.

  1. **상세 늦은 응답**(C 2026-10-20 추가): 목록은 `hb.grid` 가 요청 순번으로 막지만, 각 화면의 `loadDetail`·첨부 목록은 막지 않는다 → 행을 빠르게 바꿔 누르면 앞 행 상세·첨부가 뒤 행 자리에 그려질 수 있다. 첨부 목록이면 **다른 문서의 파일을 지울 수 있다**.

  3. **세션 만료 중 저장**(I): 401 이면 최상위 창을 `/login?expired` 로 보낸다. 셸의 이탈 경고가 뜨지만 "머무르기"를 골라도 저장할 길이 없다 → 입력이 사라진다.
- **J(입력 부담)는 한 번도 재지 않았다.** **K(현장 단말)와 E 의 "화면 안 비밀번호 승인"은 아직 대상 화면이 없다** → P2 POP 착수 체크리스트로 넘긴다.
- 클라우드 QA 세션 2회가 `~/.claude/abuse-testing.md` 를 찾지 못해 다른 분류를 썼다(`docs/qa/char-6.md`·`equip-4.md` 10행). 저장소 안에 기준이 없으면 QA 세션은 F~K 를 볼 수 없다 → 6장.

## 2. 해 볼 테스트 (우선순위 순)

### 2.1 상세·첨부 늦은 응답 — 상

- 재현: 개발자 도구 네트워크 지연(Slow 3G) 또는 서버 지연 프로브로 **행 A 클릭 → 곧바로 행 B 클릭**. A 응답이 B 뒤에 오게 만든다.
- 볼 것: 상세 칸·`current` 객체·첨부 목록이 B 인지. 그 상태에서 [저장]·첨부 [삭제] 하면 어느 문서가 바뀌는지(**감사 로그로 확인**).
- 대상: 상세가 있는 화면 전부 — 거래처·품목(첨부 있음), BOM·라우팅(행 표 + 머리 버전), 설비·자산, 특성, 클래스 속성.
- 고칠 방향(개발 세션 판단): `hb.grid` 와 같은 요청 순번을 `hb.page` 공통 헬퍼로 두고 상세·첨부·하위 표 로드가 같이 쓴다. 저장은 화면이 보여 주는 id 와 `current` id 가 같을 때만.

### 2.2 파일 드롭 위치 — 상

- 거래처·품목 상세(첨부 칸 옆 입력칸·빈 여백), 엑셀 올리기 대화상자 밖·안, 셸 메뉴 위에 파일(pdf·xlsx·exe)을 떨어뜨린다.
- 볼 것: iframe 이 파일로 바뀌는지, 입력이 남는지, 경고가 뜨는지. exe 는 내려받기로 넘어가는지.
- 고칠 방향: `hb.page` 가 문서 전체 `dragover`·`drop` 의 `preventDefault`(파일 칸만 허용). 셸 iframe 이 화면을 바꿀 때도 화면 쪽 `hb.dirty` 를 보게.

### 2.3 세션 만료 중 저장 — 중

- 재현: 상세에 입력 → 다른 탭에서 로그아웃(또는 세션 쿠키 삭제) → [저장].
- 볼 것: 401 처리 뒤 입력이 사라지는지, 저장이 됐다고 착각할 문구가 없는지.
- 선택지(결정 필요): (a) 현재처럼 로그인으로 보내되 "저장되지 않았습니다" 를 먼저 알림, (b) 입력을 `sessionStorage` 에 잠시 보관 후 재로그인 뒤 복구 제안, (c) 팝업 재로그인. 포트폴리오 설명 가치는 (b)·(c), 비용은 (a).

### 2.4 같은 회사 안 첨부 대상 바꿔치기 — 중

- 거래처 A 의 상세에서 `targetId` 를 거래처 B(같은 회사, 사용자는 거래처 권한 있음)로 바꿔 올리기·목록·삭제. **없는 `targetId`**, **품목 화면 권한으로 거래처 대상**도.
- 볼 것: 대상 행 존재·화면 권한 확인 여부(P0 6단계가 "업무 모듈 몫" 으로 남김 — P1 에서 누가 맡았는지 기록 없음).
- 신규 작성 중(저장 전) 첨부 칸이 보이는지 → 보이면 "올린 뒤 취소" 의 주인 없는 파일.

### 2.5 숫자·문자 한계 묶음 — 중

- 엑셀 올리기 **글자 셀**에 `1,200`·`１２０`·`1e3`·`007`·앞뒤 공백 (지금 기록은 숫자 셀 위주).
- 검색어 2000자·제로폭 문자만·NUL — 목록 API 4~5개(품목·BOM 찾기·특성·용어).
- BOM 전개 기준일 9999-12-31, 자산 교정 주기 최대값 + 마지막 교정일 → 다음 교정일 계산 오버플로로 **목록 전체가 500** 이 되지 않는지.
- 코드·이름 칸에 제로폭·NBSP 만 — char-6 #6 은 동의어만 고쳤다. 품목명·거래처명 공통 정리 여부.

### 2.6 브라우저 배율 — 하

- 1366×768 에서 125%·150%: 거래처·품목·BOM·라우팅. 버튼 가림, 서랍 전환 경계.

## 3. 입력 부담(J) 처음 재기

대표 업무 4개를 정해 **누른 횟수(클릭 + 칸 입력 + 확인창)·거친 화면 수**를 적는다. 고치기 전 기준선을 남기는 것이 목적이고, 포트폴리오에서 "숫자로 개선을 보였다" 의 근거가 된다.

| 업무 | 시작 → 끝 | 같이 볼 것 |
|---|---|---|
| 새 품목 1개 등록(단위·유형·클래스 속성 포함) | 품목관리 → 저장 | 매번 같은 값(유형·조달·단위)이 기본값·직전 값인지 |
| 새 BOM 확정(행 5개) | BOM 관리 → 확정 | 단위·투입 방식 기본값, 행 추가 키보드만 |
| 라우팅 새 리비전 CT 하나 변경 → 확정 | 라우팅 → 확정 | 확인창 수 |
| 금형을 다른 설비로 옮김 | 자산 → 해체 → 설치 | "옮기기" 한 번이 아닌 두 번인지 (J 4번째 항목) |
