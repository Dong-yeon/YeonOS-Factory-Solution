# 75. 메뉴 개편 — 2단 하위 폴더 · 내 업무 · 현장·모바일 (2026-11-12)

> 사용자 결정(2026-11-12): 큰 폴더는 2단 하위 폴더로 나누고, 개인 화면은 "내 업무", 단말·모바일 진입은 "현장·모바일" 폴더로 모은다.
> 모바일 웹앱 `/m`(docs/74) 진입을 메뉴에 넣는다. 메뉴는 Flyway(`sys_prog`)·시드로만 바뀐다(CLAUDE.md).

## 1. 왜 바꾸나

| # | 문제 | 근거 |
|---|---|---|
| P1 | 폴더 1단에 화면이 몰렸다 — 기준정보 21·설비 19·품질 17·시스템 20여 개 | `DevCompanySeed` 메뉴 배열(개편 전) |
| P2 | **메뉴에 한 번도 오른 적 없는 화면 11개**: 출하·출하 특이사항·고객 반품 입고·반품 출고·정위치 점검·협력사 클레임·반품 지시·PFMEA·DFMEA·관리계획서·AP 규칙표 | 마이그레이션의 `sys_prog` 목록과 시드 배열 대조(이 문서 작성 때) — 화면은 있는데 시드 배열에 넣지 않았다 |
| P3 | 데모·개발 시드와 운영 콘솔 새 회사 메뉴가 서로 다른 규칙 — 콘솔은 `module_cd` 별 1단 폴더 + 인쇄 팝업까지 전부, 폴더 이름 키도 `menu.prd` 처럼 문구가 없는 키 | `OpsConsoleService.copyDefaultMenus`(개편 전) |
| P4 | 개인 화면(내 알림·내 결재함·내 정보)이 관리 화면들과 같이 "시스템" 폴더에 섞였다 | 시드 배열 |
| P5 | 현장 단말 진입(POP·PDA)이 생산·창고 폴더 끝에 흩어졌고, `/m` 은 메뉴 자리가 없다(`sys_prog` 없음, docs/74 M1) | 시드 배열, docs/74 |

## 2. 결정

| # | 채택 | 버린 안 |
|---|---|---|
| D1 | 메뉴 트리 정의 **한 벌** `platform/security/DefaultMenuTree`(Java 상수) — 시드와 운영 콘솔이 같이 쓴다 | 마이그레이션에 메뉴 행: `sys_menu` 는 회사별(RLS) 표라 Flyway 시점에 회사가 없고, 설치된 회사의 메뉴는 회사 관리자 몫 |
| D2 | 새 화면은 트리에 넣거나 `NOT_IN_MENU`(인쇄 팝업 등)에 근거와 함께 — 시험 `MenuTreeSeedTest` 가 빠진 화면을 잡는다 | 규칙 없이 배열 추가: P2 가 생긴 원인 |
| D3 | 깊이 3단 이하(맨 위 폴더 > 하위 폴더 > 화면). 화면 4개 이하인 모듈(영업·계획·프로젝트·설계 변경)은 1단 그대로 | 모든 모듈 2단: 2~4개 폴더에 하위 폴더는 클릭만 늘림 |
| D4 | 기존 회사(이미 시드된 DB) 옮기기: **시드가 만든 뒤 아무도 손대지 않은 행**(`row_ver = 0` 이고 `created_by = updated_by = 시드 이름`)만 트리 자리로 옮긴다. 메뉴 관리에서 고친 행은 `row_ver` 가 올라가므로 그대로 | 전부 지우고 다시 만들기: 회사가 고친 메뉴를 되돌림 / 안 옮기기: 기존 데모 DB 에 개편이 안 보임 |
| D5 | 화면 본 자리는 그 화면 메뉴가 회사에 하나도 없을 때만 새로 만든다(옛 시드 규칙 그대로). 바로가기는 그 폴더에 없으면 만든다(옛 `ensureShortcut` 그대로) | — |
| D6 | 시드가 만든 빈 폴더 중 트리에 없는 이름은 지운다(이름을 바꿀 때 옛 폴더 정리) | — |
| D7 | `/m` 진입 = 안내 화면 `sys-mobile-app`(개인 화면 `self_service_yn = Y`, SEARCH 만): 주소·[모바일 화면 열기]·[주소 복사]·설치 방법 | 메뉴에 URL 행: `sys_menu` 는 `prog_cd` 로만 화면을 건다 / `/m` 에 `sys_prog`: docs/74 M1 에서 버림 |
| D8 | APQP(PFMEA·DFMEA·관리계획서·AP 규칙표)는 품질 > 개발 품질 — FMEA·관리계획서는 품질 계획 문서(IATF 16949 8.3·APQP 매뉴얼의 산출물) | 프로젝트관리 아래: `sys_prog.module_cd` 는 PMS 지만 사용자가 찾는 곳은 품질 |
| D9 | 설비 상태 타임라인·수집 카운트는 생산 폴더에서 설비 > 상태·모니터링으로 | 생산에 두기: 설비 화면이 두 폴더로 갈라짐 |

## 3. 트리

```
홈 · 업무 흐름 지도                         (맨 위)
내 업무        내 알림 · 내 결재함 · 내 공수(바로가기) · 내 정보
기준정보       품목·BOM / 공장·공정 / 인원·근무 / 품질 기준 / 거래처·연계
영업 · 계획(APS)                           (1단)
생산           작업·실적 / LOT 추적
품질           검사 / 부적합·개선 / 계측·MSA / 변경·문서 / 개발 품질(APQP) + 바로가기 특성·불량 유형
창고           재고 / 입고·출하 / 라벨·자동화
구매           구매·발주 / 협력사
프로젝트 · 설계 변경                        (1단, 설계 변경에 BOM·라우팅 바로가기)
설비           보전 / 상태·모니터링 / 설비 정보(+ 설비·금형 바로가기) / 설비 기준
현장·모바일     현장 단말(POP) · 창고 단말(PDA) · 모바일 웹앱 · 현장 단말 앱 · POP 단말 관리
시스템         사용자·권한 / 운영 설정 / 로그·점검
```

화면별 자리·순서는 `DefaultMenuTree.ROOTS` 가 원본이다(이 그림은 요약).

## 4. 바뀐 것

| 곳 | 무엇 |
|---|---|
| `platform/security/DefaultMenuTree` (새) | 트리 상수·`NOT_IN_MENU`·`progCds()`·`folderKeys()` |
| `platform/security/DevCompanySeed` | 모듈별 배열·`ensureFolder/Menu/Shortcut` 를 없애고 `ensureMenuTree`(D4~D6) 하나로 |
| `platform/ops/OpsConsoleService` | 새 회사 메뉴 = `ensureMenuTree`(P3) — 인쇄 팝업은 메뉴에 안 들어감 |
| `V9950__sys_mobile_app_menu.sql` (임시) | `sys-mobile-app` 화면 등록 |
| `templates/admin/mobile-app.html`·`static/js/views/admin/mobile-app.js` | 모바일 웹앱 안내 화면 |
| `messages*.properties` | 하위 폴더 이름 키 26개·안내 화면 문구·도움말 (ko/en 같은 키) |
| `help-flow.json` | `sys-mobile-app` 앞·뒤 화면 |

파생 설치본 주의: `DevCompanySeed.ensureMenu` 등 private 메서드와 `*_MENUS` 배열이 없어졌다 — 자기 메뉴는 `DefaultMenuTree` 에 덧붙이는 식으로 바꿔야 한다.

## 5. 시험

`MenuTreeSeedTest`(아래 표) + `TerminalEntryTest`(POP·PDA 진입 자리가 `menu.field` 로). 결과는 `docs/testing/sys.md`.

| 시험 | 본 것 |
|---|---|
| 모든 화면이 트리에 | `sys_prog`(use_yn Y) − 트리 − `NOT_IN_MENU` = 빈 집합, 트리의 화면은 모두 `sys_prog` 에, 폴더 키 중복 없음 |
| 새 회사 | 하위 폴더 자리(출하·PFMEA·결재함·모바일 안내·설비 상태·홈), 바로가기, 두 번 돌려도 행 수 같음, 깊이 ≤ 3 |
| 옛 배치 옮기기 | 시드 그대로인 행은 새 자리로 옮겨지고 중복이 안 생김 / 회사가 고친 행·회사 폴더는 그대로 / A사 시드가 B사 메뉴 행 수를 안 바꿈 |
| 권한 | 메뉴 API: 관리자는 새로 넣은 화면이 보이고, 거래처 권한만 있는 사용자는 출하가 안 보이고 모바일 안내(개인 화면)는 보임 |
