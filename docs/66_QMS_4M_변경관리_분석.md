# 66. QMS 4M 변경관리 — 지금 상태 분석 · 빈곳 · 제안 (결정 요청)

> 작성 2026-11-04 · QMS 2차 하위 세션(`claude/qms-wave2`) · 상태: **조사·제안 — 구현은 9장 결정 뒤** · 코드 변경 없음
> 계기: docs/29 2.6 "2026-11-03 사라진 작업" 표의 QMS 행 "4M 변경관리 분석 문서"(원본은 세션과 함께 사라져 다시 씀).
> 근거: ① 이 저장소의 코드·설계(docs/29_P3 11·12.1·12.3·12.9·20장, docs/39 13·14·16·23장) — [코드]로 표시 ② 공개 표준의 **요구 취지**(IATF 16949:2016 8.5.6·8.5.6.1·8.5.6.1.1·8.3.6·7.2, AIAG PPAP 4판 고객 통지·제출 대상 변경, AIAG-VDA FMEA 의 변경 시 재평가) — 원문 인용 없이 취지만 ③ 회사·고객사 자료는 쓰지 않았다(SKILL §0).
> 표기: [코드] = 코드로 확인, "추정" = 확인 안 됨. 문서 번호 66 은 2026-11-04 기준 비어 있던 번호 — 상위 세션 번호와 겹치면 병합 때 다시 매긴다.

## 1. 결론 먼저

- 4M 변경은 지금 **"설계·공정 변경(ECO) 한 건에 붙는 4M 세부"** 로만 있다(결정 D1, docs/29_P3 11장). ECO 의 결재·고객 승인·LOT 표시·첫 LOT 초품·착수 경고·PCN 메일까지 이어져 **계획된 큰 변경**은 IATF 8.5.6 의 뼈대(영향 평가 → 승인 → 검증 → 추적)를 대부분 덮는다.
- 빈곳은 네 묶음이다. **(가) 현장의 작은 변경점**(작업자 교대·대체 작업자, 수리 뒤 재가동, 같은 규격 자재의 공급사 LOT 바뀜, 지그·공구 교체)이 ECO 가 무거워 기록되지 않는다. **(나) 임시 변경(TEMP)의 복귀 확인**이 없다 — 표시 끝 날짜만 있고 "표준으로 돌아왔다" 는 기록·기한 경보가 없다(8.5.6.1.1). **(다) 변경 뒤 효과 확인**이 첫 LOT 초품 하나뿐 — 변경 전후 공정 능력·불량률 비교가 없다. **(라) 고객 통지 판단**이 ECO 의 "고객 승인 필요" 체크 하나에 맡겨져 있다 — 고객별 요구(CSR)와 4M 유형을 잇는 규칙이 없다.
- 추천 순서: **(나) → (다) → (라) → (가)**. (나)·(다)는 지금 표·계약 위에서 작게 되고 감사 질문("임시 조치가 언제 끝났나", "바꾼 뒤 괜찮은가")에 바로 답한다. (가)는 D1("4M 을 ECO 없이 따로 시작하지 않는다")을 바꾸는 결정이라 마지막에, 사용자 결정으로.

## 4. (나) 임시 변경 복귀 확인 — 제안

| # | 안 | 이유 |
|---|---|---|
| T-1 | `qms_change` 에 복귀 확인 칸(`reverted_at`·`reverted_by`·`revert_note`) — TEMP ECO 가 RELEASED 뒤에만 기록, 한 번(고침 = 무효 후 다시, 무효 사유) | 복귀 조건 글은 이미 있다(V094). "언제 누가 표준으로 돌렸나" 가 빠진 것이 감사 질문의 답이 비는 자리 |
| T-2 | 홈 카드 "복귀 기한 지난 임시 변경" = TEMP·RELEASED·복귀 기록 없음·`mark_until` < 오늘(회사 시간대). 링크 → `qms-change` 필터 | 표시 끝이 지나도 아무도 모르는 것이 조용한 실패 |
| T-3 | 복귀 기록과 LOT 표시는 묶지 않는다 — 표시 끝은 PLM 칸 그대로(QMS 는 `plm_eco_lot` 에 쓰지 않음, 11.6) | 경계 유지. 표시 끝보다 일찍 복귀하면 그 뒤 LOT 도 TEMP 로 표시되는 것은 남는다 → 질문 Q4-2 |

## 6. (라) 고객 통지 판단 — 제안

| # | 안 | 이유 |
|---|---|---|
| C-1 | 고객 CSR(`qms_csr`)에 "4M 유형별 통지 요구"(유형 × 통지만/승인 필요) 칸 | 고객마다 다르다 — 사람이 매번 기억하게 두면 빠진다 |
| C-2 | ECO 상신 규칙(④)에 경고: ECO 대상 품목의 고객 CSR 이 그 4M 유형에 승인을 요구하는데 ECO "고객 승인 필요" 가 N → 칸 경고(막을지는 정책) | 숨긴 체크는 막은 것이 아니다 — 서버 규칙으로 |
| C-3 | 품목 → 고객은 수주 이력 기준 "추정" 이 될 수밖에 없다(품목 마스터에 고객 칸 없음, 추정) — 대상 고객을 사람이 고르게 할지 질문 Q4-4 | 정의 없는 것을 임의로 정하지 않음 |

## 7. (가) 현장의 작은 변경점 — 제안(결정 필요 — D1 과 부딪힘)

지금은 작업자 교대·수리 뒤 재가동·자재 공급사 LOT 바뀜 같은 **일상 변경점**을 남길 곳이 ECO 뿐이다. ECO 는 결재·고객 판단을 거치는 무거운 길이라 현장이 쓰지 않는다 → 기록이 없다.

| 안 | 내용 | 장단 |
|---|---|---|
| **(1) 현장 변경점 기록(추천)** | 새 표 `qms_4m_event`(원장 — 추가만): 4M 유형·공정·설비·작업지시·LOT(선택)·서술·발생 시각. **ECO 가 아니다** — 결재 없음, LOT 표시 없음. 자동 후보: MES 작업자 바뀜(착수 이벤트의 작업자 ≠ 직전), CMS 보전 작업지시 완료 뒤 첫 착수, WMS 자재 입고 공급사 바뀜 → "확인 필요" 목록으로만(사람이 확인·메모) | 장: 감사 "그날 무엇이 바뀌었나" 에 답, 큰 변경과 분리. 단: 키가 둘(ECO·현장 변경점) — D1 의 "키 하나" 를 **"LOT 표시 키는 ECO 하나"** 로 좁혀 다시 정해야 함 |
| (2) ECO 간이 유형 | `change_kind = MINOR`(결재 생략) | 장: 키 하나 유지. 단: PLM 상태 기계·결재 규칙에 예외가 생김, PLM 세션 몫 |
| (3) 하지 않음 | 지금처럼 ECO 만 | 일상 변경점은 MES·CMS 원장(작업자·보전 기록)에서 사람이 찾는다 |

## 8. 하지 않을 것(이 문서 범위)

- 변경점 관리판(현장 대형 화면) — 홈 카드·목록으로 먼저, 키오스크 화면은 수요 뒤
- 협력사 4M 신고 — SRM 협력사 포털(docs/42) 뒤
- 변경 뒤 검사 빈도 자동 강화(E-3)
