## 결함 상세 · 제안 수정 (수정은 개발 세션)

### #1 넓은 열 셀 하나로 힙 고갈 — 높음

- 재현: 템플릿 첫 시트 XML 의 데이터 행에 `<c r="XFD2" t="inlineStr"><is><t>x</t></is></c>` 추가 → `ExcelSheetReader.read` 결과 행의 `cells().size() == 16384`(헤더는 11). 같은 모양 50,001행 파일 1.6MB 미만(첨부 상한 20MB, 압축 비율 검사 통과).
- 원인: `ExcelSheetReader.Collector.cell` 이 `while (cur.size() < col) cur.add("")` — 열 번호 상한이 없다. 행이 `rows` 에 모두 쌓인 뒤에야 엔진이 헤더 열만 고른다.
- 영향(추정, 미실측): 행당 참조 16,384 × 4B ≈ 64KB(+ArrayList 여유) × 50,000행 ≈ 3.2GB+. 업로드는 저장 권한만 있으면 된다.
- 제안: `ExcelSheetReader` — 헤더 행의 마지막 비지 않은 열(또는 고정 상한, 예 256)을 넘는 셀은 버린다. 첫 행(헤더)도 상한 적용. 가능하면 행을 모두 모으지 말고 콜백으로 스테이징까지 흘린다(메모리 = 배치 크기).

### #2 긴 셀 크기 증폭 — 중간

- 재현: 품목명·규격·비고에 같은 32,767자 문자열(공유 문자열 1개) 300행 → 파일 14KB, `sum(octet_length(data::text))` 86MB. 검증은 `TOO_LONG` 으로 막지만 원문은 그대로 저장.
- 원인: `ImportService.stage` 가 `raw` 를 칸 길이 제한 없이 jsonb 로. 읽기 단계도 행마다 같은 문자열을 참조하다 JSON 으로 펼치며 배치(1000행)마다 수백 MB 를 만든다.
- 제안: `ImportService.stage` — `raw` 의 각 칸을 상한(예 1,000자 또는 템플릿 열 최대 길이 + 여유)으로 자르고 잘렸다는 표시를 남긴다(오류 엑셀에 "…(잘림)"). 작업당 `cnt_total × 열 수 × 상한` 이 정책 상한을 넘으면 거부도 고려.

### #4 변경 모드 빈 Y/N 칸 — 중간

- 재현: LOT=N 품목을 사용 중지 → 같은 템플릿에 코드·이름·필수 칸만 채워 "새 것 + 변경" → 실행 → `use_yn·lot_ctrl_yn = Y·Y`. 브라우저: 미리보기 "변경 1 · 콘택트 팁(엑셀 이름 변경) · CON" 만 보이고 확인창 "변경 1건" → 실행 후 LOT N→Y.
- 원인: `ItemService.validate` 가 빈 `lotCtrlYn`·`useYn` 을 `Y` 로 정한 값을 그대로 돌려주고, 엔진은 "파일에 있는 열"(열 제목이 있으면 빈 칸이어도)을 모두 덮는다. 안내 시트 문구 "비우면 Y" 는 신규만 생각한 것. 순질량·HS 같은 선택 칸은 빈 칸이면 **지운다**(같은 원리라 일관되긴 하지만 사용자는 "안 건드림"으로 기대하기 쉽다).
- 제안: `ImportService.stage`/`execute` — 변경(UPSERT) 행에서 **빈 칸은 기존 값 유지**(`Validated` 에 "빈 칸이었던 열" 집합을 담거나 템플릿이 `values` 에 null 로 두고 기본값은 insert 때만). 지우기가 필요하면 별도 표기(예 `-`)로. 안내 문구 `import.guide.yn` 을 "신규에서 비우면 Y, 변경에서 비우면 그대로" 로. 미리보기 "변경" 행에 바뀌는 열 목록을 보여 주면 더 좋다.

### #10 순질량 표시 4자리 — 중간

- 재현(브라우저 1366): 순질량 `0.000012` 품목 → 목록 `0.0000`, 상세 `0.000012`. `0.12345` → 목록 `0.1235`. 엑셀 내보내기 값 1.2E-05(정확) · 서식 `#,##0.0000`(표시 0.0000).
- 원인: `ItemService.COLUMNS` `ColumnSpec.dec("netMassKg", …, 4, 110)` vs `MASS_SCALE = 6`.
- 제안: `ItemService.COLUMNS` 의 순질량 scale 을 6 으로(hb.grid 가 끝 0 을 채운다면 상세처럼 "자릿수 상한"만 쓰는 표시 옵션 — `data-pad="false"` 와 같은 뜻 — 을 열 정의에).

### #5 코드 열 서식 — 낮음~중간

- 재현: HS 칸에 숫자 셀 303891000(사용자가 0303891000 을 그냥 입력한 결과) → 새로 1, 실행 후 `hs_cd = 303891000`. 품목코드도 `00123` 같은 숫자형 품번은 `123` 으로.
- 원인: `ImportService.templateFile` 이 데이터 시트 열 서식을 지정하지 않는다(일반). 읽기는 숫자 셀을 숫자로.
- 제안: `ImportService.templateFile` — `ImportColumn` 에 "텍스트 열" 표시(또는 코드 열·키 열 기본)를 두고 해당 열 기본 스타일을 `@`(텍스트)로. HS 처럼 길이가 정해진 코드는 숫자 셀이면 경고(행 오류 `NUMERIC_CELL`)도 고려.

### #3 NUL 문자 500 — 낮음

- 재현: `POST /api/master/items` 이름 `"앞\u0000뒤"` → 500 `DB_ERROR`(22021). 엑셀 셀 `이름_x0000_끝` → 500(22P05 `json_errsave_error`), 브라우저 대화상자 "데이터 처리 중 오류가 발생했습니다".
- 제안: 서버 공통 — `ItemService.text`(그리고 거래처 등 같은 `text` 도우미)에서 C0 제어문자(탭·줄바꿈 제외) 포함 시 `FORMAT` 칸 오류. 엔진은 `ImportService.clean` 에서 U+0000 제거(또는 행 오류). 대안: `ApiExceptionHandler` 가 22021·22P05 를 400 `INVALID_VALUE` 로 매핑(원인 칸은 못 알려 줌).

### #6 오류 엑셀 수식 주입 방지 없음 — 낮음

- 재현: 품목코드 `=HYPERLINK("http://x","a")` → 형식 오류 → 오류 엑셀 B2 = `=HYPERLINK(…)`(문자열 셀). 사용자가 셀을 편집(F2 → Enter)하면 수식이 된다.
- 제안: `ImportService.errorReport` 의 원문·오류 문구 셀에 `ExcelExportService.safeText`(지금 package-private — 공용으로) 적용.

### #7 셀 순서 뒤바뀐 행 — 낮음

- 재현: `<row r="2"><c r="B2">이름</c><c r="A2">R1</c>…` → 칸 `["", "이름", "R1"]`.
- 원인: `Collector.cell` 이 "지금 길이 < 열 번호" 일 때만 채우고, 작으면 그냥 뒤에 붙인다.
- 제안: `Collector` — 열 번호 위치에 `set`(필요하면 늘림). #1 의 상한과 함께.

### #8 숫자 셀 double 잡음 — 낮음

- 재현: `<c r="H2"><f>0.1*3</f><v>0.30000000000000004</v></c>`(Excel 이 저장하는 모양) → 순질량 `SCALE`.
- 제안: `ExcelSheetReader.RawFormatter` — `new BigDecimal(value).round(new MathContext(15))` 후 `stripTrailingZeros`(Excel 표시 정밀도 15자리). 서식 반올림은 여전히 무시.

### #9 검증 뒤 참조 코드 변경 — 낮음

- 재현: 회사 단위 `QBX` 로 신규 1행 검증 → 단위 사용 중지 → 실행 409 `IN_USE`. 반영 0·작업 VALIDATED(정상) — 문구만 문제.
- 제안: `ImportService.execute` 의 `flush`·`update` 에서 `DataIntegrityViolationException` 중 23503 을 `IMPORT_STALE`(첫 행 번호)로. 근본적으로는 실행 때 NEW·CHANGE 행을 세션으로 다시 검증하는 방법도 있다(5만 행 비용 확인 필요).
