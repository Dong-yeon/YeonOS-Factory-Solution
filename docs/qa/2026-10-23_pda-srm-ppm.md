## 1. WMS 창고 PDA (B7-1)

### 1.1 PQ-1 — 멱등 키가 내용·출처를 보지 않음 (정책 질의)

**[코드]** `InventoryService.postAs`: `clientReqId` 가 있으면 `mapper.findReq(req)` 로 같은 id 의 원장 행을 찾고, 있으면 그대로 `replay=true` 를 돌려준다.
- `findReq` 는 `inv_trx` 전체에서 찾는다. 출처(`src_type`)·품목·위치·수량을 비교하지 않는다.
- 유일 제약도 `(comp_cd, client_req_id, req_seq)` 라 회사 안 모든 원장 쓰기(사무 화면·POP·PDA)가 한 이름 공간을 쓴다.

**[재현]** `같은_요청_id_다른_내용과_다른_출처_행은_처음_결과로_200`
- PDA 이동 3(A→B) 뒤 같은 id 로 반대 방향 1 → 200 `replay=true`, 처음 원장 id. 두 번째 이동은 일어나지 않는다.
- 사무 쪽 조정 행이 쓰던 id 로 PDA 이동 2 → 200 `replay=true`, 그 조정 행 id. 이동은 일어나지 않는다.

단말은 확정마다 새 UUID 를 만들기 때문에 실제 충돌은 단말 버그(대기열이 id 를 재사용)일 때뿐이다. 다만 그 경우 화면은 "성공" 을 보이고 재고는 움직이지 않는다 — **조용히 틀림**.

**질문:** 다음 중 무엇으로 할까?
- (가) 같은 id·다른 내용은 409(예: `REQ_MISMATCH`). 처음 요청의 품목·위치·수량 요약을 비교한다.
- (나) 현행 유지 + docs/30 에 "id 는 단말이 확정마다 새로" 를 규칙으로 적는다.

비교 **[코드]**: POP 실적은 종류별 표(`prd_result` 등)에 id 를 두고, 재전송 때 대상 공정(`woProcId`)이 다르면 `DUPLICATE_REQUEST` 로 거부한다(`PopWorkService.replayResult`). PDA 이동은 이 대상 확인이 없다.

## 2. SRM 입고 PPM (R4a) ← QMS 계약

모듈 시험 `EvalPpmTest` 는 `@MockitoBean` 으로 계약을 바꿔 끼운다. 여기서는 진짜 수입검사·NCR 을 만든 뒤 평가 생성까지 잇는다.

### 2.1 QE-1 — 무효 검사의 NCR 과 PPM 식 (정책 질의)

**[코드]** `EvalService.recvPpm`
- `inspected = Σ inspectedQty`, 0 이면 `PPM_NONE`(사람 입력).
- `rejected = Σ rejectedQty`(검사 수량 0 인 줄 포함), `ppm = rejected ÷ inspected × 10⁶`.

**[코드]** QQ-1 결정 뒤 계약은 무효 검사 LOT 의 NCR 을 "검사 0 / 불량 n" 줄로 돌려준다(판정 시각 = 근거 검사 판정 시각).

**[재현]** `무효_검사의_NCR_불량과_PPM_식`

| 그 협력사의 기간 데이터 | SRM 결과 |
|---|---|
| ① LOT 50 NG → NCR 6(OPEN) → 검사 무효, 다른 검사 없음 | `PPM_NONE`(사람 입력). 불량 6 은 근거에도 안 남는다 |
| ② ① + LOT 100 OK 검사 → 다시 계산 | `PPM:100:6:1:0`, 60,000 PPM → 0점. 분모 = OK LOT 100, 분자 = 무효 LOT 의 불량 6 |

QQ-1 의 결정은 "NCR 이 살아 있으면 불량은 남긴다" 였다. SRM 식은 분모(검사 수량)를 판정이 있는 LOT 으로만 잡으므로, 같은 불량이 ① 에서는 0 이 되고 ② 에서는 남의 분모에 얹힌다. 무효된 LOT 크기(50)가 분모에 없어 ② 는 과대 평가된다(LOT 을 넣으면 6/150 = 40,000).

**질문(SRM·QMS):**
- (가) 무효 검사 LOT 의 LOT 수량도 분모에 넣는다 — 계약이 `inspectedQty` 에 넣거나, 별도 칸을 준다.
- (나) 검사 수량 0 줄의 불량은 PPM 에서 빼고 근거에만 둔다(`otherNcQty` 처럼).
- (다) 현행 유지 + 근거에 "검사 없는 불량" 을 따로 적어 사람이 보게 한다. ① 의 `PPM_NONE` 근거에 불량 수가 없는 것은 어느 쪽이든 고칠 만하다.

시험은 현행 값을 고정했다.
