## 1. B3 — 품질 상태 연동

**[코드] 흐름**: QMS 판정·무효·NCR 종결이 같은 트랜잭션에서 계약 `QualityStockLink` 를 부른다 → `QualityStockPosting`.
- 잠금 순서는 QMS 행 → LOT(공유) → 재고 칸(`lockCells`, id 순)이다. 칸을 잠근 **뒤의 수량**으로 판단한다(`lock()` 이 다시 읽음).
- 반영 여부는 출처 원장(`liveTrxOf(QMS_INSP|QMS_NCR, id)`)으로 본다. 다시 불러도 한 번만 반영된다.

| 해 본 것 | 결과 | 근거 |
|---|---|---|
| 같은 LOT 의 NCR 두 건(폐기 6 + 6, BLOCKED 10)을 동시에 종결 — 첫 건이 칸 잠금을 쥔 채 커밋을 미루고, 둘째가 기다리는 것을 관찰한 뒤 커밋 | 첫 건 성공, 둘째 409 `WMS_QUALITY_SHORT`, SCRAP 1건, BLOCKED 4 | [재현] |
| OK 판정 → 스위치 N → 무효 | 되돌림(QC 10) — 무효는 스위치와 무관하게 판정이 남긴 원장 짝을 되돌린다 | [재현] |
| NG 판정 → 스위치 N → NCR 폐기 종결 | 오류 없음, 재고 그대로(BLOCKED 10), QMS_NCR 원장 0 — **B-1** | [재현] |
| 판정 뒤 같은 LOT 추가 생산 입고 | 다시 QC 고정, 판정은 "이미 반영" — **B-2** | [코드] `QcReceiptRule.status`, `QualityStockPosting.onInspJudged` 의 `liveTrxOf` 확인, `prd_receipt` LOT 합 트리거(V055) |
| 스위치가 켜진 공장·꺼진 공장에 걸친 LOT 의 NCR 종결 | 켜진 공장 칸만 센다 — 처분 합이 그보다 크면 409 `WMS_QUALITY_SHORT`(종결이 막힘, 조용히 틀리지 않음) | [코드] `onPlants` |

## 2. 메일 발행 취소 (#504)

- **[코드]** `MailService.cancel` 은 조건부 UPDATE 한 문장이다. 조건은 지금 회사 · MAIL 주제 · EXTERNAL · `status = 'NEW'`. 릴레이가 집으면(SENDING) 0건이라 한쪽만 이긴다.
- 모듈 시험 6건이 경합·재시도 대기·보낸 뒤 409·A사로 B사·사내 알림 404·롤백을 덮는다.
- 지금 **모듈 호출자는 없다**(플랫폼 API 만).
- 화면: PCN 이력은 `mail.state.CANCELED` 문구가 있다.
- SRM 통지(`SRM_*` 주제)·라벨 인쇄(LABEL)는 다른 주제라 CANCELED 가 생기지 않는다. 그 화면들의 상태 목록(NEW·SENDING·SENT·FAIL)은 그대로 맞다.
- **M-1**: 재시도 대기 행은 직전 시도가 시간 초과(배달 여부 모름)였을 수 있다. 취소는 "다시 보내지 않음" 만 보장한다. 화면 문구 "취소함(보내기 전)" 은 그 경우 틀릴 수 있다 — 문구를 "더 보내지 않음" 으로 하거나 시도 횟수(attempts > 0)를 함께 보여 주는 안.

## 3. PLM PCN 통지서 사본 (#518)

- **[코드]** 보낼 때 그 시점 통지서(xlsx)를 대상 `plm-eco × PCN-{id}` 에 `attachAs(reuseSameContent)` 로 넣는다. 같은 내용이면 있던 사본을 쓰고, 대상 단위 advisory 잠금이 걸린다.
- 그 사본 하나를 모든 메일에 붙이고 이력 `notice_file_id` 에 남긴다. 원장이라 insert 때만 채우고, 트리거가 같은 회사·그 통지 대상·사용 중을 확인한다.
- 사용자는 `PCN-*` 대상에 올리거나 지우지 못한다(`PlmFileLock`). 서버만 그 트랜잭션에서 연다(`NOTICE_ATTACHING` 리소스).
