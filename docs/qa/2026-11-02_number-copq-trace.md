## 1. hb.number (N1~N3)

| 해 본 것 | 결과 | 근거 |
|---|---|---|
| N1 값 있는 칸에 Tab 으로 들어와 입력 | 바꾸기(옛 값 뒤에 붙지 않음) — 포커스 때 전체 선택이었으면 원값으로 바꾼 뒤 다시 전체 선택 | [코드] `hb.input.js` focus 처리 · 시스템관리 실제 Chromium 재현·고침 확인(docs/testing/sys.md) · `hb.input.number-focus.test.js` 4건 통과 |
| N2 붙여넣기: 쉼표 위치 틀림(`1,23`·`1,2345`)·공백 묶음(`1 234`)·유럽식(`1.234,5`)·지수·통화·유니코드 빼기(`−5`)·아랍 숫자 | 모두 오류(NUMBER) — 조용히 고치지 않음. 전각 숫자·전각 쉼표(`１，２３４`)는 NFKC 로 정상 해석 | [재현] node `hb.numbers.parse` · `hb.numbers.test.js` |
| N2 전체 선택 뒤 붙여넣기 | 바꾸기 | `hb.input.number-focus.test.js` |
| **N-a** 첫 묶음이 0 인 쉼표 숫자 | `0,123` → `123`, `00,123` → `123`, `0,123.5` → `123.5` — 천 단위 묶음으로 성립하지 않는 모양(첫 묶음은 1~999)인데 받음. 소수점 쉼표 지역(유럽 엑셀 등)에서 `0,123`(=0.123)을 붙여넣으면 123 으로 조용히 저장 | [재현] node |
| N3 웨지(빠른 키 + Enter) | Enter 로 조회·저장할 때 `value()` 가 포커스 중이면 칸을 다시 읽음(`read()`) — 마지막 글자까지 반영. 클릭으로 들어와 캐럿이 끝이면 붙음(브라우저 기본 — #684 에서 의도로 남김) | [코드] |

- `1,500` 은 천 단위(1500)로 읽는다 — 한국어 표기로는 맞고, 소수점 쉼표 지역 값과는 구분할 수 없다(정책 — 회사 숫자 표기 설정이 생기기 전까지 그대로가 맞음).
- **N-a 안**: `GROUPED = /^[1-9]\d{0,2}(,\d{3})+(\.\d+)?$/` — 첫 묶음 0 시작 거부(오류로 보이게). 부록 A 의 JS 시험을 켠 채로.
