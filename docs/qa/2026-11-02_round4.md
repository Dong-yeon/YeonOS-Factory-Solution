## 2. R4-a 필수 사유 칸의 보이지 않는 글자 (고칠 것, 중간)

[코드] 판정 함수는 모듈마다 따로 있고 모두 `s == null || s.isBlank()`(Java `Character.isWhitespace` 기준 — U+200B 형식 문자·U+FEFF·U+00A0 은 공백이 아님): `sales/OrderService`·`qms/SamplingService`·`srm/SrmChecks`·`cms/CmsSupport`·`apqp/ApqpInputs`·`pms/PmsInputs`·`plm/EcoService` 등 약 25벌, 그 위 `text()` 는 `strip()` + 제어문자(`\p{Cc}`)만. WMS 사유는 `strip()` 뒤 `length() < 2`. **플랫폼 공통 도우미 없음**(platform/common 에 문자열 판정 없음).

보이지 않는 글자를 이미 막는 곳은 모두 **사유가 아닌 칸**: `ClassPropService.INVISIBLE`(`[\s\p{Z}\p{Cf}]+` 지운 뒤 빈지 — 가장 좋은 본보기, private)·`ExtService.extText`·`DefectTermService.normalizeAlias`·`FileService.BAD_NAME_CHARS`.

## 4. K5 hb.kiosk (#776, POP 홈 연결 #788)

[코드] `hb.kiosk.js` `makeKiosk`: `exit(badge, pin)` = 서버 응답 뒤 `kiosk(false)` + 다시 잠금 타이머, `worker(code)` = 앞과 다르면 `lock()`(타이머 정리 + `kiosk(true)`). `pop/home.js` 가 상태 갱신마다 `kiosk.worker(s.workerCd)`, 대화상자가 열려 있으면 스캔을 감독자 배지로. 다리가 없는 브라우저는 아무 일도 안 함(서버도 안 부름).

[재현] node(가짜 다리·서버·타이머, `makeKiosk` 직접):

| 경우 | 다리 호출 순서 | 끝 상태 |
|---|---|---|
| 작업자 A → `exit` 요청 중 → 작업자 B(잠금) → 성공 응답 | `kiosk(true)`, `kiosk(false)` | **풀림**(600초 타이머) → K-c |
| `exit` 성공 응답 → 기기가 `kiosk(false)` 거절 | `kiosk(false)`(거절) | 잠김, 화면 오류(거절 메시지), 타이머 없음 — 서버 기록은 성공 → K-d |

- K-c 질의: 요청을 보낼 때의 작업자와 응답을 받을 때의 작업자가 다르면 풀지 않는다(요청 세대 번호) — 로 할지. 감독자가 승인한 것은 "그 순간의 단말" 이라 지금도 받아들일 수 있다.
- K-d 질의: 서버 기록을 "확인됨(OK)" 으로 두고 실제 해제 여부는 기록하지 않는다(지금) / 화면이 해제 실패를 다시 알린다(새 API·기록) — 실기에서 거절이 실제로 나는지(MDM 기기는 거절 안 함) 먼저 보고 정하는 것을 권함.
- 미실행: 실제 APK·단말(구석 5초 길게 누르기, 두 단말 동시, 세션) — K 항목은 실기 확인 필요.
