### H-a "내 할 일" 목록 50건 상한이 말없이 잘림 (고칠 것, 낮음)

- 홈 카드는 56 인데 카드를 눌러 연 화면에는 50건만 있다. 작업(`findMyTasks`)·산출물(`findMyDelivs`)도 같은 50 상한 — 카드의 지연 작업·산출물 수와 같은 어긋남이 생길 수 있다(추정, 같은 코드 모양).
- 고칠 방향(안): 응답에 건수(또는 잘림 표시)를 실어 화면이 "50 / 56 — 전체 보기" 를 보이게. 상한을 없애는 것은 권하지 않음(내 할 일은 짧은 목록이 목적).

## 5. MES K5 키오스크 빠져나오기(#768, V226)

[코드] `POST /api/pop/kiosk/exit` → `PopAuthService.kioskExit` → 승인과 같은 `supervisor(...)`: 단말 배지 제한(`throttled`) → 배지(형식·해시는 회사별) → 사용 중 → 자격(정책 `POP_APPROVER_QUAL`, 공장 날짜) → PIN 있음 → `checkPin`(작업자 PIN 카운터 5회 → 15분). 실패는 `POP_KIOSK_EXIT_FAIL`(사유), 성공은 `POP_KIOSK_EXIT`(worker=감독자, 행위자 = 단말). 서버는 잠금 상태를 갖지 않는다(다시 잠그기 = 화면, 600초).

| 상위 지정 | 결과 | 근거 |
|---|---|---|
| 감독자 아닌 배지 · 자격 만료 · PIN 틀림 · PIN 없음 · 빈 본문 | 403 · 403 · 400 · 409 · 400, 실패 사유 기록 | 모듈 시험 |
| 잠김 상태(빠져나오기 5번 틀림) | 다섯째 423, 맞는 PIN 도 423 | 모듈 시험 |
| **잠김 — 다른 경로에서 시작**(승인에서 4번 틀림 → 빠져나오기 1번 틀림) | 423 잠김, 맞는 PIN 으로 빠져나오기·승인 모두 423, `PIN_LOCKED` 기록 1, 실패 사유 `locked` | [재현] `PopKioskQaTest` — 카운터가 경로 사이 양쪽으로 공유됨 |
| **사용 중지된 감독자**(퇴사) | 400 `BADGE_UNKNOWN`(작업자 코드 안 드러남, 사유 badge), PIN 카운터 그대로 0 | [재현] |
| 다른 회사 배지 | 400 `BADGE_UNKNOWN`, B사 기록 없음 | 모듈 시험 |
| 배지 맞히기(승인과 실패 카운터 공유) | 배지 로그인 6 + 빠져나오기 4 = 10 → 맞는 감독자도 429 | 모듈 시험 |
| **표기 바꿔 맞히기** | 앞뒤 공백은 지움(같은 감독자 200), 소문자·전각 배지는 없는 배지(400) | [재현] |
| 단말이 아닌 사용자 세션 | 401(쿠키 없음)·사무 사용자 거부 | 모듈 시험 |
| 접속 로그 | 성공 `OK|worker=S1|t{id}:{코드}|POP`, 실패 사유별 | 모듈 시험 + [재현] |
| **제한에 걸린 뒤 시도의 기록** | 429, `BADGE_THROTTLED` 1행 — `POP_KIOSK_EXIT_FAIL` 은 안 늘어남 → K-b | [재현] |
| 배지 존재 노출 | 감독자 아닌 배지 403 vs 없는 배지 400 → K-a | [재현]·[코드](승인과 같은 분기) |

- K-a 질의: 빠져나오기·승인 모두 "감독자 아님" 과 "없는 배지" 를 같은 응답(예: 400 `BADGE_UNKNOWN` 또는 403)으로 합칠지. 기록(사유 qual/badge)은 서버에 그대로 남기면 된다. 단말 제한(1분 10회)이 있어 위험은 낮다.
- K-b 질의: 키오스크 화면에서 막힌 시도도 `POP_KIOSK_EXIT_FAIL`(사유 throttled)로 남길지, 지금처럼 단말 공통 `BADGE_THROTTLED` 로 둘지.
