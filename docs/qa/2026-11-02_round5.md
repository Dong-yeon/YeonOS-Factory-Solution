## 2. WMS 고객 반품 ERP 송신(#791)

[코드] `CustRtnErpPublisher.publish(r, sign, at)` — 반품 입고·취소 트랜잭션 안(MANDATORY)에서 정책 `ERP_SYSTEM` 이 등록된 어댑터일 때만 아웃박스 `ERP_CUST_RTN` 한 행, 업무 키 = 반품번호-R(입고)/-C(취소), 취소는 음수 수량. 같은 요청 다시는 `findByReq` 가 먼저 돌려줘 발행 안 함, CR-a(남의 원장 요청 id) 409 는 같은 트랜잭션이라 전표도 롤백. 모듈 시험 `CustRtnTest#ERP_반품_전표는_*` 가 양수/음수·같은 요청·CR-a·A사로 B사를 덮는다.

| 확인 | 결과 | 근거 |
|---|---|---|
| 같은 반품 취소 두 번 동시(같은 rowVer) | 200/409, 아웃박스 `-R:2, -C:-2` 하나씩 | [재현] `CustRtnQaTest#ERP_반품_취소_동시_두_번이면_음수_전표도_하나` |
| 어댑터 없이 받음 → 어댑터 켬 → 취소 | 아웃박스 `-C:-2` **만** | [재현] 임시 시험(정책 질의라 커밋 안 함) → R5-a |
| 출하 송신도 같은가 | `ShipErpPublisher.shipped` 도 발행 순간 정책만 본다(키 = 출하번호-줄-v행버전) — 같은 모양 | [코드] |

- R5-a 질의: (가) 취소 때 짝(+)이 아웃박스에 있을 때만 음수 발행 / (나) 지금처럼(어댑터를 켜는 시점에 이미 받은 반품·출하는 ERP 쪽에서 맞춘다 — 운영 안내) / (다) 어댑터를 켤 때 미송신 건을 한꺼번에 송신. 출하와 같은 결정으로.

## 3. POP 홈 키오스크(#789 — `pop/home.js` 가 `hb.kiosk.attach()`)

[재현] 로컬 앱(DEMO, Playwright Chromium, `LANG=C.UTF-8`). 시험 준비: DEMO 작업자 E1001 = 감독자(배지·PIN·자격 `ZTSUP`, 정책 `POP_APPROVER_QUAL`), E1002 = 조작자, POP 단말 활성화.

| 경우 | 결과 |
|---|---|
| 다리 없음(일반 크롬) | `hb.kiosk.available()` false, 포커스 = 숨은 스캔 칸, 배지 로그인 정상, 페이지 오류 없음 |
| 가짜 다리(`Capacitor.Plugins.YeonShell.kiosk` 기록) — 홈 열림 | `kiosk(true)` |
| 조작자 로그인 → 오른쪽 위 구석 5초 길게 누르기 | 해제 대화상자 열림, **포커스 = 대화상자 [취소] 단추** |
| 대화상자 열린 채 **웨지 스캔**(감독자 배지 글자 + Enter) | 배지 안 읽힘, 숨은 스캔 칸 값 없음, **Enter 로 대화상자 닫힘**, 작업자 그대로 → **K-e** |
| 대화상자 열린 채 **SDK 스캔**(`hb:scan` 조작자 배지) + PIN | "감독자 자격이 있는 작업자만 승인할 수 있습니다." — 잠금 유지 |
| SDK 스캔 감독자 배지 + PIN 2468 | `kiosk(false)`, 대화상자 닫힘, 작업자 그대로 |
| 작업자 바꾸기 | `kiosk(true)` — 다시 잠금 |

[코드] K-e 원인: `hb.scan.listen(…, {input})` 은 웨지를 **숨은 칸의 keydown** 으로만 받는다(`hb.scan.js` `onInputKey`). `showModal` 은 대화상자 밖을 비활성으로 만들어 숨은 칸에 포커스·키가 가지 않고, `hb.pop.scanner` 의 포커스 되돌리기도 못 한다. 대화상자에는 배지를 받을 칸이 없다.

- 고칠 방향(안): 대화상자 안에 숨은 스캔 칸을 두고 열 때 포커스 → 그 칸의 Enter 를 `badge(v)` 로(웨지), 또는 대화상자가 열려 있는 동안 `hb.scan.listen` 을 문서 키 모드(입력 칸 없이 — 빠른 키 + Enter 판정)로 따로 듣기. [취소] 를 첫 포커스로 두지 않기(Enter 로 닫히지 않게). 시험: 이 흐름의 Playwright/JS 시험(웨지 = 키 입력 + Enter).
- 실기 확인 필요: 대상 단말이 SDK 스캐너만 쓰면 지금도 된다(추정) — 단말 목록·스캐너 방식 확인 뒤 우선순위.

## 부록 A. K-e 브라우저 재현 절차

1. `docker compose up -d --wait` · `./gradlew bootRun`(local). 관리자로 DEMO 작업자 둘에 배지·PIN(`PUT /api/master/workers/{id}/badge`·`/pin`), 감독자 자격(qual + `mst_worker_qual`) + 정책 `POP_APPROVER_QUAL`, POP 단말 등록(`POST /api/production/terminals`) → `/pop/activate` 에서 회사·코드 입력.
2. Playwright 컨텍스트에 `addInitScript(() => { window.Capacitor = {Plugins: {YeonShell: {kiosk: o => { (window.__k ||= []).push(o.on); return Promise.resolve(); }}}}; })` → `/pop` 열기(→ `__k = [true]`).
3. 조작자 배지를 `page.keyboard.type(…) + Enter`(웨지)로 로그인.
4. `page.mouse.move(오른쪽 위 10px) → down → 5.3초 → up` → `dialog.hb-kiosk-dialog[open]`.
5. 감독자 배지를 웨지로 입력 → **기대**: PIN 단계 / **지금**: 대화상자 닫힘, 배지 안 읽힘.
6. (비교) `window.dispatchEvent(new CustomEvent('hb:scan', {detail: {value: 감독자 배지}}))` → PIN 단계 → 키패드 PIN → `__k` 끝이 `false`.
