# 45. 모바일 앱 전환 분석 — 휴대전화에서 YeonOS 를 쓰려면 (2026-10-26)

> 사용자 질문: "통합솔루션을 앱으로 만든다면 — 휴대전화에서 앱으로 열어 작업할 수 있게 한다면?" 상위 세션 분석. **문서만**(코드·마이그레이션 없음).
> 기준: main V194(#567·#568 묶음). 근거는 파일·문서 절로 단다. 코드로 확인하지 않은 판단은 **[추정]**, 외부 사실 중 확인이 필요한 것은 **[확인 필요]**.
> 끝의 검토 절은 사용자 결정을 받아 채운다.

## 0. 결론

- **별도 네이티브 앱이 아니라 지금 웹을 PWA(설치형 웹앱)로 만든다.** 이미 정한 방향과 같다(docs/00 3장 "POP/PDA: 반응형 웹 키오스크 → PWA — 안드로이드 앱 수동 업데이트 문제 해소", docs/02·03 PDA(PWA)).
- 앱 마켓 배포·MDM·블루투스 프린터·NFC 같은 하드웨어 요구가 생길 때만 같은 웹을 감싸는 **래퍼**(Capacitor·TWA)를 덧씌운다. 화면·인증·API 는 그대로다.
- **현장 PDA 는 처음부터 래퍼 APK**(2026-10-26 사용자 결정, 7장): 사무 휴대전화 = PWA, 현장 PDA = 같은 웹을 감싼 APK(스캐너 SDK·MDM·키오스크). 화면을 새로 만드는 네이티브 앱은 아니다.
- 휴대전화 범위는 **현장 작업 + 조회·승인**으로 좁힌다. 그리드 편집·엑셀 중심의 사무 화면을 휴대전화로 옮기지 않는다.

### 2.1 M-1 PWA 셸 — CSP 실측 계획 (2026-10-29, 시스템관리)

> 상위 지시: CSP 가드를 약화시키지 않고, 서비스 워커·manifest 가 지금 CSP 에서 어떻게 동작하는지 **실제 브라우저로 재서** 이 절에 남긴다. 측정 결과가 계획과 다르면 같은 PR 안에서 구현을 바꾼다.

**전제(코드)**: CSP = `SecurityConfig.CONTENT_SECURITY_POLICY` — `default-src 'self'; script-src 'self'; …; connect-src 'self'; img-src 'self' data:` 이고 `worker-src`·`manifest-src` 는 없다. 명세상 `worker-src` 가 없으면 `child-src` → `script-src` 순으로, `manifest-src` 가 없으면 `default-src` 로 떨어진다 — 같은 출처 파일이면 통과할 것으로 **[추정]**.

| # | 잴 것 | 방법(실제 Chromium, Playwright) | 통과 기준 |
|---|---|---|---|
| P1 | 서비스 워커 등록 | 로그인 화면·셸에서 `/sw.js` 등록, `securitypolicyviolation` 이벤트·콘솔 오류 수집 | 등록 성공, 위반 0 |
| P2 | manifest 읽기 | `<link rel="manifest">` → 브라우저가 읽은 manifest(CDP `Page.getAppManifest`) 오류 없음, 응답 Content-Type | 오류 0, `application/manifest+json` |
| P3 | 아이콘 | manifest 아이콘 192·512·maskable 을 브라우저가 받음 | 200, 위반 0 |
| P4 | 워커가 가로챈 요청의 CSP | 워커를 거친 정적 자원(js·css)이 페이지 CSP 를 그대로 받는지 — 인라인 스크립트를 넣은 시험 페이지가 여전히 막히는지 | 인라인 차단 그대로 |
| P5 | 캐시 범위 | 로그인 뒤 셸·화면 몇 개를 연 다음 Cache Storage 목록 | 정적 자원(`/css`·`/js`·`/vendor`·`/images`·manifest)만, `/api/**`·HTML(`/main`·`/page/**`·`/login`)·`/pop/**` 없음 |
| P6 | 로그아웃 | 로그아웃 → 로그인 화면 도착 뒤 Cache Storage | 비어 있음 |
| P7 | 새 배포 반영 | 정적 파일을 바꾼 뒤 다시 열기(온라인) | 새 파일(캐시가 옛 파일을 내지 않음) |
| P8 | 오프라인 | 네트워크 끊고 다시 열기 | HTML 은 캐시하지 않으므로 브라우저 오프라인 화면 — 업무 데이터가 단말에 남지 않는 쪽을 택함 |
| P9 | POP 390px | `/pop` 활성화 화면·작업 화면 390 폭 | 가로 넘침 0(POP 템플릿은 MES 소유라 고치지 않고 관찰만) |

### 2.2 M-1 실측 결과 (2026-10-29, Chromium·Playwright, 로컬 `http://127.0.0.1:8093` — 보안 출처, 일회용 DB)

**CSP 는 그대로다** — `worker-src`·`manifest-src` 를 더하지 않았고 가드 테스트도 손대지 않았다. 측정이 바꾼 구현은 manifest 형식 하나(P2).

| # | 결과 | 비고 |
|---|---|---|
| P1 | 등록 성공 — 범위 `/`, 스크립트 `/sw.js`, CSP 위반 0 | `worker-src` 없음 → `script-src 'self'` 로 떨어져 같은 출처 워커 통과. 워커 안 `importScripts('/js/common/hb.pwa.js')` 도 같은 규칙으로 통과 |
| P2 | **처음 실패 → 고침**: 정적 파일 `manifest.webmanifest` 가 `application/octet-stream` 으로 나갔다(Spring 기본 형식 표에 없음). 확장자 표 보강(`configureContentNegotiation`)은 Boot 정적 처리기에 적용되지 않아, 작은 컨트롤러(`PwaController`)가 `application/manifest+json` 으로 낸다. 이후 브라우저가 읽은 manifest 오류 0·설치 가능성 오류 0(CDP `Page.getInstallabilityErrors`) | `manifest-src` 없음 → `default-src 'self'` 로 통과 |

| P5 | 로그인 → 셸 → 화면 2개 열기 뒤 캐시 35건 모두 `/css`·`/js`·`/vendor`·`/images`·manifest — `/api/**`·HTML·`/pop/**` 0건 | 정적 응답에는 Spring Security 기본 `Cache-Control: no-store` 가 붙지만 워커는 정적 경로만 일부러 저장한다(공개 코드·그림 — 사용자 데이터 없음) |

| P8 | 오프라인: 정적 자원은 캐시에서 200, API 는 네트워크 실패, `/main` 이동은 브라우저 오프라인 화면(`ERR_INTERNET_DISCONNECTED`) | 계획대로 — HTML·업무 데이터는 단말에 남기지 않는다. 오프라인 업무는 현장 대기열(`hb.pop.queue`, A-3)·관리자는 연결됐을 때만 |
| P9 | POP 활성화 화면·작업 화면(배지 대기) 390 폭 가로 넘침 0, JS 오류 0. 셸 390 도 넘침 0·워커 제어 | POP 템플릿은 MES 소유라 manifest·워커를 넣지 않았다 — POP 을 홈 화면 앱으로 쓰려면 MES 가 `<link rel="manifest">`(POP 용 `start_url=/pop`) 를 넣는 후속이 필요(지금은 브라우저·APK 로 충분) |

**정한 것**
- 워커는 로그인 화면·셸(`/main`)에서만 등록한다 — 업무 화면은 셸의 iframe 이라 같은 범위로 잡힌다. 협력사 포털(`/portal`)·운영자(`/ops`)는 이번 범위 밖.
- 캐시 이름 `yeonos-static-v1` — 규칙을 바꾸면 v 를 올리고, 새 워커가 활성화될 때 옛 이름을 지운다.
- "홈 화면에 추가"는 브라우저 기능(안드로이드 Chrome 설치 안내 / iOS Safari 공유 → 홈 화면에 추가)을 쓴다 — 화면에 설치 단추는 두지 않았다(필요하면 M-3 에서).

## 3. 방식 비교

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **반응형 웹 + PWA** | 코드 하나, 즉시 배포(앱 업데이트 문제 없음), 지금 인증·CSP·멱등을 그대로 | 블루투스·NFC 등 하드웨어 접근 제한, iOS 알림 제약 | **1순위** |
| 웹뷰 래퍼(Capacitor·TWA) | 마켓 배포, MDM 배포, 하드웨어 플러그인 | 빌드·서명·심사 관리가 생긴다 | 사무 휴대전화는 필요해질 때 / **현장 PDA 는 1순위**(7장) |
| 네이티브(React Native 등) | 오프라인·하드웨어·체감 속도 최고 | 화면을 다시 만들고 토큰 인증·API 계약 전면 정리 — 1인 개발로는 부담 | 비추천 |

## 7. 현장 PDA = 웹을 감싼 APK (2026-10-26 사용자 결정)

> 사용자 질문: "A사(고객사) PDA 처럼 APK 로 설치하는 앱이 더 좋지 않나?" → APK 로 가되 **화면을 새로 만드는 네이티브가 아니라 같은 웹을 감싼 APK**. A사 PDA 가 네이티브인지 웹뷰인지는 코드로 확인하지 않았다 **[확인 필요]**.

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 형태 | Capacitor 래퍼 APK — 껍데기는 한 번 배포, 화면은 서버에서 받는다 | 화면을 고쳐도 APK 재배포 없음 — docs/00 3장 "안드로이드 앱 수동 업데이트 문제"를 다시 만들지 않는다. 단말마다 버전이 갈려 API 변경이 옛 버전을 깨는 일도 없다 |
| 스캐너 | 산업용 PDA 내장 스캐너는 제조사 SDK(intent)를 APK 플러그인으로 받는다. 화면은 공통 `hb.scan` 하나 — 브라우저 = 키보드 웨지·카메라, APK = 스캐너 SDK | 웨지 입력은 포커스를 잃으면 값이 엉뚱한 칸에 들어간다(조용히 틀림) |
| 배포·잠금 | MDM 배포, 키오스크 모드(다른 앱 막기) | 현장 단말 관리 |
| 인증·API | 지금 그대로(세션 쿠키 + CSRF, 단말 세션·배지 + PIN, 멱등 키) | 토큰 인증 신설 없음 |
| 사무 휴대전화 | PWA 그대로(M-1·M-3) | 업데이트 즉시, 설치 부담 없음 |

**지켜야 할 것**
- 래퍼는 **우리 서버 출처만** 연다(허용 출처 목록 고정, 외부 링크는 시스템 브라우저로). 웹 화면이 플러그인을 부를 수 있으므로 CSP·인라인 금지 규칙을 그대로 둔다.
- 플러그인이 넘기는 값(스캔 문자열)은 키보드 입력과 같게 **서버가 다시 검증**한다 — APK 라고 믿지 않는다.
- APK 서명 키는 저장소 밖에 둔다(커밋 금지). 껍데기 버전과 서버가 요구하는 최소 버전을 맞춰, 낮으면 "업데이트 필요" 화면만 낸다.
- 설치형(폐쇄망)은 서버 주소를 APK 첫 실행 때 입력·고정하고, 사내 인증서를 단말에 배포한다(2장 설치형 줄).

**POP 도 같은 APK(2026-10-26 사용자)**: APK 하나에 POP(설비·공정 태블릿, `/pop`)와 PDA(창고, docs/30 B7)를 함께 담는다 — 단말 등록 때 갈래를 정하고 등록된 단말은 그 화면으로 바로 연다. POP 의 단말 세션·배지 + PIN·감독자 승인·`POP_PATHS` 는 그대로(APK 는 감싸기만). **웹과 APK 둘 다 지원**: POP·PDA 화면은 브라우저(키오스크 PC·태블릿 브라우저)에서도 지금처럼 열리고, APK 는 같은 화면을 감쌀 뿐이다 — APK 전용 기능(스캐너 SDK·키오스크 잠금)이 없으면 브라우저 대체 동작(키보드 웨지·카메라)으로 같은 일을 끝낼 수 있어야 한다. 키오스크 빠져나오기·화면 꺼짐 방지·웹뷰 카메라(C25 `capture=environment`)는 docs/50 에서 정한다.

**개발 범위(2026-10-26 사용자)**: ① 설계 문서 docs/50 → ② APK 다운로드 화면(**로그인한 사용자만** — `sys_prog` 화면 + `@ProgAuth`, 파일은 저장소 밖 설정 경로, 화면에 버전·SHA-256 표시) + 최소 버전 API → ③ Capacitor 껍데기 `mobile/pda`(APK 빌드는 Android SDK 가 있는 로컬·CI). 담당: 시스템관리 세션.

**남은 질문**: 대상 PDA 기종(제조사 SDK 결정), MDM 유무, 사내망 인증서 배포 방식 — M-2 착수 전에 받는다.

## 9. M-3 관리자 모바일 — 결재함·홈 카드 + Web Push (2026-10-29, 시스템관리, V210·임시 V9715)

> 범위(사용자 A-1·A-2·A-3): 관리자는 개인 기기(iPhone 포함)에서 **조회·승인/반려만**. 사무 MFA 는 **현행 규칙 그대로**(새 MFA 없음). 결재는 **연결됐을 때만**.
