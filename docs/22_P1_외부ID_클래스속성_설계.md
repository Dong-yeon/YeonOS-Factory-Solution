## 1. 결론 먼저

- **7a 외부 연계 키** — 업무 테이블에 ERP·고객 전용 컬럼을 넣지 않는다(07 하지 말 것 12). 대신
  - `mst_ext_system`(회사별 외부 시스템: ERP·고객 포털·협력사 — 고객이면 거래처에 연결),
  - `mst_ext_id_map`(시스템 × 대상 유형(품목·거래처) × 내부 id ↔ 외부 코드·외부 이름, **시스템마다 1:1**),
  - `if_code_map`(시스템 × 코드 유형(단위·품목 유형·창고) × 외부 코드 → 내부 코드).
- **ERP 주인 필드 잠금(D8)** — 정책 `ERP_ITEM_SYNC_MODE`(PULL·EXCEL·OFF, 기본 EXCEL). **PULL** 이면 품목의 ERP 주인 필드(코드·이름·규격·유형·조달·단위)는 MES 화면·API·엑셀 올리기에서 바꿀 수 없고(`ERP_OWNED`), 품목 신규도 ERP 동기화로만. MES 주인 필드(LOT 관리·순질량·HS·비고·클래스 속성)는 그대로 편집.
- **7b 클래스 속성** — 품목 클래스 `mst_item_class`(회사별 분류: 코일·볼트류·프레스품 …) + 설비 클래스(4b `mst_equip_class`)에 **속성 정의** `mst_class_prop`(코드·이름·형식·단위·필수·선택지·AAS semantic_id). 값은 **대상 테이블의 `attrs jsonb`**(`mst_item.attrs`, `mst_equip.attrs`) — 키는 정의에 있는 것만, 형식·필수는 DB 트리거가 최종 판정.
- 진행: **7a → 7b**. 화면 = 외부 시스템·코드 매핑 `mst-ext-system`(새), 품목관리 상세에 "외부 품번" 칸·ERP 잠금 표시, 7b 는 클래스 속성 정의 화면과 품목·설비 상세의 속성 칸.

## 2. 7a 규칙

| 규칙 | 내용 | 이유 |
|---|---|---|
| 시스템 | `system_cd`(회사 안 유일) · 이름 · 유형 `EXT_SYSTEM_TYPE`(ERP·CUSTOMER·SUPPLIER·OTHER) · 고객/협력사면 거래처(선택) | 고객 품번은 고객사마다 다르다 — "현대 품번", "기아 품번" 이 각각 시스템 |
| 외부 ID | (시스템, 대상 유형, 외부 코드) 유일 **그리고** (시스템, 대상 유형, 내부 id) 유일 | 한 시스템 안에서 1:1 이어야 송신(내부 → 외부)·수신(외부 → 내부)이 모두 한 값으로 정해진다. 고객이 같은 품목에 품번 둘을 쓰면 시스템을 나눈다 [추정] |
| 대상 유형 | `EXT_ENTITY`: ITEM·CUST (P1). 설비·창고는 연계가 생길 때 코드 추가 | 07 3.1 에서 ERP 와 키를 맞출 대상이 품목·거래처 |
| 대상 검증 | 내부 id 가 그 회사의 그 유형 행인지 — 트리거(다형 참조라 FK 불가) | FK 는 RLS 를 무시하고 다형 참조를 못 건다 |
| 코드 매핑 | `IF_CODE_TYPE`: UOM·ITEM_TYPE·WH. 내부 코드는 그 유형의 쓸 수 있는 코드(단위 = `hb_unit_usable`, 품목 유형 = 시스템 코드, 창고 = 사용 중 WH 노드 코드) | 07 4.2 "EA·개 → EA", B1·이카운트 창고 코드 |
| 삭제 | 없음(사용 중지). 사용 중지 행은 유일 검사에서 빠진다 — 잘못 넣은 매핑을 끄고 다시 넣을 수 있게 | 송신 이력(`if_history`, P6)이 매핑 id 를 남긴다 |

### ERP 주인 필드 (D8)

| 모드 | 품목 신규 | ERP 주인 필드 수정 | MES 주인 필드 | 엑셀 올리기(품목) |
|---|---|---|---|---|
| `EXCEL`(기본) | 가능 | 가능 | 가능 | 가능 |
| `OFF` (연동 없음) | 가능 | 가능 | 가능 | 가능 |
| `PULL` (ERP 가 주인) | **거부** `ERP_OWNED` | **거부**(칸 오류 `ERP_OWNED`) | 가능 | 새 행·주인 필드 변경 행 오류 |

- ERP 주인 필드 = `itemCd`·`itemNm`·`spec`·`itemType`·`procType`·`unitCd` (07 3.1 품목 행 + 단위). 사용 여부는 MES 도 끌 수 있다(현장 사용 중지) [추정].
- PULL 의 실제 동기화(어댑터)는 P6 — 그때 어댑터는 같은 서비스의 "동기화 경로"로 쓴다. 7a 는 **잠금 규칙과 화면 표시**까지.

## 5b. 7b 상세 — 클래스 속성

| 규칙 | 내용 | 이유 |
|---|---|---|
| 품목 클래스 | `mst_item_class`(회사별 코드·이름 — 코일·볼트류·프레스품 …), 품목은 클래스 하나(선택) | docs/17 1단계 "회사별 분류는 7단계 클래스". 품목 유형(FG·RM)은 시스템 코드라 회사 분류를 못 싣는다 |
| 설비 클래스 | 4b `mst_equip_class` 그대로 | |
| 속성 정의 | `mst_class_prop`: (클래스 유형 ITEM·EQUIP, 클래스, 속성 코드) 유일, 이름·형식 `PROP_DATA_TYPE`(TEXT·NUM·DATE·BOOL·LIST)·단위·자릿수(NUM)·선택지(LIST)·필수·순서·AAS `semantic_id`(선택) | docs/02 6.3 수정 채택 |
| 값 | 대상 테이블 `attrs jsonb`(객체) — 키 = 속성 코드, 값 = 형식에 맞는 JSON(TEXT·DATE·LIST 는 문자열, NUM 은 숫자, BOOL 은 true/false) | EAV 대신 jsonb(조회·정렬·엑셀·GIN) |
| 검증 | DB 트리거 `hb_check_attrs` 가 최종: 키는 그 클래스에 정의된 것만, 사용 중 필수 속성은 값 있음, 형식·자릿수·선택지·길이(TEXT 500). 서비스는 같은 규칙으로 칸 오류(`attrs.{속성 코드}`) | 직접 SQL 까지 |
| 형식 고정 | 속성의 형식은 만든 뒤 바꾸지 않는다(이미 저장된 값의 뜻이 바뀜) — 새 속성 코드로 | |
| 사용 중지 | 속성 사용 중지 = 새 입력 대상에서 빠짐, 저장된 값은 남고 필수 검사에서 빠진다. 클래스를 바꾸면 값이 새 클래스 정의에 맞아야 한다(맞지 않는 키는 화면이 지우고 저장) | 조용히 버리지 않음 — 화면에서 사용자가 보는 상태로 지운다 |
| 정의 변경 뒤 기존 값 | 선택지 삭제·자릿수 축소·길이 등 정의를 바꿔도 **바뀌지 않은 값은 둔다** — 클래스가 같고 이전 값과 같은 키는 형식·정의 검사를 건너뛴다(트리거 `hb_check_attrs` 의 `p_old`, 서비스 같은 규칙). 값을 바꾸거나 클래스를 바꾸면 새 정의로 검사 | "새 참조만 막는다"(6단계 QA 결함1)와 같은 원칙. 2026-10-20 QA 결함4 사용자 결정(V031) |
| 설비 클래스 바꾸기 | 설비 속성 저장 API 가 `classId` 를 함께 받아 클래스와 새 클래스 값을 한 번에 저장(품목과 같게). 화면은 클래스를 바꾸면 새 클래스 칸을 그리고 같은 코드 값은 옮긴다 | 필수 속성 값이 있는 설비가 그 속성 없는 클래스로 못 가던 교착(QA 결함3) |
| NUM 값 | 서비스는 BigDecimal 로 읽고 조회 응답은 글자(`toPlainString`) — Double 을 거치지 않는다 | 반올림 저장·지수 표기 비교 실패(QA 결함1·2) |
| 필수 검사 시점 | 품목은 클래스·값을 한 번에 저장(속성 저장) — 그때 필수까지. **설비는 폼에서 먼저 만들고 속성을 나중에 넣으므로 속성 값을 저장할 때만 필수**, 설비 생성·클래스 변경은 키·형식만 | 구현 중 발견(2026-10-20): 필수 속성이 있는 클래스로 설비를 만들 수 없었다 |
| 필수 속성을 나중에 추가 | 기존 품목은 다음 저장 때 채워야 한다(트리거는 attrs·클래스가 바뀔 때만 검사) | 일괄 채움은 엑셀(후속) |
| 엑셀 올리기 | 품목 올리기는 클래스·속성을 다루지 않고 **건드리지도 않는다**(UPDATE 에서 attrs·클래스 칸 제외) | 열 구성이 클래스마다 달라 템플릿이 달라진다 — 후속 |

화면: **클래스 속성** `mst-class-prop`(왼쪽 클래스 유형 선택 + 클래스 목록 — 품목 클래스는 여기서 추가, 설비 클래스는 4b 화면 / 오른쪽 속성 정의 표·폼), 품목관리·설비 관리 상세에 클래스 선택 + 속성 칸(정의에 따라 그려짐).

데이터 모델 (V027): `mst_item_class`, `mst_item.item_class_id`·`attrs`, `mst_equip.attrs`, `mst_class_prop`, 함수 `hb_check_attrs`, 트리거(품목·설비 attrs·클래스 변경 시, 속성 형식 고정·대상 클래스 같은 회사).
