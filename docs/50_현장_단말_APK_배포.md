# 50. 현장 단말 APK 배포 설계 — POP·PDA 를 한 APK 로, 웹을 감싼 Capacitor 껍데기 (2026-10-26)

> 근거: docs/45 7장(사용자 결정 2026-10-26 — 현장 PDA = 같은 웹을 감싼 APK, 사무 휴대전화 = PWA), docs/29 7.9 시스템관리 줄, 상위 전달(사용자 결정 2026-10-26 — **POP 도 같은 APK**). 담당: 시스템관리 세션.
> 이름: 화면·파일 식별자(`sys-pda-app`, `yeonos-pda.apk`, `mobile/pda`)는 처음 정한 대로 두고, 이 APK 는 **POP 태블릿과 창고 PDA 공용**이다(6장).
> 범위: ① 이 문서 → ② APK 다운로드 화면 + 최소 버전 API → ③ 껍데기 `mobile/pda`. **②③ 은 이 문서의 검토(10장) 뒤에** 한다.
> 표시: **[결정]** 상위·사용자가 정한 것, **[제안]** 이 문서의 제안(검토 대상), **[질문]** 사용자 답이 필요한 것.

## 0. 결론

- APK 는 **껍데기**다. 화면·인증·API 는 서버의 지금 웹 그대로 — 껍데기는 한 번 깔고, 화면을 고쳐도 다시 깔지 않는다 **[결정]**.
- 껍데기가 하는 일은 여섯뿐: ① 서버 주소 고정 ② 최소 버전 확인 ③ 우리 서버만 여는 웹뷰(시작 = `/pop`) ④ 스캐너 SDK 를 화면 스캔 입력으로 넘기기 ⑤ 키오스크(화면 고정)·화면 꺼짐 방지 ⑥ 카메라 파일 선택기 **[제안]**.
- **POP·PDA 는 한 APK, 그리고 브라우저도 그대로** **[결정]**. 키오스크 PC·태블릿 크롬에서 `/pop` 이 지금처럼 열리고, APK 는 같은 화면을 감싸기만 한다. 어느 화면이 열리는지는 APK 가 아니라 **서버의 단말 등록**(`sys_terminal.terminal_type`)이 정한다 — 등록 안 된 단말은 `/pop/activate`, POP 단말은 작업장 홈 `/pop`, PDA 단말은 창고 홈 `/pop/wh`(지금 서버 리다이렉트 그대로, docs/25 4.33). 서버는 브라우저·APK 를 **구분하지 않는다**(6장).
- APK 전용 기능(스캐너 SDK·키오스크 잠금·화면 꺼짐 방지)이 없어도 화면은 **브라우저 대체 동작으로 같은 일을 끝낸다** — 스캔은 키보드 웨지·카메라 입력, 고르는 것은 공통 함수(`hb.scan`)가 환경을 보고 한다 **[결정]**(6.1·7장).
- APK 파일은 **저장소·DB 밖** 설정 경로에 운영자가 놓는다. 서버는 그 파일의 크기·SHA-256 을 **스스로 계산**해 다운로드 화면에 보인다(메타 파일의 해시를 믿지 않는다) **[제안]**.
- 다운로드 화면은 **로그인한 사용자만**(`sys_prog` 화면 + `@ProgAuth`) **[결정]**. 최소 버전 확인은 껍데기가 로그인 전에 불러야 하므로 **공개 JSON 한 개**(`/status.json` 과 같은 모양)로 둔다 **[제안 — 9장 Q2]**.
- 스캐너는 화면 공통 `hb.scan` 하나. 이번에는 **계약(`types/hb.d.ts`) + 키보드 웨지 구현**까지, 제조사 SDK 플러그인은 기종이 정해진 뒤 **[결정]**. 단말 화면(POP·PDA)은 지금의 `hb.pop.scanner` 를 그대로 쓰고, 네이티브 스캔은 그 안으로 같은 경로로 넣는다(7장 C6).

## 1. 구성

```
[PDA] Capacitor 껍데기(APK, mobile/pda)
   ├─ 첫 실행: 서버 주소 입력·고정(설치형) / 빌드 때 고정(SaaS)
   ├─ 기동: GET {서버}/pda/version.json → 내 버전 < minVersion 이면 내장 "업데이트 필요" 화면만
   ├─ 웹뷰: {서버}/pop … 지금 단말 웹 그대로(단말 쿠키 HB_TERMINAL + 쿠키 CSRF, 배지 + PIN)
   │     등록 안 됨 → /pop/activate · POP → /pop(작업장 홈) · PDA → /pop/wh(창고 홈)  ← 서버가 정한다
   ├─ 키오스크: 화면 고정(lock task) + 화면 꺼짐 방지 — 빠져나오기 = 감독자 배지 + PIN(서버 확인)
   ├─ 카메라: <input type=file capture> 를 Android 카메라 앱으로(POP 고장 신고 사진, docs/25 4.44)
   └─ 플러그인: 스캐너 SDK → window 이벤트 → hb.scan (기종 확정 뒤)
[서버] 지금 앱
   ├─ /pda/version.json (공개, 허용 칸만)                 ← 최소 버전 확인
   ├─ /page/sys-pda-app (로그인, @ProgAuth SEARCH)          ← 다운로드 화면: 버전·크기·SHA-256·설치 안내
   └─ /api/platform/pda-app/download (로그인, @ProgAuth)  ← 파일 스트림 + 접속 로그 FILE_DOWNLOAD
[운영자] 서버 디스크 happyboot.pda.dir
   ├─ yeonos-pda.apk
   └─ release.json  {"version":"1.2.0","minVersion":"1.1.0","releasedAt":"2026-11-01","notesKo":"…","notesEn":"…"}
```

## 3. 최소 버전 확인

| # | 정한 것 | 다른 안 |
|---|---|---|
| V1 | `GET /pda/version.json` — **로그인 없이**(껍데기가 로그인 화면을 열기 전에 부른다). 내보내는 칸은 `version`·`minVersion`·`releasedAt` 셋뿐(파일 경로·해시·노트 없음). `/status.json` 과 같은 규칙: 허용 값·길이만 다시 만들어 보낸다 **[질문 Q2 — 공개 여부]** | 로그인 뒤 확인 — 옛 껍데기가 로그인 화면까지 들어가서야 막힌다. 그 사이 옛 껍데기의 플러그인 계약이 새 화면과 어긋날 수 있다 |

## 6. POP·PDA 한 APK (상위 전달 2026-10-26)

**한 줄**: APK 는 단말 웹(`/pop/**`)을 여는 그릇이다. 단말 활성화(`/pop/activate`, 회사 코드 + 등록 코드 → 쿠키 `HB_TERMINAL`), 작업자 배지 + PIN, 감독자 승인(docs/25 4.37), 유형별 경로(`POP_PATHS`·`PDA_PATHS`, `ROLE_TERMINAL_{유형}`)는 **서버에 지금 있는 그대로** 쓴다. APK 가 유형을 정하거나 체인을 건너뛰는 길은 만들지 않는다.

### 6.1 두 환경 — 기능별 APK 구현과 브라우저 대체

| 기능 | APK(다리 `YeonShell` 있음) | 브라우저(키오스크 PC·태블릿 크롬) | 고르는 곳 |
|---|---|---|---|
| 화면·인증 | `{서버}/pop` 웹뷰 | 같은 주소를 크롬으로 | 없음(같은 서버 화면) |
| 스캔 | 제조사 SDK → `hb:scan` 이벤트(기종 확정 뒤) — 그 전에는 웨지 | 키보드 웨지(USB·블루투스 스캐너) + [카메라로 읽기] 단추(C5) | `hb.scan` |
| 사진(C25) | 파일 선택기 → 카메라 앱(K8) | `<input capture>` 그대로(태블릿 = 카메라, PC = 파일) | 없음(같은 태그) |
| 키오스크 잠금 | lock task(K3) + 감독자 빠져나오기(K4) | 기기 쪽 잠금(설치 안내) — 화면은 같은 동작 | 화면이 `YeonShell` 있을 때만 부름 |
| 화면 꺼짐 방지 | `FLAG_KEEP_SCREEN_ON`(K7) | Wake Lock API, 없으면 OS 설정 | `hb.pop`(작은 함수 `hb.pop.keepAwake()`) |
| 앱 버전 확인 | 기동 때 `/pda/version.json`(V1·V2) | 해당 없음(늘 최신 화면) | 껍데기 |

- 원칙: 화면 JS 는 `window.YeonShell` 을 **직접 부르지 않는다** — `hb.scan`·`hb.pop.keepAwake`·`hb.kiosk`(7.2) 가 있는지 보고 고른다(다리 없으면 대체·무동작). 화면이 APK 전용 분기를 갖지 않게.
- 대체 동작이 "같은 일을 끝낸다" 는 기준: 배지 로그인·할 일·착수·실적·투입 스캔·고장 신고·사진, 창고 이동·실사가 **APK 기능 없이** 브라우저에서 끝까지 된다.

**KS9 서버 계약(MES 2차 세션 몫 — 화면은 위대로 이미 부른다)**: ① `/api/pop/kiosk/exit` 응답에 `exitRef`(문자열, 그 빠져나오기 기록을 가리키는 값 — 접속 로그 id 나 임의 값, 추측 불가하게) 추가 ② `POST /api/pop/kiosk/unlock-failed` `{exitRef, reason}` — POP 체인(단말 쿠키), `reason` ∈ {`stale`, `refused`}(그 밖 400), 같은 단말이 받은 `exitRef` 만(다른 단말·다른 회사 = 404), 같은 `exitRef` 두 번째는 200 아무것도 안 함(멱등), 기록 = 접속 로그 새 이벤트(예 `POP_KIOSK_UNLOCK_FAIL`, FAIL, 사유 글) — `AccessEvent`·`ACCESS_EVENT` 공통코드·문구 같이. 응답 본문은 화면이 쓰지 않는다.
**구현(2026-11-04, MES 2차 — docs/25 4.54, V235(임시 V9101))**: `exitRef` = 128비트 임의 값(base64url 22자), 빠져나오기 기록 detail 끝 `ref=…` 로 가리킨다. 같은 단말 = 그 단말 행위자의 최근 1시간 `POP_KIOSK_EXIT` OK 행, 멱등 = `sys_inbox`, 기록 `POP_KIOSK_UNLOCK_FAIL`(FAIL·WARN, `worker=… ref=… reason=…`). 화면 `hb.kiosk` 는 그대로(계약 모양 같음).

**keepAwake 구현(K7 브라우저 대체, 2026-11-03)**: `hb.pop.keepAwake(opts?)` → `{state(), release()}` — 다리 있음 = `native`(껍데기 `FLAG_KEEP_SCREEN_ON`, 아무것도 안 함), Wake Lock 없음 = `unsupported`, 잡음 = `active`, 가려져 OS 가 풂 = `released` → 다시 보이면(`visibilitychange`) 다시 잡음, 거절 = `failed`(다음에 보일 때 다시). `opts.onChange(state)`. POP 작업장 홈이 초기화 때 한 번 부른다. 실패를 화면에 보일지(docs/27 U12 "실패 시 표시")는 **미정 — 사용자 질문**(표시 자리·문구가 정의되지 않음).

MES 에 넘길 붙임(상위 경유): `pop/home.html` 에 `hb.pop.js` 뒤 `<script th:src="@{/js/common/hb.kiosk.js}">` / `home.js` 초기화에 `var kiosk = hb.kiosk ? hb.kiosk.attach() : null;` / `render` 에서 `kiosk.worker(s.workerCd)` / 스캐너 처리 맨 앞에 `if (kiosk.isOpen()) { kiosk.badge(v); return; }`.

## 8. 보안 요약

- 서버: 다운로드 = 로그인 + 화면 권한, 고정 파일 이름(경로 파라미터 없음), 실제 경로가 설정 디렉터리 안인지 확인, 스트리밍, 접속 로그. 공개는 버전 JSON 의 세 칸뿐.
- 껍데기: 출처 하나·https 만·외부 링크는 시스템 브라우저·플러그인 최소. 서명 키 커밋 금지.
- 껍데기(POP·PDA 공용): 단말 인증·유형·배지·감독자 확인은 서버 체인 그대로, 다리는 `kiosk`·`appInfo` 둘, 키오스크 빠져나오기는 서버가 확인한 감독자만(4.37 카운터 공유), 카메라는 OS 카메라 앱 + 앱 캐시 FileProvider.
- 신뢰 경계: 껍데기가 보내는 값(스캔·UA 의 버전·다리 호출)은 모두 **입력**이다 — 서버 검증·권한 판단에 쓰지 않는다. 단말 유형은 서버 등록 값만 믿는다.
