## 1. 결론 먼저

- 홈은 **카드를 모아 그리기만** 한다. 카드는 각 모듈이 **자기 패키지에 `HomeCardProvider` 빈**으로 둔다(결재 카드처럼 플랫폼 기능의 카드는 홈 패키지). 홈 모듈은 어떤 업무 표도 직접 읽지 않는다.
- 카드 = **제목 · 숫자(행동이 필요한 건수) · 상태(톤) · 링크(화면)** + 보조 숫자 최대 3개 + 맨 앞 항목 최대 5줄. 숫자는 "현황" 이 아니라 **"지금 손댈 것"** 이다(docs/11 3.3 "숫자 대시보드보다 할 일 목록이 행동을 만든다").
- 보이는 카드 = 카드가 가리키는 **화면의 조회(SEARCH) 권한**이 있는 것만. 링크 없는 **개인 카드**(결재 대기)는 권한 대신 "로그인 사용자 본인 것만" 을 제공자가 보장한다.
- 카드 하나가 느리거나 실패해도 홈은 뜬다: **카드마다 따로 읽기 전용 트랜잭션 + `statement_timeout`**, 실패 카드는 "불러오지 못함" 으로만 그린다.
- 1단계 = 규약 + 홈 화면 `home-main` + 카드 4장(오늘 작업지시·진행 공정 / 보류 LOT / 납기 임박 수주 / 결재 대기). **새 업무 표 없음** — 마이그레이션은 `sys_prog` 1행(V049)뿐.
- 사용자별 카드 숨김·순서, 역할별 기본 카드 세트, 카드 → 화면 조건 전달(딥 링크)은 2단계 이후(3장).

## 4. 카드 규약

### 4.1 제공자 인터페이스 (`io.smarthappy.module.home.HomeCardProvider`)

```java
public interface HomeCardProvider {
    String code();          // 카드 코드 ^[a-z][a-z0-9-]{1,39}$, 전체에서 유일 — 모듈 접두(prd-, sal-, qms- …)
    String titleKey();      // 제목 문구 키 (ko/en)
    String progCd();        // 링크·권한 화면. 그 화면 SEARCH 가 있어야 보인다. null = 개인 카드(아래 규칙)
    int sortNo();           // 홈 기본 순서 — 모듈 sort_no 대역을 그대로(MES 400~, SAL 300~, 개인 카드 10~)
    HomeCard load(HomeCardContext ctx);   // 읽기 전용 트랜잭션 안에서 불린다
}
```

- `HomeCardContext` = 오늘(`BizClock.today()`, 회사 시간대) · 로그인 사용자 id · 문구 해석(`msg(key, args…)`, 로그인 언어). 제공자는 `LocalDate.now()` 를 쓰지 않는다(가드).
- `HomeCard` = `count`(행동 필요 건수, long) · `tone` · `facts`(보조 숫자 ≤ 3: 이름·값·톤) · `items`(맨 앞 ≤ 5줄: 제목·설명·톤). 홈 서비스가 개수 상한을 넘는 항목은 자른다(제공자 실수로 응답이 커지지 않게).
- 톤 = `NEUTRAL`(할 일 없음·정상) / `INFO`(볼 것 있음) / `WARN`(확인 필요) / `ALERT`(지연·위반). **초록(success) 없음**(12 2.1).

### 4.2 규칙

| # | 규칙 | 이유 |
|---|---|---|
| R1 | 카드는 `progCd` 화면의 **SEARCH 권한**이 있을 때만 응답에 들어간다. 판정은 `PermissionService.actions(progCd)`(요청 내 캐시) | 메뉴·화면 권한과 같은 기준 — 권한 없는 숫자로 존재(건수)를 흘리지 않는다 |
| R2 | 개인 카드(`progCd = null`)는 **로그인 사용자 본인 것만** 센다(결재 = 내 차례인 결재선). 회사 전체 건수를 개인 카드로 만들지 않는다 | 화면 권한 없이 보이므로 범위가 곧 권한 |
| R3 | 카드마다 **별도 읽기 전용 트랜잭션** + `statement_timeout` 2초(트랜잭션 로컬) | 한 카드의 SQL 오류가 PG 트랜잭션을 깨뜨려 다음 카드까지 실패하는 것을 막는다 / 느린 카드 하나가 홈 전체를 붙잡지 않게 |
| R4 | 실패·시간 초과 카드는 `error=true` + 숫자 없음으로 내려 주고 서버 로그(WARN, 카드 코드)만 — 오류 원문은 응답에 넣지 않는다 | 01 오류 규약(SQL 비노출) |
| R5 | 회사 범위는 요청의 `TenantContext` 그대로(트랜잭션 시작 때 `app.comp_cd`). 제공자는 `comp_cd` 조건을 쓰지 않아도 RLS 가 거르지만, 인덱스 첫 열 때문에 **조건에 `comp_cd = hb_current_comp()` 를 넣지 않는다** — RLS 정책이 같은 식을 붙인다 | 기존 매퍼 관례 |
| R6 | 카드 코드 형식·중복은 **기동 시 검사**(위반이면 기동 실패) | 두 모듈 세션이 같은 코드를 쓰면 화면에서 한 카드가 사라진다 |
| R7 | 항목 글자(LOT 번호·보류 사유·거래처명)는 화면이 **textContent 로만** 넣는다 | 저장형 XSS(I) |
| R8 | 숫자는 "지금 손댈 것" — 끝난·취소된 것은 세지 않는다. 기준(예: 납기 7일)은 카드 설명 문구에 적는다 | 11 3.3 |
| R9 | 카드 응답에 **사람 이름·사번별 집계를 넣지 않는다**(결재 요청자 이름처럼 업무 문서에 붙은 이름은 허용) | 11 3.4 감시 경계 |
| R10 | 링크는 화면 하나(`progCd`). 화면 안 조건 전달(딥 링크)은 2단계 — 그 전에는 카드 설명에 "어느 조건으로 보면 되는지" 를 적는다 | 셸 `open` 은 지금 화면 코드·제목만 받는다(공통 변경을 1단계에 넣지 않음) |

## 5. 홈 화면 `home-main`

- `sys_prog`: `home-main` / `prog.homeMain` / `home/home-main` / SYS / `{SEARCH}` / 950. 전역 행이라 Flyway(V049)로만.
- 역할별 홈으로 쓰려면 권한그룹 `home_prog_cd = 'home-main'`(회사 데이터 — 관리 화면 또는 시더). 로컬 시더는 ADMIN 그룹이 비어 있을 때만 `home-main` 으로 채운다(사용자가 바꾼 값은 둔다).
- 배치: 머리(제목·기준 시각·새로 고침) + **카드 격자**(`grid-template-columns: repeat(auto-fill, minmax(260px, 1fr))` — 작업 영역 폭 기준, 390 에서 1열).
- 카드: 제목 / 큰 숫자 + 상태 글자(기호 + "확인 필요"·"지연"·"할 일 없음") / 보조 숫자 줄 / 항목 목록 / 아래 "화면 열기" 버튼(링크 있는 카드만, `window.top.hbShell.open(progCd, progTitle)` — 셸 밖 단독으로 열었으면 `/page/{progCd}` 로 이동).
- 새로 고침: 버튼 + **5분 자동(문서가 보일 때만, `visibilitychange`)**. 응답 순서 꼬임은 `hb.latest('home', …)` 로 막는다(C). 버튼은 `hb.busy`(연타).
- 빈 상태: 보이는 카드 0장 → "볼 수 있는 카드가 없습니다(화면 권한을 받으면 그 화면의 카드가 나타납니다)".
- 오류 카드: 숫자 대신 "불러오지 못했습니다 — 잠시 뒤 새로 고침" (톤 neutral + 기호 ✕).
- 입력 칸이 없는 화면이라 `hb.dirty`·검색 패널을 쓰지 않는다.

## 6. 1단계 카드 4장

오늘 = 회사 시간대 날짜(`BizClock.today()`). 공장별 시간대(docs/25 D5)는 2단계에서 공장 선택과 함께.

| 코드 | 위치(패키지) | 링크 | 숫자 | 보조 숫자 | 톤 | 항목(≤5) |
|---|---|---|---|---|---|---|
| `prd-wo-today` | `module.production` | `prd-wo` | 오늘 할 지시 = 상태 RELEASED·IN_PROGRESS 이고 `plan_start ≤ 오늘` | 진행 중 공정(RUN) / 일시정지 공정(PAUSE, WARN) / 계획 종료일 지난 지시(WARN) | 일시정지·지난 지시가 있으면 WARN, 아니면 NEUTRAL | 우선순위·시작일 순: 지시 번호 — 품목 · 계획 수량 · 상태 |
| `prd-lot-hold` | `module.production` | `prd-lot` | 보류 LOT 중 **잔량이 남은 것**(`hold_yn='Y'` + `hb_lot_balance > 0`) | — | 1건+ WARN | 오래된 순: LOT 번호 — 품목 · 잔량 · 보류 사유 |
| `sal-due-soon` | `module.sales` | `sal-order` | 열린 수주 행 중 납기 ≤ 오늘 + 7일 | 납기 지남(ALERT) / 오늘(WARN) / 7일 안 | 지남 있으면 ALERT, 아니면 1건+ WARN | 납기 순: 수주 번호-행 — 거래처 · 품목 · 수량 · 납기 |
| `apr-todo` | `module.home`(결재는 플랫폼 기능 — 플랫폼이 모듈에 의존하지 않게) | 없음(결재함 화면은 아직 없음 — 결정 H3) | 내 차례 결재 | 3일 넘게 기다린 것(WARN) | 1건+ WARN | 요청 순: 제목 — 요청자 · 요청일 |

- 쿼리는 각 제공자 매퍼 XML(`#{}` 만). 수량은 `trim_scale(…)::text`(기존 관례), 날짜는 글자.
- 인덱스: `sal_order_line` 은 기존 부분 인덱스 `ix_sal_order_line_due (comp_cd, due_date) WHERE status='OPEN'` 를 탄다. `prd_wo` 는 기존 `ix_prd_wo_plan (comp_cd, plan_start, wo_id)` 범위 스캔 + 상태 필터 — 지시가 많아지면(끝난 지시 수만 건) **부분 인덱스 `WHERE status IN ('RELEASED','IN_PROGRESS')` 가 낫다**. `lot_master` 보류는 순차 스캔(보류 LOT 은 적고 표도 작다). 남의 표 인덱스라 1단계에서 만들지 않고 결정 H5 로 MES 세션에 넘긴다(실행계획은 9장).

### 14.1 카드 설정 `sys_home_user_card`

| 칸 | 뜻 |
|---|---|
| `pref_id` | 대리 키(감사 트리거 `hb_audit('pref_id')` 용) |
| `comp_cd`·`user_id`·`card_cd` | 회사별(RLS + FORCE + `tenant_isolation`), 같은 회사 사용자 트리거(`hb_check_user_comp` 재사용), 유일 `(comp_cd, user_id, card_cd)` |
| `sort_no` 1~999 · `hidden_yn` | 표시 순서 · 숨김 |

- 카드 코드는 **코드(빈)에만** 있으므로 FK 없음. 없어진 카드 행은 읽을 때 무시, 다음 저장 때 사라진다.
- 순서 규칙: 설정 행이 있는 카드 먼저(그 순서) → 행 없는 카드(새 카드·처음 쓰는 사용자)는 뒤에 기본 순서. **새 카드는 숨겨진 채로 오지 않는다**(모듈 세션이 카드를 붙이면 바로 보인다).
- 권한이 우선: 설정이 있어도 화면 권한이 없으면 카드도 설정 목록도 없다(R1). 권한을 다시 받으면 옛 행이 있으면 그 자리, 없으면 끝.
- 저장 = **한 벌 저장**(지우고 다시 넣기, 한 트랜잭션). 본인 설정이라 `row_ver` 없이 나중 저장이 이긴다(두 탭). 지금 볼 수 없는 카드의 옛 행도 같이 지운다.
- 보존 클래스 `USER_SETTING`(그리드 설정과 같음), 감사 트리거 있음(예외 목록 공유 파일을 건드리지 않으려고 — 행이 작고 드물다).

| API | 권한 | 비고 |
|---|---|---|
| `GET /api/home/settings` | `@ProgAuth(home-main, SEARCH)` | 볼 수 있는 카드만, 사용자 순서, 숨김 여부 |
| `PUT /api/home/settings` | 같음 | 본문 `[{code, hidden}]` 순서 = 표시 순서. 빈 목록 `REQUIRED`, 볼 수 없는·없는 카드 `NO_SUCH_CODE`, 중복 `DUPLICATE` — 행 키 = 카드 코드(없으면 순번) |
| `POST /api/home/settings/reset` | 같음 | 내 행 전부 지움 = 기본 |
| `GET /api/home/cards` | (1단계) | 숨긴 카드는 계산도 하지 않는다 + `hiddenCount` |

홈 화면의 액션은 SEARCH 하나 — 개인 설정 저장을 별도 액션(SAVE)으로 나누면 "홈은 보는데 내 카드 순서는 못 바꾸는" 권한 조합만 생겨 쓸모가 없다.

### 14.2 항목 링크 조건(딥 링크)

- 카드 항목 `Item.link` = **그 카드 화면의 조회 패널 칸 이름 → 값**(예 `{keyword: LOT 번호, from: 등록일, to: 등록일}`). 화면별 코드를 고치지 않고 **조회 패널(`hb.searchPanel`) 공통 동작**으로 붙인다:
  - 새 탭: 셸이 `/page/{prog}?q.keyword=…&q.from=…` 로 연다 → 패널이 `ready` 전에 주소 조건을 채운다 → 화면의 첫 조회가 그 조건으로.
  - 이미 열린 탭: 셸이 `hb.applyLinkQuery(params)` → 패널에 채우고 조회. **입력 중이면 셸이 먼저 묻는다.**
    - (2026-11-02 홈 감사 ③ 고침) 채우기 전에 **조회 칸을 기본값으로 되돌린다** — 링크에 없는 칸(검색어 등)에 이전 값이 남아 목록 건수가 카드 숫자보다 적게 보이던 것. 카드들이 빈 값까지 명시하던 우회는 그대로 둬도 된다.
    - (2026-11-02 후속) "기본값" = 패널을 만들 때 칸에 있던 값. 화면 JS 가 패널 생성 **전에** 채운 기간(CMS 알람·상태 검토·KPI·위험 관리의 최근 7일 등)도 기본값으로 기록해 되돌림·[초기화]가 빈 칸이 아니라 그 값으로 돌아간다. 패널 생성 **뒤**에 정하는 기본값은 `sp.setDefault(name, value)` 로(QMS COPQ `copq.js` 의 월 칸 — 해당 모듈 몫). 첫 화면의 `?q.` 링크 값은 기본값에 섞지 않는다.
    - (2026-11-02 후속 2, MES #780 제안) 기간 컴포넌트도 `sp.setDefault(시작·종료 칸 이름, {from, to})`(또는 날짜 하나 = 그쪽만)로 **프리셋이 아닌 기본 기간**을 기억한다 — 되돌림·[초기화]가 `data-default` 프리셋 대신 그 날짜로. 부르지 않은 기간은 지금처럼 프리셋.
    - 화면 훅 `SearchPanelOptions.onLink(query)`: 되돌림·채움 **뒤** 조건 전체(조회 칸 밖의 키 포함 — QMS SPC `view`, PMS `chgReq`)를 받는다. `true` 를 돌려주면 화면이 처리한 것(예: 그 문서 열기)이라 조회하지 않는다. 처음 여는 화면(주소 `?q.`)에서는 부르지 않는다(지금처럼 `ready` 뒤 화면이 읽는다). 각 화면 적용은 해당 모듈 몫.
  - 패널에 없는 칸 이름은 무시(기존 `setValue` 동작). 이름 형식 `^[a-zA-Z][a-zA-Z0-9]{0,29}$`·6개·값 200자를 넘으면 **통째로 버린다**(서버 `HomeService.safeLink` 와 화면 `cleanLink` 둘 다 — 주소는 누구나 만들 수 있으므로 화면 쪽 검사가 실제 방어).
- 1단계 카드의 링크: 지시 = 지시 번호 + 계획 시작일 하루, 보류 LOT = LOT 번호 + 등록일 하루, 납기 = 수주 번호 + 수주일 하루 — 각 화면 목록의 기간 기준(계획 시작·등록일·수주일)에 맞춰 **하루로 좁혀** 기본 기간(지난 30일) 밖 문서도 찾게 했다.
- 보안: 링크는 **조회 조건만** 채운다(저장·상태 변경 없음). 값은 칸 `value` 로만 들어가 HTML 로 해석되지 않는다. 다른 사람이 만든 주소를 열어도 그 사람이 볼 수 있는 결과가 아니라 **여는 사람 권한**으로 조회된다.

### 15.1 겹쳐 쓰기 — 사용자 > 그룹 > 코드

| 층 | 원천 | 쓰는 때 |
|---|---|---|
| 1 사용자 | `sys_home_user_card`(2단계) | 사용자가 "카드 설정" 을 저장했으면 |
| 2 역할별 기본 | `sys_home_grp_card`(이번) — 사용자가 속한 **사용 중 그룹 중 세트가 있는 첫 그룹**(그룹 `sort_no`, 코드 순 — 역할별 홈 `findHomeProg` 와 같은 기준) | 1 에 행이 없는 카드 |
| 3 코드 기본 | 제공자 `sortNo()` | 1·2 어디에도 행이 없는 카드(새 카드) — 보이기, 맨 뒤 |

- 순서 = 1 행 있는 카드(그 순서) → 2 행만 있는 카드(그 순서) → 나머지(코드 순서). 숨김 = 1 행이 있으면 그것, 없으면 2 행, 없으면 보이기.
- **세트는 권한을 주지 않는다.** 카드가 보이는지는 여전히 링크 화면 조회 권한(R1). 세트에 넣어 둔 카드는 그룹이 권한을 받으면 그 자리에 나타난다.
- 개인 설정 "기본값으로"(2단계 reset) = 내 행을 지움 → 역할별 기본으로 돌아간다(문구도 그렇게 고침).
- 여러 그룹 합치기(그룹별 세트를 섞기)는 하지 않는다 — 한 사용자에게 두 세트의 순서를 섞는 규칙은 설명하기 어렵다. 홈 화면(`home_prog_cd`)과 같은 "첫 그룹" 규칙.

### 15.2 표 `sys_home_grp_card`

|---|---|

### 15.3 관리 화면 `home-card-mgt` · API

- `sys_prog`: `home-card-mgt` / `prog.homeCardMgt` / `home/home-card-mgt` / SYS / `{SEARCH, SAVE}` / 951. 메뉴는 시스템 폴더(`DevCompanySeed.HOME_MENUS`, 940).
- 배치: 왼쪽 권한그룹 목록(이름·코드·사용 여부·세트 카드 수) → 오른쪽 카드 목록(보이기 체크 + 위·아래, 홈 "카드 설정" 대화상자와 같은 조작) + 저장·세트 지우기.
- 카드 목록 = **등록된 카드 전체**(그룹이 지금 못 보는 카드 포함, "이 그룹은 {화면} 조회 권한이 없어 보이지 않음" 안내). **숫자는 계산하지 않는다** — 관리자가 이 화면으로 남의 업무 건수를 보지 않게(제목·설명·화면 이름만).

| API | 권한 | 비고 |
|---|---|---|
| `GET /api/home/grp-cards` | `@ProgAuth(home-card-mgt, SEARCH)` | 그룹 목록 + 세트 카드 수 |
| `GET /api/home/grp-cards/{grp}` | 같음 | `{group, ver, cards[{code,title,desc,progCd,progTitle,visible,hidden,inSet}]}` — 없는 그룹(다른 회사 포함) 404 |
| `PUT /api/home/grp-cards/{grp}?ver=` | SAVE | 본문 `[{code, hidden}]` 순서 = 표시 순서. 빈 목록 `REQUIRED`, 등록 안 된 카드 `NO_SUCH_CODE`, 중복 `DUPLICATE`(행 키 = 코드 또는 순번), 200개 초과 400, `ver` 없음 400, 판이 다르면 409 `CONFLICT` |
| `POST /api/home/grp-cards/{grp}/reset?ver=` | SAVE | 세트 지움(그 그룹 사용자는 다음 세트 또는 코드 순서) |

## 16. 4단계 — 카드 다시 읽기 · 카드 숫자 링크 규약 (2026-10-21, 마이그레이션 없음)

> 15.7 후보 1번(사용자 2026-10-21 "1번으로 진행"). 결정 필요는 16.5.

### 16.1 카드 하나 다시 읽기

| API | 권한 | 응답 |
|---|---|---|
| `GET /api/home/cards/{code}` | `@ProgAuth(home-main, SEARCH)` + 카드별 R1·R2 | `{"data": {"asOf", "card": CardView}}` |

- 판정은 홈 전체(`/api/home/cards`)와 **같은 코드 경로**(`visible`)를 쓴다. 볼 수 없는 카드와 없는 코드는 **같은 404**(응답 본문까지 같음) — 권한 없는 카드가 있는지 흘리지 않는다.
- **숨긴 카드도 읽는다** — 숨김은 보기 설정이지 권한이 아니다(화면은 숨긴 카드를 그리지 않으므로 부를 일이 없다).
- 실패 격리·시간 예산은 그대로(R3·R4): 카드 트랜잭션 하나 + `statement_timeout` 2초, 실패면 `error=true`. 트랜잭션 안에서 부르면 거부.
- 화면: 카드 머리 오른쪽 `↻` 버튼(`hb.busy`, 카드별 `hb.latest('home.card.'+code)`), 응답이 오면 **그 카드 자리만** 바꾸고 포커스를 새 `↻` 로. 404(권한을 잃었거나 다른 탭에서 숨김)면 홈 전체를 다시 읽는다.
- 1단계의 "카드 단위 API 없음"(4.3)은 이것으로 바뀐다 — 오류 카드 하나 때문에 전체를 새로 고치지 않아도 된다.

### 16.2 카드 숫자 → 목록 (카드 수준 링크)

- `HomeCard.link`(새 칸, 기존 4인자 생성자 유지 → 모듈 카드 코드 무변경) = 카드 숫자를 누르면 그 숫자의 목록을 여는 조회 조건. 형식·한도는 항목 링크와 같다(`safeLink`: 이름 `^[a-zA-Z][a-zA-Z0-9]{0,29}$`·6개·값 200자, 링크 화면 없는 개인 카드는 버림).
- 화면: `link` 가 있고 숫자 > 0 이면 큰 숫자가 밑줄 버튼(색 + 밑줄)이 되어 셸 `open(progCd, title, params)`(2단계 딥 링크)로 연다. 없으면 지금처럼 글자 숫자 + "화면 열기".
- **규칙: 화면이 카드 조건을 모두 받을 수 있을 때만 `link` 를 채운다.** 일부만 맞으면(예: 기간만) 목록 건수가 카드 숫자와 달라져 "숫자를 믿을 수 없는 홈" 이 된다.

### 16.3 1~3단계 카드 4장의 링크 — 지금은 채우지 않음

| 카드 | 카드 조건 | 대상 화면 조회 패널(현행) | 빠진 칸 |
|---|---|---|---|

## 17. 5단계 — 결재 카드 링크 · 공장 선택 · 새 모듈 카드 (2026-10-21, 마이그레이션 없음)

> 사용자 결정(2026-10-21, 상위 세션 경유): 홈 5단계 = ① 결재 카드 링크(H3) ② 공장 선택(공장 시간대 "오늘", docs/25 D5) ③ QMS·CMS·WMS 카드. 결정 필요는 17.6 — 추천안으로 진행.

### 17.1 결재 카드 링크 (H3 해소)

- `apr-todo` 의 `progCd` 를 `null` → **`sys-approval`**(결재함, 시스템관리 3단계). 결재함은 `self_service_yn = 'Y'` 라 로그인 사용자 모두 조회 권한이 있어 **보이는 범위가 바뀌지 않는다**(R1 통과 = 지금과 같음). 숫자 범위는 R2 그대로(내 차례인 결재만).
- 카드 숫자 링크는 두지 않는다 — 결재함은 조회 패널이 없고 기본 탭이 "내 차례"(`box=TODO`, 기간 없음, 최신 200건)라 **"화면 열기" 만으로 카드 숫자와 같은 목록**이다.

### 17.2 공장 선택 — 공장 시간대 "오늘"

| 항목 | 정한 것 |
|---|---|
| API | `GET /api/home/cards?plant=P1`, `GET /api/home/cards/{code}?plant=P1`, 공장 목록 `GET /api/home/plants`(홈 SEARCH, 사용 중 공장만) |
| 검증 | 없는 공장·사용 중지 공장·다른 회사 공장(RLS 로 안 보임) → 400 `INVALID_VALUE`(칸 `plant`, `NO_SUCH_CODE`) — 조용히 전체로 바꾸지 않는다 |
| 문맥 | `HomeCardContext` 에 `plantCd`(null = 전체)·`plantNow`(공장 시간대, null 이면 회사) 추가. `today()` = 회사 날짜 그대로, **`plantToday()`** = 공장 날짜 |
| 카드 | 제공자 기본 메서드 `plantScoped()`(기본 false). true 인 카드(작업지시·점검·고장)는 공장 조건과 공장 날짜를 쓰고, 링크에 `plantCd` 를 넣는다. false 인 카드(결재·수주·보류 LOT·시정조치·PMS·실사)는 공장 선택과 상관없이 회사 기준 |
| 응답 | `HomeView` 에 `plant`·`plantToday` + 카드마다 `plantScoped` — 화면이 "공장 P1 기준" 표시를 공장 카드에만 붙인다 |
| 화면 | 머리에 공장 선택(전체 + 공장들). 선택은 **브라우저에만 기억**(localStorage, 실패해도 "전체" 로 동작). 바꾸면 전체 다시 읽기 |

- 왜 카드마다 다른 "오늘" 인가: 링크 대상 목록이 그 기준으로 계산한다. 작업지시 목록은 기간을 링크가 날짜로 정해 주므로 공장 날짜를 쓸 수 있고, 시정조치 목록(`CapaMapper`)·고장 목록(`MwoService`, 신고 시각을 회사 시간대로 자름)은 **서버가 회사 날짜로 계산**하므로 카드도 회사 날짜를 써야 숫자가 같다.
- 공장 시간대가 없는 공장(`sys_plant.time_zone` null)은 회사 시간대(`BizClock.zone(plant)` 규칙 그대로).

| 코드 | 패키지 | 링크 화면 | 숫자 | 보조 숫자 | 카드 링크(= 목록과 같은 건수) | 오늘 |
|---|---|---|---|---|---|---|

- **창(window)**: 점검·고장 목록은 기간 필수 + 상한 `DateRanges.maxDays(366)`(회사 정책 `SEARCH_MAX_RANGE_DAYS` 가 더 짧으면 그것). 카드는 같은 상한으로 창을 잡아 **링크가 400 이 나지 않고 건수가 같게** 한다. 창보다 오래 밀린 것은 숫자에 넣지 않고 보조 숫자("1년 넘게 밀린 점검" 등, ALERT)로 따로 알린다 — 숨기지 않되 링크 숫자와 섞지 않는다.
- 쿼리는 각 모듈 패키지의 새 매퍼(`QmsHomeMapper`·`CmsHomeMapper`·`WmsHomeMapper`)에 둔다 — 남의 매퍼 XML 을 고치지 않는다(1단계 `ProductionHomeMapper`·`SalesHomeMapper` 와 같은 방식, H6). 조건이 목록 쿼리와 갈라지면 "카드 숫자 = 목록 건수" 시험이 먼저 깨진다.
- 정렬 순서: 시정조치 660·점검 560·고장 530·실사 760(각 화면 `sys_prog.sort_no` 와 같게 — PMS 800·805 와 겹치지 않음).

## 23. 9단계 — 늦은 ASN 카드 (2026-11-02, 마이그레이션 없음)

| 코드 | 위치 | 화면(R1) | 숫자 | 보조 숫자 | 숫자 링크 | 항목 |
|---|---|---|---|---|---|---|
| `srm-asn-late` | `module.srm.asn` (`AsnLateCard`·`AsnHomeMapper`) | `srm-asn` | 늦은 ASN — 보냄·입고 중 + 덜 받은 행 > 0 + 도착 예정일 < 회사 오늘(목록 "늦은 ASN 만" 과 같은 정의), 목록 상한 창(366일) 안 | 오늘 도착 예정 · 창보다 오래 늦음(있을 때만) | `late=true` + 기간(창 시작 ~ 오늘) + `status`·`keyword` 빈 값 (2,000건 이하) | 오래 늦은 순 5건, 링크 = ASN 번호 + 도착 예정일 하루 + `late=true` |

- 왜: 협력사가 "보냈다" 고 알린 물건이 예정일이 지나도 덜 들어왔다 = 협력사 독촉 또는 입고 누락. ASN(V133) 이후 기다리는 상태가 생겼는데 카드가 없었다. WMS "입고 예정" 은 공장·도착 예정 목록(조회 계약)이라 화면이 다르다 — 카드는 목록 조건을 그대로 받는 ASN 관리 화면으로 잇는다.
- 회사 카드: ASN 목록이 공장 조건 없이 회사 날짜(`clock.today()`)로 "늦음" 을 계산하므로 `ctx.today()`(H21). 목록 기간은 "출하~도착 구간이 기간과 겹침" 이라 늦은 ASN(출하 ≤ 도착 < 오늘)은 기간 끝 = 오늘이면 도착일만 본다.
- 함정(시험으로 발견): 항목 링크에 `late=""` 를 넣으면 목록 API 의 boolean 칸이 **400**. 항목은 모두 늦은 ASN 이라 `late=true` 로 넣는다.
- 성능: 집계는 열린 ASN 만 담은 부분 색인 `ix_srm_asn_open`(V189) 범위 — 받은·마감 ASN 이 쌓여도 읽는 행이 늘지 않는다.
- 결정 **H35 — 사용자 확인 2026-10-22: 추천안**: 숫자 = 늦은 것만(다른 안: 7일 안 도착 예정까지 — 목록이 상태 하나라 숫자 링크를 못 건다). 오늘 도착 예정은 보조 숫자.
