## 1. 요약

### 1.1 한 줄 결론

중소 협력사용 제품에서 AI의 가치는 **모델 자체보다 "학습 가능한 데이터가 키로 묶여 쌓이는 구조"**와 **"AI가 제안하고 사람이 확정하는 화면"**에서 나온다. 모델은 상용 장비·외부 API·오픈소스로 바꿔 끼울 수 있지만, LOT·설비·특성(`qms_char`)·시각으로 묶인 원장과 판정 피드백은 나중에 만들 수 없다. 그래서 **P1~P3에서는 데이터 키와 피드백 기록만 잡고**, 눈에 보이는 AI 기능은 **LLM 기반 도움말·문서 초안·조회(P5 전후)**부터, 예측 모델은 고객 데이터가 쌓인 **2차 이후**에 붙이는 순서를 권한다.

### 1.3 원래 세션에 넘길 결정 사항

1. **공정 파라미터 실측 원장**(`prd_param_actual` 가칭)을 P2 실적 원장과 같이 만들지 — 00 5.3에는 "파라미터 세트(목표·허용범위)"만 있고 **실측값을 LOT·설비·시각으로 남길 테이블이 없다**. 불량 예측·가상 계측·원인 분석이 모두 이것을 입력으로 쓴다. ([3.1](#31-데이터-수집-키--지금-잡아야-하는-것))
2. **AI 모듈 경계**: `sh-ai`(Java, LLM 게이트웨이·도구·RAG)를 모놀리스 안에 두고, 학습·이미지·시계열은 **별도 Python 프로세스 `sh-ml`**(Collector처럼 선택 설치)로 분리할지. ([3.2](#32-모델-서빙-위치))
3. ~~Spring AI 버전~~ → **결정(2026-10-15, 사용자): Spring Boot 4로 간다.** AI는 처음부터 **Spring AI 2.x**(Boot 4 / Spring Framework 7 요구 [L13])를 쓴다. 2.0에서 MCP SSE 전송은 deprecated → **Streamable HTTP** 사용, Jackson 3 기반 ☑️. Boot 4 전환 자체(현재 코드 3.4.5, 전환 시점·영향 범위)는 원래 세션이 00/01과 코드에 반영할 일이다. AI 쪽 영향은 버전 선택뿐이고 이 문서의 구조 제안은 그대로 유효하다.
4. **세 번째 DB 계정**(`yeonos_ai_ro`, 읽기 전용·뷰만 GRANT)을 둘지 — Text-to-SQL을 허용할 때만 필요. `DatabaseRoleGuard` 검사 대상에 포함해야 한다. 권고는 **P6까지 만들지 않고 도구 방식만**.
5. **고객 데이터 학습 정책**을 약관·계약 기본값으로 무엇으로 할지 — 권고: **기본 학습 금지, 회사별 서면 opt-in**, 외부 LLM은 "학습 미사용" 정책 제공사만. ([3.3](#33-saas-멀티테넌트에서-고객-데이터-분리학습-동의))

### 2.1 비전검사

#### 사례·기술
- **비지도 이상탐지(정상 이미지만 학습)가 업계 표준 접근이다.**
  - 학계 기준선: PaDiM [V1], **PatchCore**(CVPR 2022, 정상 패치 메모리뱅크 + 최근접 이웃) [V2], FastFlow [V3], **EfficientAD**(WACV 2024 — 초록 기준 GPU에서 이미지당 약 2ms) [V4] ✅. 여러 품목을 모델 하나로 다루는 UniAD [V5].
  - 합성 불량으로 정상만 학습: CutPaste [V6], DRAEM [V7].
  - 2024~2026 동향: 제로·퓨샷(WinCLIP [V8], AnomalyCLIP [V9], AnomalyDINO [V10] — 정상 1장~수 장). 기존 벤치마크(MVTec AD, VisA)가 포화되어 실환경에 가까운 **MVTec AD 2**(2025)가 나왔고, 저자들은 최신 기법도 이 데이터에서 성능이 크게 떨어진다고 보고했다 [V11] ☑️.
  - **멀티모달 LLM의 직접 판정은 아직 이르다**: MMAD 벤치마크(ICLR 2025)에서 GPT-4o 평균 정확도 74.9%, 저자 결론은 산업 요구 수준에 못 미친다는 것 [V12] ☑️. → LLM은 "불량 설명·보고서 문장" 같은 보조 역할.
- **오픈소스 Anomalib**(Intel open-edge-platform): Apache-2.0, PatchCore·EfficientAD·PaDiM 등 구현, OpenVINO IR 내보내기로 CPU/iGPU/NPU 엣지 추론 [V13] ✅. Jetson은 ONNX → TensorRT 경로 ☑️.
- **상용(해외)**: Cognex VisionPro Deep Learning(Red Analyze 등 도구 체인)·In-Sight 2800 Edge Learning [V14][V15], Keyence IV4·VS(AI 내장 카메라, OPC UA/MQTT) [V16][V17], Landing AI LandingLens [V18], MVTec HALCON 이상탐지·GCAD [V19] — 모두 상용 ☑️.
- **상용(국내)**: 세이지 SAIGE VISION(정상만 학습·가상 결함 생성) [V20], 뉴로클 Neuro-T/Neuro-R(GAN 가상결함, 비지도 이상 분류) [V21], 링크제니시스 VLAD(반도체·자동차 부품, SECS/GEM 업체) [V22], 티윔·슈퍼브에이아이·AHHA Labs·엠엔비젼 등 [V23] ☑️. 트윔은 자동차부품 도금 외관검사 구축 사례가 기사로 있다 [V24] ☑️.
  - 정정: 딥인스펙션은 시설물 안전점검 AI로 제조 라인 비전검사 업체가 아니다. 마키나락스·에이아이비즈는 시계열 이상탐지 중심이다 [V25] ☑️.
- **데이터셋**: VisA는 CC BY 4.0(PCB 포함, 데모 학습 가능) [V26], **MVTec AD 2는 CC BY-NC-SA(비상업)** — 제품 데모 모델 학습에 쓰지 말 것 [V11]. KAMP 제조AI 데이터셋 중 이미지가 확인된 것은 X-ray·크로메이트 2종 정도 [V27] ☑️.
- "중소 자동차부품사가 정상 이미지만으로 외관검사를 도입한" 공개 사례는 이번 조사에서 찾지 못했다.

#### L사 PoC와 대조
| PoC에서 겪은 것 | 조사 결과와의 관계 | 제품 기능으로 바꾸면 |
|---|---|---|
| 부품 검출·정렬 후 학습이 핵심(오검율 54%→0.8%) | 패치 기반 이상탐지는 위치·배경 변화에 민감 — 상용 도구도 Locate → Analyze 체인 구조 [V14] | 모델 문제가 아니라 **촬영·전처리 표준**(지그, 조명, ROI) 문제 → 장비 벤더 몫. MES는 "검사 레시피 리비전"만 관리 |
| 불량 샘플 부족 | 정상만 학습(PatchCore/EfficientAD)과 합성 불량(DRAEM, 상용 가상결함 생성)이 표준 해법 | MES는 **재판정 결과로 불량 이미지를 계속 모으는 피드백 루프** 제공 |
| 판정 스펙 미확정 | 이상 점수 임계값은 결국 **한도견본·고객 합의**로 정해야 함 | QMS에 **한도견본(이미지) + 불량 유형 코드 + 판정 기준 리비전**을 `mst_doc`·`qms_char`에 연결 |

#### 필요한 데이터 / 확보 여부
| 데이터 | 상태 | 비고 |
|---|---|---|
| 검사 결과 ↔ LOT·설비·특성 | 🟡 | P3 측정값에 `lot_no`·`equip_cd`·`gauge_id` 필수(02 채택). 비전 결과도 같은 원장에 `insp_method = VISION` |
| 이미지 원본 참조 | 🔴 | `sys_file` 키 참조 컬럼 + 보존 클래스(이미지 용량 큼 → 보존 기간 별도) |
| 이상 점수·판정·모델 버전 | 🔴 | `score`, `ai_judge`(OK/NG), `model_ver`, `threshold` — 모델 바뀐 시점 추적 |
| 사람 재판정 | 🔴 | `final_judge`, `judged_by`, `defect_cd` — **이것이 라벨 데이터** |
| 한도견본·판정 기준 리비전 | 🟡 | `mst_doc`(P3) + `qms_char` 연결 |

#### 난이도·가치·지원사업
- **결과 수신(어댑터)**: 하~중. 외부 장비 → `/ext/**` + `sys_inbox` 멱등(01 5.8 그대로).
- **자체 추론 서비스**(Anomalib + OpenVINO, Python): 중~상. 1인이 촬영 환경까지 책임지는 순간 범위가 폭발한다 — **고객별 프로젝트로만** 하고 제품 코어에는 넣지 않는다.
- 고객 가치: 상. 다만 효과는 "불량률"보다 "검사 인력·시간"에서 먼저 나타난다는 정부 점검 결과 요약이 있다(1차 보도자료 미확인) [V28] ☑️.
- 지원사업: **제조AI특화 스마트공장·AI바우처의 대표 과제 유형** [G1][G3]. SmartHappy는 "비전 공급기업과 컨소시엄 시 MES 연계·데이터 관리 담당"으로 들어가는 것이 현실적.

#### 제안
- **P3**: 검사 원장에 이미지 참조·AI 점수·모델 버전·재판정 컬럼 자리를 잡는다(값은 비어 있어도 됨).
- **P6**: 비전 결과 수신 어댑터(표준 JSON: `lot_no, equip_cd, char_cd, score, ai_judge, image_uri, model_ver, occurred_at`) + **재판정 화면**(Kendo Grid에 썸네일, NG 이미지 확인 → 확정/오검 처리).
- **2차**: 재판정으로 쌓인 라벨을 내보내기(회사 동의 시) → 장비 벤더 재학습용, 또는 `sh-ml` 자체 PatchCore/EfficientAD.

### 2.2 품질 예측 (공정 파라미터 → 불량, 가상 계측, SPC 조기경보, 원인 분석)

#### 사례·기술
- **공정 파라미터 → 불량 예측은 "트리 모델 + SHAP"이 공통 패턴이다.**
  - 사출: XGBoost·LightGBM + SHAP으로 핵심 변수(사출압·전환압·온도) 도출 [Q1]; KAMP 사출 데이터로 품질불량 예측(국내 학회지) [Q2]; 한 불량만 최적화하면 다른 불량이 늘 수 있다는 지적 [Q3] ☑️.
  - 다이캐스팅: 실공장 사이클 데이터로 RF 최우수, 일정 데이터량 이후 개선 둔화 [Q4]; 기계 내장 공차 판정보다 ML이 우수 [Q5] ☑️.
  - 저항 점용접: 동저항 신호 기반 온라인 검사(자동차 라인) [Q6], 모델 비교 [Q7] ☑️.

- **공통 패턴**: ① 자연어 데이터 조회 ② 문서·매뉴얼 Q&A(출처 인용) ③ 교대·변경 요약 ④ 번역 ⑤ **AI가 제안하고 사람이 확정**.

#### Text-to-SQL의 현실
- Spider 2.0(엔터프라이즈형) 원 논문에서 최고 에이전트 정답률 21.3% [L12] ☑️, 이후 리더보드 점수는 크게 올랐지만 평가 신뢰성 논란이 있다 ☑️.
- 비즈니스 의미 문서(용어·지표 정의)를 붙이면 최신 모델들의 정확도가 약 45~50% → 약 68%로 올랐고 모델 간 차이는 무의미해졌다 [L15] ✅. → **모델 선택보다 용어 정의가 중요하고, 그래도 3번에 1번은 틀린다.**
- "실행은 되지만 틀린 SQL"(날짜 기준·양품 정의·중복 조인)이 가장 위험 [L16] ☑️. MES 숫자(불량률·OEE)를 틀리게 답하면 신뢰가 바로 무너진다.

#### 안전 설계 (SmartHappy 구조에 맞춤)
- **1안(권고): 도구(function calling / MCP) 방식** — 기존 조회 서비스(MyBatis)를 `@Tool`로 노출. LLM은 "어떤 조회를 어떤 파라미터로"만 고르고, SQL은 이미 검증된 코드가 만든다. 요청 사용자의 `TenantContext`·`@ProgAuth`가 그대로 적용되므로 **RLS·화면 권한이 자동으로 지켜진다**. KPI 산식은 `sys_kpi_def`(P5) 하나만 쓴다.
- **2안(제한적 Text-to-SQL)**: 롱테일 질의용. 반드시 ① 별도 읽기 전용 롤(비소유자·NOBYPASSRLS) ② `security_invoker` 뷰만 GRANT ③ `comp_cd`는 서버 코드가 트랜잭션 로컬로 설정, LLM SQL에서 `SET`·`set_config`·다중 문장 금지(파서 검증) ④ `statement_timeout`·LIMIT ⑤ 생성 SQL을 화면에 보여주고 "AI 조회" 표시 [L17][L18] ☑️. 01의 3중 방어와 같은 원리다.

#### 다국어·음성
- 국내 사례: HD한국조선해양이 조선 용어집·작업지시 문장으로 외국인 근로자 번역 PoC(베트남어·우즈베크어·네팔어·태국어) [L19] ☑️, 안전교육 모국어 서비스 [L20] ☑️. 공통 교훈은 **범용 번역기는 현장 용어에 약하다 → 용어집 필수**.
- 음성: Whisper는 오픈웨이트지만 소음 환경은 소음 데이터로 파인튜닝해야 개선된다는 연구(영어) [L21] ☑️. 네이버 CLOVA Speech는 키워드 부스팅 지원, 스트리밍은 한·영·일만 [L22] ☑️. **공장 소음 환경의 한국어 STT 실측 자료는 찾지 못했다.**

| 데이터 | 상태 | 비고 |
|---|---|---|
| 조회 서비스·화면 권한 | 🟢 | P0 `@ProgAuth`, API 규약 |

### 2.5 사용자 매뉴얼·도움말·작업표준서

#### 사례
- 작업자 지원 플랫폼들이 생성형 AI를 이미 상용화: Augmentir(문서·영상으로 작업표준서·체크리스트 생성) [M1], Dozuki(작업 영상으로 SOP, 승인된 지식 기반 Q&A) [M2][M3], Poka(작업지시서 작성, 2026-10 MCP 서버) [M4] ☑️. 공통점: **승인된 콘텐츠만 근거로, 사람이 편집·승인**. 시간 절감 수치는 모두 업체 주장.
- "화면에서 도움말 자동 생성"을 직접 제품화한 사례는 찾지 못했다(Critical Manufacturing의 객체·문서 Q&A가 가장 가깝다 [L5]).
- 기술: **pgvector**(PostgreSQL License, 일반 테이블이라 **RLS가 벡터 검색에도 그대로 적용**) [M5][M6] ☑️. 주의: 필터 + HNSW 근사 검색 조합에서 결과가 덜 나오는 문제 → 테넌트별 recall 테스트 [M7] ☑️. Spring AI `PgVectorStore`(HNSW, COSINE 기본 — 1.1 문서 기준 [L13], 2.x에서 재확인) ☑️ — 단 자체 `JdbcTemplate`을 쓰므로 **`TenantAwareTransactionManager`의 `set_config`가 같은 트랜잭션에 걸리는지 테스트로 확인**해야 한다(⚠️ 추론, 미검증).

#### SmartHappy에 특히 맞는 이유
- HappyBoot는 화면이 `sys_prog`(프로그램)·메뉴·권한·API 규약으로 **메타데이터화**되어 있다. 화면 정의(그리드 컬럼·버튼·상태 전이 `confirm/cancel/start`)와 정책 키(`SYS_POLICY`)를 입력으로 LLM이 **도움말 초안**을 만들고, 사람이 검수해 저장하는 구조가 가능하다. 고객별 정책 차이(LOT 정책·게이트 모드)가 도움말에 반영되는 점이 범용 매뉴얼보다 낫다.
- 관리문서 리비전(`mst_doc`, P3)을 RAG 원천으로 쓰면 "**POP에서 최신판 작업표준서에만 근거해 답변**"이 된다(구판 인용 방지).

#### 필요한 데이터 / 확보 여부
| 데이터 | 상태 |
|---|---|
| 화면·메뉴·권한 메타 | 🟢 P0 |
| 정책 키·설명 | 🟢 P0 |
| 관리문서·리비전·배포 상태 | 🟢 P3 |
| 문서 청크·임베딩 | 🔴 `ai_doc_chunk`(회사별, RLS) + `ai_prod_doc_chunk`(제품 공통 매뉴얼, 전역) 분리 |

#### 난이도·가치·지원사업
- 도움말 초안 생성(배치, 사람 검수): 하~중. RAG 검색: 중. 작업표준서 초안: 중(사진·영상은 2차).
- 고객 가치: 중~상 — **1인 개발자의 지원 부담을 줄이는 효과가 가장 직접적**(문의 응대). 정부지원 사업의 "구축 후 미활용" 문제(02 2.7)를 줄이는 근거로도 쓸 수 있다.

#### 제안
- **P0~P1**: 화면 정의에 `help_key`, 정책 정의에 설명 컬럼을 두는 규칙만.
- **P5**: 제품 매뉴얼 RAG(전역) → 회사 관리문서 RAG(회사별) 순서. 답변에 문서명·리비전·페이지 인용 필수, 근거 없으면 "모름".
- **P5**: 도움말 초안 자동 생성 → 검수 → 저장(빌드 시 배치, 런타임 호출 아님).

## 3. SmartHappy 아키텍처에 AI를 붙이는 방식

### 3.1 데이터 수집 키 — 지금 잡아야 하는 것

AI 기능은 나중에 붙여도 되지만, **아래 키가 없으면 나중에 학습 데이터를 만들 수 없다**(02 6장 판단 기준 ① 그대로).

| 키·테이블 | 내용 | 시점 | AI 용도 |
|---|---|---|---|
| 공정 파라미터 실측 원장 (신규) | `equip_cd, lot_no/wo_id, param_cd, value, occurred_at, recorded_at, source` — 원장 규약 | **P2** | 불량 예측, VM, 원인 분석 |
| 불량 유형 코드 2단(표준 상위 + 회사 하위) | 실적 폐기·재작업, NCR, 비전 재판정에 같은 코드 | **P1~P2** | 모든 품질 모델의 라벨 |
| 검사 원장 확장 | `insp_method`, `image_file_id`, `ai_score`, `ai_judge`, `model_ver`, `final_judge`, `judged_by` | **P3** | 비전 피드백 루프 |
| 내시(수요 예측) 버전 보관 | 수신 버전별 스냅샷, 덮어쓰기 금지 | **P2** | 내시 정확도, 수요 예측 |
| 알람 이벤트 | Collector 표준 이벤트에 `ALARM`(코드·심각도·발생·해제) | **P2** 스키마 | 예지보전 |
| 고장 모드 코드 | 수리 이력의 표준 고장 모드 | **P5** | 예지보전 라벨 |
| 용어 사전 | 지표·용어 정의, 동의어, 다국어 번역어 | **P1** 테이블 / P5 내용 | Text-to-SQL, RAG, 번역 |
| `help_key`·정책 설명 | 화면·정책 메타 | **P0~P1** 규칙 | 도움말 생성 |

시각은 모두 `occurred_at` 기준(설비 시계 보정은 Collector 책임), 키는 LOT·설비·특성(`qms_char`)·작업지시로 통일 — 이 4개로 조인되면 대부분의 분석이 가능하다.

### 3.2 모델 서빙 위치

| 구성 | 위치 | 내용 | 이유 |
|---|---|---|---|
| **`sh-ai` 모듈** | 모놀리스 안(Java) | LLM 게이트웨이(포트/어댑터), 도구(조회 서비스 노출), RAG(pgvector), 호출 감사, 회사별 AI 정책 | LLM 호출은 HTTP API라 Java로 충분. 권한·테넌트 컨텍스트를 그대로 써야 한다 |
| **`sh-ml` 서비스** | **별도 프로세스(Python, 선택 설치)** — Collector와 같은 취급 | 학습·배치 추론: LightGBM/SHAP, Chronos-2, Anomalib(이미지), 알람 패턴 | 생태계가 Python. 무거운 의존성을 모놀리스에 넣지 않는다. 없으면 기능만 꺼진다 |
| 외부 LLM API | SaaS 기본 | Claude·OpenAI 등(학습 미사용 정책 [L23][L24] ✅) | 1인 운영으로 GPU 서버를 유지할 수 없다 |
| 로컬 LLM | 설치형·폐쇄망 옵션 | Ollama/vLLM + 상업 이용 가능한 오픈웨이트(Qwen3 Apache-2.0 등, **모델별 라이선스 확인**) [L25] ☑️ | Siemens·Rockwell도 온프레미스판을 따로 냈다 [L2][L9] |
| 비전 추론 | 현장 엣지(카메라·IPC) | 상용 장비 또는 Anomalib+OpenVINO | 지연·네트워크·이미지 용량 |

**연동 규칙 (01 설계 재사용)**
- `sh-ai` → 외부 LLM: 화면 응답이 필요한 대화는 동기 호출(타임아웃·실패 시 "AI 없이" 계속 동작). 배치(도움말 생성, 요약, 번역)는 **아웃박스** 경유.
- `sh-ml` ↔ 모놀리스: `sh-ml`이 DB에 직접 쓰지 않는다. ① 학습 데이터는 **회사별 내보내기 API**(TenantRunner 경유, 동의 플래그 확인) ② 결과는 `/ext/ml/**` + `sys_inbox` 멱등 수신 → 결과 원장(`ml_score` 가칭: 대상 키, 점수, 모델 버전, 생성 시각). Collector와 같은 패턴이라 새 개념이 없다.
- **AI 없이도 모든 업무가 끝나야 한다** — AI 결과는 항상 "제안" 컬럼이고, 확정 컬럼은 사람이 쓴다(SAP Joule [L4], 작업자 플랫폼 공통 패턴).
- JVM 안 추론이 필요하면 ONNX Runtime Java로 작은 모델만(⚠️ 미검증, 2차 검토).

```
[브라우저/POP] ─ Spring(sh-*) ─ sh-ai ──(동기/아웃박스)──> 외부 LLM API | 로컬 Ollama
                      │            └─ pgvector(ai_doc_chunk, RLS)
                      ├─ /ext/ml/** <──(sys_inbox)── sh-ml (Python, 선택) <── 내보내기 API(동의 시)
                      └─ /ext/**    <──(sys_inbox)── sh-collector, 비전 장비
```

### 3.3 SaaS 멀티테넌트에서 고객 데이터 분리·학습 동의

- **RLS를 AI 테이블에도 똑같이**: `ai_doc_chunk`, `sys_ai_call_log`(프롬프트·응답 요약·토큰·모델·사용자·`prog_cd`), `sys_ai_feedback`, `ml_score`, 내보내기 이력 모두 `comp_cd` + FORCE RLS + `tenant_isolation`. 격리 테스트(`TenantIsolationTest` 류)에 "A사 문서가 B사 RAG 검색에 안 나온다"를 추가. 제품 공통 매뉴얼만 전역 테이블.
- **검색·도구 호출은 실행 전에 테넌트로 제한**(사후 필터 금지), 트레이싱·로그 저장소도 고객 데이터로 취급 [D1] ☑️.
- **회사별 AI 정책**(`SYS_POLICY` 키로 충분): `AI_ENABLED`, `AI_EXTERNAL_API_ALLOWED`, `AI_PROVIDER`(EXTERNAL/LOCAL/NONE), `AI_TRAINING_CONSENT`(서면 동의일·범위), `AI_PII_MASKING`.
- **학습**: 기본은 **회사별 모델만**, 회사 간 통합 학습은 금지. 통합 학습 데이터는 지울 수 없으므로(un-train 불가) 사전 동의가 필요하다는 것이 SaaS 아키텍처 가이드의 공통 권고 [D2][D3] ☑️. 계약에 "서비스 개선" 같은 포괄 문구 대신 **학습 금지 기본 + 서면 opt-in + 하위 LLM 제공사까지 학습 금지** [D4] ☑️.
- **개인정보**: 작업자명·사번은 LLM 프롬프트에 넣기 전에 코드로 치환. 개인정보보호위원회 「생성형 AI 개발·활용을 위한 개인정보 처리 안내서」(2025-08) 확인 [D5] ✅.
- 공공기관에 공급하지 않는 한 CSAP는 의무가 아니다 [D6] ☑️.

### 3.4 온프레미스(설치형) 고객 대응

| 고객 환경 | LLM | ML | 비고 |
|---|---|---|---|
| 인터넷 허용 | 외부 API(고객 키 또는 우리 키) | `sh-ml` 고객 서버 설치(선택) | SaaS와 같은 코드, 정책 값만 다름(01 1.3 원칙) |
| 폐쇄망 | 로컬 Ollama + 오픈웨이트(사양: GPU 서버 필요 ⚠️) 또는 **AI 끔** | `sh-ml` 오프라인 설치 | 모델 파일 반입 절차, 라이선스 고지 |
| AI 불필요 | NONE | 없음 | **모든 기능이 AI 없이 동작**해야 함 |

- `LlmPort` 인터페이스 하나에 `ExternalApiAdapter`, `OllamaAdapter`, `NoopAdapter` — 01의 `FileStorage`(Local/S3)와 같은 방식.

| 고장 모드 코드 | **P5** | 예지보전 라벨 |

### 6.3 기능 로드맵 (Top 10) — 동의, 일부 조정

- 동의: SPC 규칙 경보 P3, 비전 결과 수신 스키마 P3·연계 P6, RAG 도움말 P5, NCR·8D 초안 P5, 문서 OCR P5, 자연어 조회(도구 방식) P6, 간이 예지보전·불량/수요 예측 2차.
- 조정: **AI 호출 감사 로그(`sys_ai_call_log`)·AI 테이블 RLS 는 AI 기능 첫 착수(P5) 때 같이** — 별도 단계로 미루지 않는다. 격리 테스트에 "A사 문서가 B사 RAG 검색에 나오지 않음" 추가.
- 표기 원칙 채택: SPC 규칙·ABC 분석·최적화는 "AI"라고 부르지 않는다(지원사업 평가·고객 감사 대응).

### 6.4 하지 말 것 (4장) — 전부 동의

특히 LLM 이미지 직접 양불 판정, 코어에 자체 비전 학습 엔진, 무제한 Text-to-SQL, 상업 금지 오픈웨이트(EXAONE 4.0 등) 번들, 비상업 데이터셋(MVTec AD 2)으로 데모 학습, 동의 없는 통합 학습은 00 6장 "하지 않는 것"에 추가한다.
