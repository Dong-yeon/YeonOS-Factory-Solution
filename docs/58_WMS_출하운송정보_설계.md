## 0. 요약

- **무엇**: 출하 지시에 운송사·차량 번호·송장 번호를 적고, 상차·적재 사진이나 운송장 스캔(PDF)을 증빙으로 붙인다.
- **왜**: docs/49 2장 표 "출하 — 운송 정보·증빙 사진: 없음". 고객이 "어느 차로 언제 나갔나·송장 번호" 를 물을 때 출하 화면에서 바로 답하고, 파손 클레임 때 상차 사진을 증빙으로.
- **어디**: 사무 출하 화면(`wms-ship`) 상세 아래 "운송 정보·사진" 칸. PDA 는 이번 범위 밖(4장).

## 1. 모양

| 항목 | 결정 | 근거 |
|---|---|---|
| 저장 위치 | 새 표 `wms_ship_transport`(지시 1 : 0..1, PK = `ship_id`) | 머리(`wms_ship`)에 열을 더하면 운송 저장이 머리 `row_ver` 를 올린다 → 사무가 송장 번호를 적는 사이 PDA·사무 피킹·확정이 409 `CONFLICT` 로 튕긴다(`ShipService.lock` 이 머리 rowVer 비교). 따로 두면 운송 정보끼리만 겨룬다 |
| 동시성 | 머리를 `FOR UPDATE`(지시 취소와 줄 세움, 머리 row_ver 는 안 올림) → 운송 행 `row_ver` 비교. 행이 없으면 rowVer = null 로 보내야 함 | 둘이 동시에 처음 저장하면 늦은 쪽 409(덮어쓰기 없음) |
| 고칠 수 있는 상태 | DRAFT·PICKING·**SHIPPED**, CANCELLED 는 409 `WMS_SHIP_STATE` | 송장 번호는 보통 출하 확정 뒤에 나온다 |
| 입력 | 운송사 100자·차량 번호 30자·송장 번호 60자, 앞뒤 공백 정리, 빈 값 = 지움(null), 제어문자 400 `FORMAT` | DB CHECK 도 빈 문자열 거부(최종 방어) |
| 운송사 | 자유 입력 | 운송사 기준정보는 아직 없음 — 쓰임이 쌓이면 기준정보로(4장) |
| 회사 격리 | RLS + **회사까지 맞춘 FK** `(comp_cd, ship_id) → wms_ship(comp_cd, ship_id)`(`uq_wms_ship_comp_id` 추가) | `ship_id` 만 FK 면 FK 검사는 RLS 를 보지 않아, B사 세션이 A사 지시 id 로 자기 회사 행을 넣어 A사 운송 행을 PK 충돌로 막을 수 있다(직접 SQL 시험으로 확인) |
| 감사·보존 | `hb_audit` 트리거, 앱 계정 DELETE 없음, 보존 클래스 `QUALITY_RECORD`(출하 표와 같음) | W-8 |
| 사진·증빙 | 플랫폼 첨부 `sys_file`(target_type = `wms-ship`, target_id = 지시 id) — 새 표 없음. 권한 = 출하 화면 SEARCH(보기)·SAVE(올리기·지우기) | 플랫폼 `FileService` 검사(확장자·크기·시그니처·SHA-256)를 그대로 |
| 사진 잠금 | `ShipFileLock`(FileLockRule): 취소된 지시·없는 지시(다른 회사 포함)·숫자 아닌 id → 409 `FILE_LOCKED` | 플랫폼 첨부는 대상 존재를 모른다 — 없는 지시에 붙은 파일이 생기지 않게. 읽기는 취소 지시도 됨 |
| 사진 보존 | 출하 기록과 같음 — 지우기는 `use_yn = 'N'`(실제 파일·변경 감사 남음) | W-8 "별도 규칙 없음" |
| 목록 | 출하 그리드에 운송사·송장 번호 열(좁은 화면에선 숨김 우선순위 3) | |

API: `POST /api/wms/ships/{id}/transport` `{rowVer, carrierNm, vehicleNo, trackingNo}` → 상세(`ShipView`, 머리에 `carrierNm`·`vehicleNo`·`trackingNo`·`transportRowVer`·`transportAt`·`transportBy`). 사진은 기존 `/api/platform/files`.

## 2. 화면

- 상세 맨 아래 "운송 정보·사진": 세 칸 + [운송 정보 저장](SAVE, 취소 지시는 읽기만), 마지막 수정 시각·사람, 첨부 목록(내려받기·지우기) + 파일 고르기(`image/*,.pdf`).
- 다른 동작(피킹 등)으로 상세를 다시 그려도 운송 rowVer 가 그대로면 치던 값을 덮지 않는다(`transKey`).

## 3. 하지 않음 · 고른 것

- **운전자 이름·연락처는 받지 않는다** — 개인정보(이름+전화)를 새로 모으지 않는다(최소 수집). 필요하면 운송사 쪽 연락처로. 요구가 생기면 보존·가림(감사 로그 가릴 컬럼) 설계와 함께 따로.
- 배차(차량 배정·적재율)·문자 발송·운송사 연동(송장 조회 API) — 범위 밖(docs/49 2장 "배차·사진·문자" 중 기록만).
- ERP 출하 송신(아웃박스) 본문에 송장 번호 — 넣지 않음(확정 시점에 보통 아직 없음, 정정 송신 규칙이 필요).
- 송장 번호로 지시 찾기(검색 조건) — 후속 후보.
