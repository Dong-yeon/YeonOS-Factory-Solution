## 2. 고칠 것

### F1. 예시 파일(.env.example)에 실제 값이 들어가는 것을 기계적으로 막기 — **상 · S**

- **위험**: 저장소에 비밀번호가 남으면 이력에서 지울 수 없다(공개 여부와 무관하게 포크·클론·캐시). 이번에도 사용자가 예시 파일에 실제 값을 넣는 실수가 있었다.
- **현재 상태**
  - 작업 트리의 `.env.example` 에 **스테이징되지 않은 변경**이 있고, 개발 관리자·운영자 부트스트랩 비밀번호 줄이 예시 값(`change-me…`)이 아닌 값으로 바뀌어 있다(커밋 전 — 상위 세션에 별도로 알림). 스테이징된 쪽은 DB 이름 3줄뿐.
  - 예시 값 차단 목록은 고정 문자열 집합이라 예시 파일과 따로 논다 — `ProdStartupGuard.java:46-47`. 예시 파일 값이 바뀌면 운영 가드도 그 값을 모른다.
  - 비밀 스캔 도구(gitleaks 등)·커밋 전 훅 없음(`.github/`·빌드 스크립트에 없음).
- **제안**
  1. 가드 시험 `EnvExampleGuardTest`(guard/ 아래): `.env.example`·`deploy/demo/.env.example` 에서 이름이 `*_PASSWORD`·`*_SECRET*`·`*_KEY`·`*_TOKEN`·`*_CIPHER_PASS` 인 줄은 **비었거나 `change-me` 로 시작**해야 통과. 운영 가드의 예시 목록에 그 값들이 다 들어 있는지도 같은 시험에서 대조(목록 동기화).
  2. 비밀 스캔 1회(이력 전체) + 이후 수동 CI 또는 로컬 훅. Actions 자동 실행은 꺼져 있으니(2026-11-02) **로컬 훅 또는 `check` 에 붙는 가벼운 패턴 검사**가 현실적.
  3. 로컬 개발 비밀번호는 `.env` 에만 — 이미 규칙(CLAUDE.md "`.env` 커밋 금지")이지만 예시 파일 쪽 규칙이 없다. TESTING/CLAUDE 에 한 줄.
- **노력**: S(시험 1개 + 문서 한 줄). 스캔 도구 반입은 의존성 정책 확인 필요.

### F2. 런북의 운영자 키 생성 방식 — **상 · S (문서)**

- **위험**: 런북 예시가 앱 실행 명령 안에서 키를 **매번 새로 만든다**. 그대로 따라 하면 재기동할 때마다 키가 바뀌어 봉인된 운영자 TOTP 비밀을 열 수 없고, `MFA_SECRET_KEY` 를 따로 안 준 설치본은 회사 관리자 MFA 비밀도 전부 못 연다 → **관리자 전원 로그인 불가(가용성)**. 또 키를 명령줄에 두면 셸 기록·프로세스 목록에 남는다.
- **현재 상태**: `deploy/README.md:20`. 키 백업·분실 절차는 런북에 없다(MFA 분실 절차 5.1 은 사람 쪽 절차).
- **제안**: ① 키는 설치 때 **한 번** 만들어 권한 600 환경 파일(systemd `EnvironmentFile`, Windows 는 서비스 계정만 읽는 파일)·비밀 보관소에 둔다 ② **키 사본은 DB 백업과 다른 곳**(01 7.2 "백업 암호화 키는 DB 서버와 다른 곳" 과 같은 원칙)에 ③ 키를 잃었을 때 = 운영자 TOTP 재등록 절차·회사 MFA 초기화 범위를 런북에 ④ 같은 문서의 다른 비밀(`DB_*_PASSWORD`)도 명령줄이 아니라 환경 파일로 예시를 바꾼다.
- **노력**: S. 이름 변경 작업이 `deploy/README.md` 를 고치는 중이니 **그 커밋 뒤** 별도로.

### F3. SaaS 모드에서 "서버가 사설망으로 먼저 연결하는 기능" 막기 — **상 · M**

- **위험**: 설계는 DIRECT 장비 어댑터(HTTP POST)와 라벨 프린터 직접 TCP 를 **설치형 전용**으로 정했다(docs/65 11·293행 "DIRECT = 설치형", docs/30 D6 "SaaS 인쇄 에이전트는 2부"). SaaS 에서 이 기능이 열려 있으면, 권한 있는 회사 사용자가 **호스팅 망의 사설 주소**(다른 내부 서비스, 같은 망의 다른 회사 자원)로 서버가 요청을 보내게 만들 수 있다(SSRF 성격). 사설 대역만 허용하는 지금 검사는 설치형 LAN 에는 맞지만 SaaS 에서는 오히려 공격 대상 대역이다.
- **현재 상태 (추정 포함)**: 연동 저장은 연결 방식이 `DIRECT`/`EDGE` 인지·주소 형식만 본다 — `EquipLinkService.java:129-150`. 배포 모드(`happyboot.deploy.mode`) 검사를 `module/cms`·`module/wms/label` 에서 찾지 못했다(**추정: SaaS 에서도 열려 있음** — 화면·정책 쪽 차단이 따로 있는지는 확인 못 함). 송신기 `EquipCmdHandler.java:57-69`, `LabelPrintHandler`.
- **제안**: `deploy.mode=saas` 이면 ① DIRECT 연동·프린터 직접 주소 **저장 거부**(칸 오류) ② 송신기에서도 한 번 더 거부(직접 SQL·옛 데이터 대비) ③ 시험: SaaS 모드 저장 400·송신 fail, onprem 모드 그대로. 데모(`prod,demo`)는 SaaS 모드라 가짜 엣지(EDGE) 시연만 남는지 확인 필요.
- **노력**: M(두 모듈 + 시험). 하위 세션 대상.

### F4. 데모 배포 묶음이 MFA 키를 앱에 넘기지 않음 — **상(가용성) · S**

- **위험**: 운영 가드는 prod 프로필에서 MFA 키가 없으면 기동을 멈춘다. 데모는 `prod,demo` 다.
- **현재 상태**: 커밋된 `deploy/demo/compose.yml` 의 `app.environment` 에 MFA·운영자 키 항목이 없다(compose 의 `.env` 는 보간에만 쓰이고 컨테이너로 자동 전달되지 않는다). 이 파일의 마지막 커밋은 2026-10-20 이고 MFA 키 가드는 10-21 에 들어왔다 — `ProdStartupGuard.java:93-105`. **추정: 지금 묶음으로 데모를 다시 배포하면 기동 거부**(VM 의 실제 파일이 다를 수 있어 확인 필요).
- **제안**: `MFA_SECRET_KEY: ${MFA_SECRET_KEY:?}` 를 app 에 추가하고 `deploy/demo/.env.example`·README 에 항목(값 없이). **가드를 약화하지 않는다.** 데모는 운영자 콘솔을 쓰지 않으니 운영자 키는 넣지 않는 편이 낫다(키 분리 — Q2).

### F5. 로그인 시도 제한의 빈틈 — **중 · S**

- **위험**: 계정 잠금(DB)은 그대로라 단일 계정 대입은 막히지만, **여러 계정에 흔한 비밀번호를 하나씩 대 보는 시도(스프레이)** 에 대한 IP+회사 제한이 약해지는 경로가 있다.
- **현재 상태**: ① 로그인 성공 때 IP+회사 실패 수를 통째로 지운다 — `LoginAttemptLimiter.java:67-69`(같은 회사 계정 하나를 가진 사람이 제한을 되돌릴 수 있다) ② 키가 5만 개를 넘으면 전체를 비운다 — `:90-92` ③ IPv6 는 주소 단위(대개 /64 를 통째로 받으므로 주소를 바꿔 가며 우회 가능) ④ 인메모리라 다중 인스턴스에서 인스턴스마다 따로 센다(SaaS 확장 시).
- **제안**: 성공 시 전체 삭제 대신 유지(또는 그 계정 몫만 차감) / IPv6 를 /64 로 정규화 / 전체 비우기 대신 오래된 창부터 축출 / "같은 IP 에서 서로 다른 계정 N개 실패" 를 ALERT 로(01 7.3 탐지 규칙 "여러 계정 동시 실패" 를 코드로). ④는 SaaS 다중 인스턴스가 정해질 때(공장 NAT 신뢰 IP — 05 G14 — 와 함께).
- **노력**: S(③까지), ④는 M.

### F6. 운영자 TOTP 봉인·재사용 방지를 회사 MFA 수준으로 — **중 · S**

- **위험**: 회사 사용자 MFA 는 봉인을 사용자에 묶었지만(AAD — docs/36 14.4.1 #6) 운영자 쪽은 묶지 않았다. DB 쓰기 권한을 얻은 사람이 운영자 행끼리 봉인값을 옮겨 넣을 수 있다. 또 같은 코드 재사용 방지 기록이 메모리에만 있어 재기동 직후 짧은 창이 있다.
- **현재 상태**: AAD 없이 봉인 `OpsAuthService.java:145`, 열기 `:105`, 재사용 기록 `:39`(ConcurrentHashMap). 회사 MFA 는 `last_step` 칸 + 조건부 UPDATE(docs/36 14.4.1 #2).
- **제안**: `sys_operator:{op_id}` AAD(옛 값은 AAD 없이 한 번 열리면 그 자리에서 다시 봉인 — 마이그레이션 없이 점진 전환), `sys_operator.totp_last_step` 칸(새 V)과 조건부 갱신.
- **노력**: S~M(V 1개 + 시험).

### F7. 봉인 키 회전 경로 — **중 · M**

- **위험**: 키가 새거나 의심될 때 바꿀 방법이 "전원 재등록" 뿐이다 → 실제로는 바꾸지 않게 된다.
- **현재 상태**: 봉인 형식이 `Base64(iv‖암호문)` 로 키 식별자가 없다 — `SecretBox.java:13-28`. 같은 상자를 운영자 TOTP·회사 MFA·(설계상) SSO 클라이언트 비밀이 같이 쓴다(docs/36 16.4).
- **제안**: 접두 `k{n}:` 키 버전 + 열기 전용 옛 키(`*_SECRET_KEY_PREV`) + 운영 도구 "다시 봉인"(migrate 프로필 같은 일회 실행). 옛 형식(접두 없음)은 k1 로 읽는다. 런북에 회전 절차.
- **노력**: M.

### F8. 첨부 파일이 백업·복원 시험에 없음 — **중~상 · S~M**

- **위험**: 랜섬웨어·디스크 고장 뒤 DB 는 PITR 로 돌아와도 **첨부(도면·성적서·PPAP 문서)는 사라진다**. `sys_file` 행은 있는데 파일이 없는 상태가 된다.
- **현재 상태**: docs/01 7.2 는 "설치형은 DB 백업과 같은 시점 묶음, `sys_file` 해시로 복원 후 검증" 으로 정했지만, `deploy/backup/linux/backup.sh`·`windows/backup.ps1`·두 `restore-test` 모두 첨부 루트(`FILE_ROOT`, `application.yml:111`)·`sys_file`·해시를 다루지 않는다(문자열 0건 확인). 런북 3장 표도 DB 만.
- **제안**: ① 백업 스크립트에 첨부 루트 스냅샷(추가만 하는 복사 — 저장 키가 uuid 라 덮어쓰기 없음)을 불변 사본으로 ② 복원 시험에 `sys_file` 표본 N건 SHA-256 대조 → 상태 파일 `last-restore-test.json` 에 결과 ③ 백업 건강 상태에 "첨부 마지막 백업". PDA APK 폴더(`PDA_APK_DIR`)는 다시 만들 수 있어 제외 가능.
- **노력**: S(Linux) + S(Windows) + 시험 문서. 이 문서의 1.2 "다이제스트 반출" 도 같은 스크립트에 붙이면 함께 끝난다.

### F9. `/ext/**` 잘못된 키 요청의 비용 — **중 · S**

- **위험**: 키는 32바이트 난수라 추측 공격은 현실적이지 않다. 대신 **잘못된 Bearer 를 대량으로 보내면** 요청마다 DB 조회 + 접속 로그 1행이 생겨 로그 테이블이 부풀고(보존·다이제스트 대상) 연결 풀을 쓴다.
- **현재 상태**: 실패 기록 `ExtSecurityConfig.java:83` → `PopAuthService.java:211-214`, 인증 `:176-203`(회사 형식이 맞으면 그 회사 범위에서 조회). IP 단위 제한 없음. (정정: 처음 판에 "정상 요청도 매번 UPDATE" 라고 썼으나 `PopMapper.xml` `touch` 가 이미 1분 간격으로만 갱신한다 — 해당 없음.)
- **제안**: 같은 출처의 거부 기록을 분당 상한까지만 남긴다. 요청 자체를 IP 로 막으면 공장 NAT 뒤 고장 난 장치 하나가 같은 IP 의 정상 장치까지 끊으므로 막지 않는다(응답은 늘 401).
- **노력**: S.

### F10. 데모 컨테이너 강화 — **하 · S**

- **현재 상태**: 이미지가 태그로만 고정(`deploy/demo/compose.yml:15` `postgres:16-alpine`, `:75` `caddy:2`, `deploy/demo/Dockerfile:1` `eclipse-temurin:25-jre`). Actions 는 SHA 로 고정하면서(`WorkflowPinGuardTest`) 이미지는 아님. `no-new-privileges`·`cap_drop`·읽기 전용 루트 없음. 앱은 비루트 사용자(`Dockerfile:2-5`)라 좋다.
- **제안**: 다이제스트 고정(`image@sha256:…` + 주석에 태그) + 같은 결의 가드 시험, `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]`(caddy 는 `NET_BIND_SERVICE` 만), app `read_only: true` + `/tmp` tmpfs(첨부 임시 파일 위치 확인 필요 — 추정).
- **노력**: S. 이름 변경 커밋 뒤.

### F11. 브라우저 쪽 추가 방어 — **하 · S**

- **현재 상태**: CSP 는 강하다(`SecurityConfig.java:43-45`). 로그아웃은 세션 쿠키만 지운다(`:100-108`). 세션 쿠키 이름은 기본값(`application-prod.yml:11-17`).
- **제안**
  - `require-trusted-types-for 'script'` — 이미 innerHTML·insertAdjacentHTML 금지 가드가 있어 우리 코드는 거의 그대로 통과할 것(추정). **vendor(Kendo·Highcharts)가 DOM 싱크를 쓰는지** 먼저 확인 — 막히면 Report-Only 로 시작.
  - `Cross-Origin-Opener-Policy: same-origin`(다른 창이 우리 창을 잡지 못하게).
  - 사무 화면 로그아웃에 `Clear-Site-Data: "cache"`(공용 PC). `"storage"` 는 POP·PDA 의 IndexedDB 대기열·서비스 워커를 지우므로 **사무 체인에만**.
  - prod 세션 쿠키 이름 `__Host-` 접두(Secure·Path=/·Domain 없음 강제). 데모·설치형 모두 https 라 영향 없음(추정).
- **노력**: S(각각), Trusted Types 는 vendor 확인에 따라 M.

### F12. `.env` 읽기 규칙 차이 — **하 · S**

- **위험**: 같은 `.env` 를 compose 는 compose 규칙(따옴표 제거·`$` 보간), Spring 은 Java properties 규칙(따옴표 그대로·`\` 이스케이프·앞 공백 제거)으로 읽는다 → 특수문자·따옴표가 있으면 **DB 컨테이너가 만든 비밀번호와 앱이 보내는 비밀번호가 조용히 달라진다**(증상은 28P01, 원인은 안 보임 — SKILL §5 2026-10-22 함정과 같은 결). 또 Spring 쪽 가져오기는 프로필 구분 없이 **작업 폴더의 `.env` 를 운영에서도 읽는다**.
- **현재 상태**: `application.yml:12` `optional:file:.env[.properties]`, `docker-compose.yml:15-17`. 데모 DB 초기화는 이미 비밀번호를 `[A-Za-z0-9_-]{16,}` 로 제한한다 — `deploy/demo/initdb/01-init-roles.sh:7`.
- **제안**: ① 로컬도 같은 문자 집합 규칙(LocalDevSeeder·local 프로필 기동 시 DB 비밀번호에 따옴표·`$`·`\`·공백이 있으면 경고) ② `.env.example` 머리 주석에 규칙 한 줄 ③ prod 프로필에서 작업 폴더 `.env` 를 읽었으면 경고 로그(운영은 환경 파일·서비스 설정이 원칙 — 끌지 말지는 Q8).
- **노력**: S.

시험 결과(작업 트리 복사본, JDK 25, Testcontainers): 전체 `./gradlew check` **3,193건 중 실패 1 = `EnvExampleGuardTest`(의도, 아래)**, 16 건너뜀, JS 검사는 Node 없음으로 건너뜀(JS 변경 없음). 복사본에서 `.env.example` 두 줄을 `change-me…` 로 되돌리면 그 가드도 3/3 통과. 기존 `LoginSessionTest` 의 "성공하면 IP|회사 실패 수 초기화" 시험은 F5 로 규칙이 바뀌어 새 규칙 시험으로 바꿨다.

알려진 한계·주의:
- **F1 가드는 지금 작업 트리에서 실패한다**(의도) — `.env.example` 의 미커밋 변경 2줄(개발 관리자·운영자 부트스트랩 비밀번호)을 잡는다. 사용자가 그 두 줄을 `change-me…` 로 되돌리면 통과. 이 세션은 그 파일을 고치지 않았다(사용자 변경).
- F3: 기존 local 개발(saas 모드)은 local 프로필이라 그대로 켜짐. **공개 데모(prod,demo)는 꺼진다** — 데모에서 DIRECT·프린터 시연을 하려면 `LAN_DIRECT=true`(데모 VM 망이 분리돼 있다는 판단 뒤). 설치형 기본값은 그대로.
- F5: 인스턴스별 인메모리 한계(④)와 "같은 IP 여러 계정 실패" ALERT 는 하지 않았다(접속 로그 이벤트 코드 추가 = 스키마 — 별도).
- F6: 재기동 직후 1분 안에 같은 운영자가 다시 로그인하면 다음 코드를 기다려야 한다(의도된 비용).
- 1차 때 하지 않은 F2·F4·F8·F10·F12 는 이름 변경이 main 에 들어간 뒤 2차로 했다(아래 6.1). **F7**(키 회전)은 범위가 커서 다음.
- Trusted Types(F11 첫 항목)·세션 쿠키 `__Host-` 접두는 하지 않았다 — vendor 호환 확인·운영 쿠키 이름 변경(기존 세션 끊김)이 필요.
