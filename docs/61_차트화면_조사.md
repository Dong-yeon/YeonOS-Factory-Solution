# 61. 차트 화면 조사 — 무엇을 그릴지 · 무엇으로 그릴지

> 작성 2026-11-02 · 상위 병합 세션 · 상태: **결정됨(10장) · hb.chart 구현(11장, 2026-11-03)**

> 관련: docs/10 H7 "차트·간트 라이브러리는 P3 전 별도 조사" — 그 조사가 이 문서다(지금까지 미실시)

## 1. 결론 먼저

- 지금 차트는 **두 군데뿐**이다.
  - QMS SPC 관리도: `spc.js` 가 SVG 를 손으로 그린다.
  - PMS 포트폴리오 연도·유형: `pms-home.js` 의 CSS 막대.
  - 나머지 KPI 는 숫자 카드(홈 23장)와 그리드뿐이다. 추세·비율·순위를 한눈에 보는 화면이 없다.
- 데이터는 이미 있다. 실적·불량·설비 상태 원장, NCR·COPQ, 재고·LOT·정위치 점검, 공수가 쌓여 있다.
  - 그래서 새 표 없이 **집계 SQL + 차트 화면**만으로 만들 수 있는 것이 대부분이다.
- 추천은 아래와 같다(사용자 결정 대기 — 8장).
  1. **그리는 도구 = 자체 `hb.chart`(SVG) 최소 세트.** 막대·누적 막대·선·파레토·게이지 정도면 된다. 근거는 다음과 같다.
     - CSP `style-src 'self'`(인라인 스타일 금지 + 가드 시험)를 지키기 쉽다.
     - SPC 가 이미 같은 방식이다.
     - 조회 그리드를 자체 `hb.grid` 로 만든 판단과도 같다.
     - 외부 라이브러리(Apache ECharts)는 PoC 후보로 남긴다.
  2. **첫 화면 3개**
     - 생산 현황판(계획 대비 실적·OEE 추세·비가동 파레토)
     - 품질 현황판(불량 파레토·PPM 추세·COPQ 추세)
     - 재고 현황판(재고 연령·정위치 정확도 추세)

## 2. 지금 상태 (코드 확인)

| 위치 | 그리는 방법 | 내용 |
|---|---|---|
| `qms/spc.js` | 손으로 만든 SVG(`createElementNS`) | X̄-R·I-MR 관리도, 관리한계·위반 점 |
| `pms/pms-home.js` | CSS 막대(`pms-chart-bar`) | 포트폴리오 연도·유형 건수 |
| 홈 카드 23장 | 숫자·보조 숫자·항목 목록 | 추세·비교 그림 없음 |

- vendor 에 차트 라이브러리가 없다.
  - 들어 있는 것: jquery·kendo-ui-core·lucide·pretendard·split.js·tabulator·tom-select·vanilla-calendar-pro
  - Kendo UI Core(Apache-2.0)에는 차트가 없다(docs/10 255행).
- CSP 는 `default-src 'self'; script-src 'self'; style-src 'self'` 이다(SecurityConfig).
  - 인라인 `<style>`·`style="…"` 속성은 막힌다.
  - JS 로 `element.style.x = …`(CSSOM)를 바꾸는 것은 CSP 대상이 아니다(MDN style-src).

## 3. 무엇을 그릴지 — 조사 요약

조사 출처 대부분은 MES·대시보드 벤더 글이다. 수치 기준(목표 %)은 참고만 하고, 구성 패턴만 가져온다. KPI 정의의 표준 근거는 **ISO 22400-2**(제조 운영 관리 KPI 34개 — OEE·처리율·스크랩율·MTBF·MTTR 등)다.

| 영역 | 여러 출처가 공통으로 꼽는 화면 구성 |
|---|---|
| 생산·설비 | OEE(가동률 × 성능 × 품질) 목표 대비 + 세 요소 분해 / **비가동 사유 파레토(상위 3~5개)** / 최근 7~14일(감독자 30일) 추세선 + 목표선 / 근무조·라인별 **계획 대비 실적** / 짧은 정지는 타임라인(간트)으로 |
| 품질 | **불량 파레토**(유형·라인·품목별) / FPY·불량률·PPM 추세 / 공급사 PPM(12개월 이동) / COPQ 추세 / SPC 상태·Cpk / CAPA 진행 깔때기 |
| 창고 | 재고 정확도(실사·점검) 추세 / **재고 연령 구간**(90일 이상 정체) / 입고 → 적치 시간(dock-to-stock) / 출하 정시·충족률 |
| 공통 원칙 | 지표 정의는 화면마다가 아니라 **한곳(집계 SQL)**에서 / 목표선이 있어야 색·경고가 의미 있음 / 빨갛게만 하지 말고 다음 행동(드릴다운 링크)을 / 부풀린 지표(OEE 과대)는 신뢰를 깎음 |

## 4. 우리 데이터로 만들 수 있는 후보

| # | 화면(제안 이름) | 차트 | 데이터(있음) | 새 표 | 규모 | 담당 |
|---|---|---|---|---|---|---|
| C1 | **생산 현황판** | 일별 계획 대비 실적(막대+선), 근무조·라인별 달성률, 비가동 사유 파레토, OEE 추세(가능 범위) | 작업지시·실적(V036·V090), 설비 상태 원장(V051) | 없음(집계) | 중 | MES |
| C2 | **품질 현황판** | 불량 유형 파레토(누적 % 선), 일·주 PPM 추세, COPQ 월 추세(내부·외부 누적 막대), NCR 열림·종결 추세 | NCR·불량 유형, COPQ(V221), 검사 판정 | 없음 | 중 | QMS |
| C3 | **재고 현황판** | 재고 연령 구간 누적 막대(0~30·31~90·91~180·180+), 정위치 정확도 추세, 상태별(가용·QC·보류·부적합) 구성 | inv_stock·LOT 입고일, 정위치 점검 | 없음 | 소~중 | WMS |
| C4 | 설비 보전 현황 | MTBF·MTTR 월 추세, 고장 사유 파레토, PM 준수율 | CMS 고장·보전 기록 | 없음 | 중 | CMS(세션 없음) |
| C5 | 공급사 품질 | 공급사별 PPM 12개월 추세, 순위 막대 | SRM 공급사 품질(#… PPM 화면 있음) | 없음 | 소 | SRM(세션 없음) |
| C6 | PMS 보강 | 기존 CSS 막대를 hb.chart 로, 공수 계획·확정 S-곡선, 사람 × 주 부하(결정 ⑦) | PMS 공수 | 없음 | 소~중 | PMS |
| C7 | SPC 이전 | 손 SVG 를 hb.chart 의 관리도로(동작 그대로) | 기존 | 없음 | 소 | QMS |

- **OEE 주의:** 성능률(실제 속도 ÷ 기준 속도)은 품목·공정 기준 사이클 타임이 있어야 정확하다. 라우팅 표준 시간이 공정별로 채워져 있는지 MES 가 먼저 확인한다. 없으면 C1 은 가동률·품질률·계획 달성률로 시작하고, "OEE"라고 부르지 않는다(부풀림 방지, 3장 공통 원칙).
- 현황판은 **홈 카드와 다르다.** 홈 카드는 숫자 + 링크이고, 현황판은 기간·공장을 고르는 별도 화면(`sys_prog`)이다. 사람별 숫자를 홈에 두지 않는 규칙(R9)은 그대로다.

## 5. 무엇으로 그릴지 — 도구 비교

| 안 | 라이선스·크기 | CSP(`style-src 'self'`) | 장점 | 단점 |
|---|---|---|---|---|
| **A. 자체 `hb.chart`(SVG)** | 우리 코드 | SVG 속성·class 만 쓰면 문제없음(SPC 와 같은 방식) | 의존성 0, 디자인 토큰·다크 테마·i18n·접근성(role=img·표 대체)을 우리 규칙대로. 가드 시험과 잘 맞음 | 종류를 늘릴 때마다 우리가 만든다. 확대·축소·대용량은 약함 |
| B. Apache ECharts | Apache-2.0, 약 150~170 KiB gzip(전체) | 과거 인라인 스타일 위반이 몇 번 고쳐졌다(SVG 렌더러 style 대입·툴팁 innerHTML, zrender #1030·echarts #19717). 지금 판의 엄격 CSP 완전 호환은 **미확인** → PoC 필요 | 종류가 많고(히트맵·간트형·게이지), 대용량에 강함 | 크기, CSP 확인 비용, 테마를 우리 토큰에 맞추는 일 |
| C. Chart.js | MIT, 약 45~58 KiB gzip | 반응형일 때 `<style>` 을 자동 주입해 막힌다 → 주입을 끄고 CSS 파일을 따로 싣는 우회(공식 안내) | 작고 익숙함 | 캔버스라 인쇄·접근성 대체를 따로 해야 함. 우회 유지 |
| D. uPlot | MIT, 약 22 KiB | 캔버스(추가 확인 필요) | 시계열에 아주 빠름 | 파레토·누적 막대 등은 직접 |

- 결론은 그대로다. 무료라도 외부 라이브러리는 크기·CSP·테마 맞추기 비용이 든다. 첫 5종(막대·누적·선·파레토·게이지)은 자체 `hb.chart` 로 만든다.

- 상용 Kendo 를 사는 경우(docs/10 11장 PoC 결정)에는 Kendo Chart 도 후보가 된다.

### 5.1 `hb.chart` 최소 계약(안)

- `hb.chart.bar(el, {categories, series:[{name, data, kind:'bar'|'line', axis:'left'|'right'}], target?, stacked?})`
- `hb.chart.pareto(el, {categories, values})` — 큰 순 정렬 + 누적 % 선 + 80% 선
- `hb.chart.gauge(el, {value, target, min, max})`
- 공통 규칙은 아래와 같다.
  - 색은 디자인 토큰 class 로, 인라인 style 은 쓰지 않는다.
  - `role="img"` + `aria-label` 요약을 두고, 아래에 접을 수 있는 수치 표(스크린 리더·인쇄)를 둔다.
  - 빈 데이터 상태를 표시하고, 툴팁은 `title`/SVG `<title>` 또는 CSS class 기반 겹침으로 한다.
  - 클릭하면 드릴다운 링크(`hb.open` 규약)로 간다.
  - 타입 계약은 `types/hb.d.ts`, 시험은 node 단위(좌표·정렬·누적 %) + 브라우저 1366·390 이다.
- 담당: 시스템관리(공통 플랫폼) — `hb.grid` 와 같은 자리.

## 11. 구현 — `hb.chart` Highcharts 정식판 (2026-11-03, 시스템관리)

> 10장 결정(도구 = Highcharts, CLAUDE.md 스택 절)을 반영했다. 2026-11-03 브랜치 정리로 사라진 첫 구현(docs/29 표)을 새 main 위에 다시 만든 것이다.
> 5.1 의 자체 SVG 안 계약을 그대로 이어받고, 안쪽만 Highcharts 로 그린다.

### 11.1 결론

- 화면은 **`hb.chart.pareto|bar|gauge|control(el, 옵션)` 만** 부른다. 모두 `Promise<ChartHandle>` 을 돌려준다.
  - Highcharts 전역과 파일 경로는 `hb.chart.js` 안에만 둔다.
  - 화면 JS·템플릿이 직접 쓰면 `ChartLibraryGuardTest` 가 실패한다. 상업 유료 라이브러리라 바꿀 수 있어야 하기 때문이다.
- Highcharts 파일은 **커밋하지 않는다.**
  - `node scripts/fetch-highcharts.mjs` 로 받는다. 버전 13.1.1 고정, npm tarball SHA-256 과 꺼낸 파일 6개의 SHA-256 을 확인한다.
  - 받는 곳은 `src/main/resources/static/vendor-local/highcharts/13.1.1/` 이고, 이 폴더는 .gitignore 에 있다.
  - `--check` 를 붙이면 받지 않고 대조만 한다.
- 템플릿은 `hb.js` 다음에 **`hb.chart.js` 하나만** 싣는다.
  - Highcharts 스크립트 4개(본체·more·solid-gauge·accessibility)와 CSS 2개(highcharts.css·hb.chart.css)는 처음 그릴 때 hb.chart 가 한 번만 싣는다.
- 파일이 없으면 화면은 깨지지 않는다. 그림 자리에 안내 문구(`js.chart.missing`)가 나오고, 수치 표가 펼쳐진다(`drawn=false`).
- 확인 화면은 `/dev/poc/chart` 다(local 프로필 전용, `ChartPocController`, 메뉴 없음, 가짜 데이터).

### 11.2 계약 (`types/hb.d.ts` → `HB.ChartApi`)

| 함수 | 꼭 줄 것 | 고를 것 | 그림 |
|---|---|---|---|
| `pareto(el, o)` | `categories`, `values` | `valueName`, `unit`, `threshold`(80), `top`(뒤는 "기타"), `onClick(category, 원래 index·기타 -1)` | 큰 순 막대 + 오른쪽 축 누적 % 선 + 기준선. 기준선 뒤 항목은 옅게 |
| `bar(el, o)` | `categories`, `series[{name, data, kind:'bar'\|'line', axis:'left'\|'right', tone:'muted'}]` | `target`(목표선), `stacked`, `horizontal`, `unit`·`rightUnit`, `onClick` | 막대·선 섞기. 계획은 `tone:'muted'`(옅은 회색), 실적이 기본색 |
| `gauge(el, o)` | `value` | `min`(0)·`max`(100), `target`, `higherIsBetter`(기본 true, 불량률은 false), `warnPct`(10), `unit` | 반원 게이지 + 목표 눈금. 색은 상태(충족·근접·벗어남), 범위 밖 값도 라벨은 실제 값 |
| `control(el, o)` | `labels`, `values`, `ucl`·`cl`·`lcl`(값 하나 또는 점마다) | `alarms`(서버 규칙 판정), `marked`(이벤트 기록 점), `tips`, `valueName` | 관리도. 한계는 계단선(`step:'center'`), 마지막 점에 UCL·CL·LCL 값, 위반 점은 ◆·크게·빨강 |

- 공통 옵션: `title`, `height`(px, 폭은 칸에 맞춤), `decimals`, `unit`, `summary`(낭독기 문장), `emptyText`.
- 보조 함수:
  - `hb.chart.paretoData(categories, values, {threshold, top})` — 화면 요약 문장(예: "상위 2개가 80%")에 쓴다.
  - `hb.chart.gaugeStatus(value, target, higherIsBetter, warnPct)`
  - `hb.chart.ready()` — 라이브러리가 있는지 알려 준다.
- 같은 `el` 에 다시 부르면 앞의 그림을 지우고 그린다. 먼저 부른 호출이 늦게 끝나면 버린다(조회 연타 대비).
- 빈 데이터: 파레토는 0 초과 값이 없을 때, 게이지는 값이 없을 때다. 이때 `js.chart.empty` 한 줄만 나온다.

### 11.3 쓰는 법 — 현황판(C1~C3)·SPC 이전(C7)

```html
<div id="defectPareto"></div>
...
<script th:src="@{/js/common/hb.js}"></script>
<script th:src="@{/js/common/hb.chart.js}"></script>
<script th:src="@{/js/views/qms/qms-dashboard.js}"></script>
```

```js
hb.latest('pareto', hb.api(API + '/defect-pareto?' + q)).then(function (r) {
    return hb.chart.pareto(document.getElementById('defectPareto'), {
        categories: r.data.map(function (x) { return x.defectNm; }),
        values: r.data.map(function (x) { return x.qty; }),
        valueName: hb.t('js.qmsDash.defectQty'), unit: hb.t('js.qmsDash.ea'), top: 8,
        onClick: function (name, i) { /* 드릴다운: hb.open 규약으로 NCR 목록 */ }
    });
});
```

- SPC(`qms/spc.js` 의 `draw(box, pts, val, ucl, cl, lcl, alarm, scale, marked)`)는 이렇게 옮긴다.
  - 계산 함수 인자를 점 배열로 바꿔 넘긴다: `labels: pts.map(p => String(p.index + 1))`, `values: pts.map(val)`, `ucl: pts.map(ucl)`, `cl: pts.map(cl)`, `lcl: pts.map(lcl)`, `alarms: pts.map(alarm)`, `marked: pts.map(marked)`, `tips: pts.map(p => …LOT…)`, `decimals: scale`.
  - 판정(WE 규칙)은 지금처럼 서버가 한다. hb.chart 는 alarms 를 받지 않을 때만 한계 밖(규칙 1)을 스스로 표시한다.
  - p 관리도도 같은 함수를 쓴다(R 관리도 칸만 비운다).
- 클릭 드릴다운 index 는 파레토라도 **원래 배열의 자리**다(정렬 뒤 자리가 아니다).

### 11.4 CSP·테마·인쇄·접근성

| 주제 | 처리 | 근거 |
|---|---|---|
| CSP `style-src 'self'` | **styled mode 만 쓴다.** styled mode 가 아니면 Highcharts 13 이 SVG `<defs>` 에 `<style class="highcharts-palette">` 를 넣어 막힌다. 13.1.1 소스 `Palette.injectCSS` 는 `!styledMode` 일 때만 불린다. 남은 동적 스타일은 CSSOM(`el.style.x=`)이라 CSP 대상이 아니다 | 확인 화면에서 CSP 위반 0건, SVG 안 `<style>` 0개(11.6) |
| 색·글꼴 | `tokens.css` 에 `--hb-chart-1~6·muted·grid·axis·ref·limit·center` 를 추가했다. `hb.chart.css` 가 `.hb-chart` 에서 `--highcharts-color-N`·neutral·highlight 변수를 이 토큰으로 다시 정한다. 옵션에는 color·style 을 넣지 않는다(node 시험이 막는다). 파랑은 동작 전용이라 계열에 쓰지 않는다 | DesignTokenGuardTest |
| OS 다크 모드 | highcharts.css 는 `color-scheme: light dark` + `light-dark()` 를 쓴다. 앱에 다크 테마가 없으므로 `.hb-chart` 에서 light 로 고정한다 | — |
| 글자 | Highcharts 는 라벨을 HTML 조각으로 해석한다. 그래서 항목·계열 이름, 제목, 단위, 툴팁은 `escapeText`(&<>)를 거친다. 서버 데이터의 `<img onerror>` 도 글자 그대로 보인다 | node 시험 + 확인 화면 |
| 인쇄 | Highcharts 가 SVG 에 `viewBox` 를 단다(없으면 hb.chart 가 넣는다). `@media print` 에서 컨테이너를 100% 로 줄인다 | 확인 화면 인쇄 미리보기 |
| 접근성 | 차트 아래 접는 **"표로 보기"**(textContent 표, caption)를 둔다. accessibility 모듈과 요약 문장(`accessibility.description`)도 넣는다. 색만으로 구분하지 않는다: 위반 점은 ◆·크기, 파레토 중요한 소수는 표와 기준선으로 알 수 있다 | — |
| 크레딧 | `credits.enabled=false` | Highcharts 가 공식 옵션으로 제공 |

### 11.5 라이선스 주의

- Highcharts 는 **비상업(개인·학습·포트폴리오) 무료**다(Highsoft EULA). **상업·납품·SaaS 는 유료**다. 이 저장소는 포트폴리오·학습 용도라 비상업이다.
- 납품·SaaS 로 가면 둘 중 하나다.
  - Highsoft 라이선스를 산다.
  - `hb.chart.js` 의 안쪽(`optionsOf`·`ready`·`mount`)만 다른 라이브러리로 바꾼다. 계약(11.2)과 화면은 그대로 둔다.
  - 무료 후보는 5.0 표의 Apache ECharts(Apache-2.0)다.
- 파일을 저장소·공개 데모 이미지에 넣지 않는다.
  - 공개 데모(deploy/demo)는 지금 이 파일을 받지 않는다. 그래서 데모 화면에서는 안내 + 표만 나온다.
  - 데모에도 그림을 보이려면 데모 빌드에서 스크립트를 돌린다. 공개 배포가 "비상업"에 드는지 확인한 뒤에 한다 — 후속.
