# 74. 모바일 웹앱 `/m` 설계 — 사무·관리자가 휴대폰으로 쓰는 화면 (2026-11-12)

> 사용자 결정(2026-11-12): 모바일 웹앱 `/m`(PWA)으로 만든다. 앞선 분석 = docs/45(4장 역할별 작업, 6장 A-1~A-3, 9장 M-3).
> 범위: 화면 6개. **새 업무 로직·새 표·새 `sys_prog` 없음**(마이그레이션 없음) — 기존 API·권한을 그대로 쓴다.
> 메뉴 구조는 바꾸지 않는다(메뉴 개편은 다른 세션). 현장 단말 `/pop`·창고 PDA `/pop/wh` 의 단말 인증과 섞지 않는다.

## 1. 결론

- `/m/**` 는 사무 화면과 **같은 보안 체인**(SecurityConfig @Order(2))을 그대로 탄다 — 로그인(회사코드 + 아이디), 세션, CSRF, 회사 범위(`TenantRequestFilter`), MFA·비밀번호 변경 강제, 협력사 경계(`PortalBoundaryFilter` — 협력사 사용자는 `/m` 에 못 온다)가 모두 같다.
- 화면은 셸(탭·iframe) 없이 **고정 화면 6개 + 아래 탭 줄**. 협력사 포털(`/portal`, docs/42)과 같은 방식 — 전용 페이지 컨트롤러 `platform.mobile.MobilePageController`.
- 화면 권한 = **사무 화면의 `progCd` 권한 그대로**. 모바일 화면이 부르는 API 는 전부 기존 API 라 판정은 그 API 의 `@ProgAuth`(또는 결재선·대상 화면 기준 서비스 판정)가 한다. 페이지 컨트롤러의 권한 확인(403)과 탭·단추 숨김은 편의다.
- 오프라인: 대기열 없음. 끊기면 위쪽에 "오프라인" 띠 + 저장 단추 끔(docs/45 A-3 "관리자 결재는 연결됐을 때만").

## 2. 화면·경로·API·권한

| # | 화면 | 경로 | 부르는 기존 API | 화면을 여는 권한(없으면 403) | 저장 권한 |
|---|---|---|---|---|---|
| 1 | 홈 | `/m` | `GET /api/home/cards`(오늘 확인할 것) · `GET /api/platform/approvals/box?box=TODO`(결재 대기 수) · `GET /api/platform/inbox/count`·`GET /api/platform/inbox?unread=true`(알림) | 회사 사용자면 누구나(허브) — 조각마다 `home-main`·`sys-approval`·`sys-inbox` SEARCH 가 있을 때만 보임 | — |
| 2 | 결재 승인 | `/m/approval` | `GET …/approvals/box` · `GET …/approvals/{id}` · `POST …/approvals/{id}/approve`·`/reject`(`X-Idempotency-Key`) | `sys-approval` SEARCH(개인 화면 — 회사 사용자 모두) | 결재선(현재 차례) — `ApprovalService` 판정, 남의 결재·다른 회사 = 404 |
| 3 | 찾기 | `/m/find` | LOT: `GET /api/production/lots/by-no` → `GET /api/production/lots/{id}`(상태·보류·바로 위아래 계보) / 설비: `GET /api/cms/state/plants` → `GET /api/cms/state?plantCd=`(오늘 타임라인에서 그 설비의 현재 구간) | `prd-lot` 또는 `cms-state` SEARCH 중 하나(가진 쪽만 보임) | — (읽기 전용) |
| 4 | 부적합 사진 등록 | `/m/ncr` | `GET /api/qms/ncrs/defects` · `GET /api/platform/codes?grp=QMS_NCR_SOURCE` · `POST /api/qms/ncrs`(`X-Idempotency-Key`) → `POST /api/platform/files`(targetType `qms-ncr`, targetId = 부적합 id) · `GET /api/qms/ncrs/{id}` | `qms-ncr` SAVE(등록 화면이라 조회 권한만으로는 열지 않는다) | `qms-ncr` SAVE (첨부도 대상 화면 SAVE — `FileService`) |
| 5 | 현황 조회 | `/m/status` | 작업지시: `GET /api/production/wos?from=오늘&to=오늘` · `GET /api/production/wos/{id}`(공정 진행) / 설비: `GET /api/cms/state/plants` → `GET /api/cms/state?plantCd=` | `prd-wo` 또는 `cms-state` SEARCH 중 하나 | — (읽기 전용) |
| 6 | 내 정보 | `/m/me` | `POST /api/platform/my-info/locale` · `POST /logout` | 회사 사용자면 누구나 | 언어 변경 = `sys-my-info` SAVE |

- "오늘" 은 서버가 준다(`BizClock.today()` → 화면 `data-today`). 화면 JS 가 기기 시계로 날짜를 만들지 않는다.
- 부적합 "초안" = 지금 NCR 의 첫 상태 `OPEN`(등록만, 처분·종결은 사무 화면). 회사 정책 `QMS_NCR_AUTO_HOLD` 가 켜져 있으면 등록과 함께 LOT 이 보류된다 — 화면이 등록 전에 알리고, 등록 뒤 결과(보류됨)를 보여 준다.
- 사진은 `<input type="file" accept="image/*" capture="environment">` — 기기 카메라 앱·사진첩을 OS 가 연다. 페이지가 카메라 스트림을 쓰지 않으므로 `Permissions-Policy: camera=()` 는 그대로다.
- 스캔: `hb.scan`(키보드 웨지·APK 스캐너 이벤트). 카메라 바코드 읽기는 범위 밖(docs/50 C5 미구현 그대로). 휴대폰에서는 주로 손 입력, 블루투스 스캐너를 물리면 스캔.

## 3. 정한 것 / 다른 안

| # | 정한 것 | 다른 안(안 한 이유) |
|---|---|---|
| M1 | **전용 페이지 컨트롤러**(`/m`, `/m/approval` …) — `sys_prog` 를 늘리지 않는다 | `sys_prog` 6개 + `/page/{progCd}`: 메뉴·권한 표·도움말(가드)·데모 계정 허용 목록이 다 늘고, 같은 일의 권한이 두 군데(사무 화면 / 모바일 화면)로 갈라진다 |
| M2 | 권한 = 사무 화면 `progCd` 그대로. 페이지 컨트롤러가 `PermissionService.actions(progCd)` 로 403 을 내고, 접속 로그(PAGE_VIEW·PERM_DENIED)는 그 사무 화면 코드 + 설명 `m` 으로 남긴다 | 모바일 전용 권한: 같은 사람이 PC 로는 되고 폰으로는 안 되는 이유를 설명할 수 없다. 기기 제한이 필요하면 접속 IP 정책·MFA 가 맡는다 |
| M3 | 모바일 **전용 API 를 만들지 않는다** — 화면 JS 가 기존 API 를 조합한다 | 모바일용 묶음 API: 응답 한 번이 편하지만 권한·회사 범위 판정이 한 곳 더 생긴다(가드·시험 대상 증가) |
| M4 | 로그인 뒤 이동: 로그인 전에 열려던 주소가 `/m` 아래였을 때만 **고정 주소 `/m`** 으로 보낸다(그 밖은 지금처럼 `/main`). 저장된 주소 자체로는 돌아가지 않는다 | 저장된 요청으로 복귀: API 주소·외부 주소로 튕기는 것을 막으려던 기존 결정(SecurityConfig 주석)을 깬다 / 늘 `/main`: 폰에서 로그인할 때마다 PC 셸이 뜬다 |
| M5 | PWA: `/m/manifest.webmanifest`(start_url `/m`, 로그인 전 공개 — 앱 이름·아이콘뿐). 서비스 워커는 기존 `/sw.js`(정적 자원만 캐시, HTML·API 는 가로채지 않음) 그대로 | manifest 하나로: 설치한 앱이 PC 셸(`/main`)로 열린다 |
| M6 | CSS 는 `m.css` 하나(의미 토큰만, `@media` 없음 — 360px 기준 한 단, 넓은 화면은 가운데 최대 폭). 누를 곳 높이 44px 이상(WCAG 2.5.5 권장 크기), 목록은 카드 | 사무 화면을 반응형으로: 결재함은 이미 됐지만(docs/45 N1) 그리드·상세 폼 화면은 휴대폰 폭에서 입력이 어렵다 |
| M7 | 결재 처리: 내 차례인 건만 승인·반려 단추, 반려는 사유 필수(서버 `apr.reject.commentRequired`, 화면도 먼저 확인). 누른 순간 만든 `X-Idempotency-Key` — 같은 누름의 재전송은 409, 이미 처리된 결재를 다시 누르면 서버가 거부(결재 차례 아님). 전자서명이 필요한 문서는 `hb.esign` 그대로 | 목록에서 바로 승인(밀기): 문서를 안 보고 승인하게 된다 |
| M8 | 부적합 등록은 두 걸음: ① NCR 등록(멱등 키) ② 사진을 한 장씩 올리기. ①이 끝나면 폼을 잠가 **같은 NCR 을 두 번 만들지 않고**, 사진만 실패하면 실패한 사진만 다시 올린다 | 한 요청(multipart)으로: 새 API·새 트랜잭션 경계가 필요하다(M3). 사진 올리기는 원래 따로 커밋되는 구조(FileService) |
| M9 | 설비 "현재 상태" = 오늘 타임라인(`cms-state`)의 그 설비 마지막 구간. 오늘 구간이 없으면 "오늘 기록 없음" | 설비 카드(`cms-equip-card`) 요약: 보전 이력 요약이라 "지금 도는가"가 없다 |

## 4. 보안·이상 사용에서 볼 것

- 비로그인 `/m/**` → `/login`(302), 로그인 뒤 `/m`. 협력사 사용자 → `/portal`(기존 경계 필터).
- 화면 권한 없음 → 403. **단추를 숨겨도 막은 것이 아니다** — 권한 없는 계정으로 그 화면이 쓰는 API 를 직접 불러 403 인지 시험한다(`/api/qms/ncrs` POST, 첨부 올리기, `/api/production/lots/by-no`, `/api/cms/state`, `/api/production/wos`, `/api/home/cards`, 언어 변경).
- A사 계정으로 B사: 결재 상세·승인·반려 = 404, B사 LOT 번호로 NCR 등록 = 400(LOT 없음), B사 NCR 상세 = 404, B사 NCR id 로 사진을 올려도 B사에서 보이지 않음(회사 범위).
- 같은 승인 두 번: 같은 멱등 키 = 409 `DUPLICATE_REQUEST`, 새 키로 다시 = 거부(이미 처리됨) — 결재 이력에 승인 한 줄만.
- CSP: 인라인 스크립트·스타일 없음. 서버 글자는 `textContent` 로만. 주소(쿼리)에 스캔 값·업무 값을 싣지 않는다(LOT 번호 조회는 기존 API 가 쿼리로 받는 것만 예외 — 기존 화면과 같음).
