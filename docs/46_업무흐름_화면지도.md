## 1. 결론 먼저 — 큰 흐름 9개

공장 하나가 돌아가는 순서로 읽는다. 화살표 하나 = **다음 화면이 앞 화면의 결과(표 행·상태)를 받아 쓴다**. 굵은 글자는 화면 이름, 괄호는 화면 코드(progCd).

### F0 기준정보 준비 — 모든 흐름의 바닥

**공장**(mst-plant) → **장비 계층·창고**(mst-equip-hier) → **설비·자산**(mst-equip·mst-asset) → **품목**(mst-item) → **BOM**(mst-bom) · **공정 → 라우팅**(mst-proc → mst-routing) → **특성·불량 유형**(mst-char·mst-defect) → **근무조·작업 달력·자격·작업자**(mst-shift·mst-work-cal·mst-qual·mst-worker) → **POP 단말 등록**(sys-terminal).
- BOM·라우팅은 [확정]한 리비전만 쓰이고, 작업지시를 **발행할 때** 지시 안으로 복사된다(`J/production/WoService.java:304-342`). 그 뒤 기준정보를 바꿔도 이미 발행한 지시는 그대로다.
- 정책 `PLM_ECO_REQUIRED`=Y 면 BOM·라우팅 [확정]은 막히고 설계변경(F5) ECO 적용으로만 확정된다.
- 회사 운영(F8): 회사 정보 → 부서·사용자 → 권한그룹 → 메뉴 → 정책·코드·채번.

### F1 수주 → 생산 → 출하 (중심 흐름)

```
수주 관리(sal-order) ─▶ 작업지시 관리(prd-wo) 만들기 PLANNED ─▶ 생산계획(aps-plan) 계산·반영 ─▶ 작업지시 [발행] RELEASED
   │ (고객 내시 sal-forecast 는 지금 아무도 읽지 않음)                                        │
   ▼                                                                                          ▼
POP(/pop) 배지 로그인 → 착수 → 실적 확정 + 자재 LOT 투입(산출 LOT 생성) → 파라미터 → 종료(READY)
   ▼
작업지시 관리: 공정 완료판정 DONE → 지시 완료 DONE ─▶ 생산 입고(prd-receipt) = 재고 원장 RCV_PRD
   ▼
재고 현황(wms-stock) ─▶ (출하검사 qms-insp, 공장 스위치) ─▶ 출하(wms-ship) 지시 → 피킹 → 팔레트 → [출하 확정] = 수주 행 출하 수량
   ▼
ERP: 정책 ERP_SYSTEM 에 따라 자동 송신(아웃박스) 또는 ERP 업로드 엑셀(prd-erp-export)
```
- **APS 는 지시를 만들지 않는다** — 이미 있는 PLANNED·RELEASED·진행 중 지시의 시작일·설비만 계산해 반영한다. 그래서 실제 순서는 수주 → 지시 만들기 → APS → 발행이다.
- POP 의 [종료]는 공정을 끝내지 않는다(READY 로 돌아감). 공정 완료는 사무실의 작업지시 화면 "완료판정"에서.
- 실적 확인(prd-result)·LOT 추적(prd-lot → prd-lot-report)·설비 상태(cms-state)는 읽기 화면이다. 실적 정정은 POP 에서 역분개로만.

### F2 구매요청 → 입고 → 수입검사 (워크스루 W1 이 자세한 판)

**협력사 정보**(srm-supplier) → **구매요청**(srm-pr) 승인 → **발주**(srm-po) 작성·결재·[발행] → **통지**(srm-notify)·**발주서 출력**(srm-po-print) → **납기 회신**(srm-ack, 협력사는 포털) → **독촉 대상**(srm-po-status) → **ASN**(srm-asn, 협력사는 포털) → **입고**(wms-rcv: SRM 게이트가 발주 행 받은 수량을 올리고, MES 가 내부 LOT 을 만들고, 재고 원장 RCV_PO) → **수입검사**(qms-insp, QC → 가용/차단) → **발주 마감**(srm-po, 자동 마감 없음) → **평가 기준·협력사 평가**(srm-eval-tmpl·srm-eval, OTD 는 입고 이력에서).
- 정책 `SRM_PO_SOURCE=ERP` 면 발주는 ERP 에서 받아 오고(결재 없음) OTD 계산에서 빠진다.

### F3 부적합 → 봉쇄 → 시정조치 (→ 협력사)

**검사 실행**(qms-insp)·**SPC**(qms-spc)·현장 → **부적합 NCR**(qms-ncr, 정책 `QMS_NCR_AUTO_HOLD` 면 LOT 자동 보류 — MES `LotHoldPort`) → **봉쇄**(qms-contain) → 처분(특채·폐기·재작업 → 재고 상태 풀림/폐기) → **시정조치 CAPA**(qms-capa) → 협력사 책임이면 **반품 지시**(srm-return) → **반품 출고**(wms-rtn-issue) · **클레임**(srm-claim, 협력사 포털 회신).
- QMS 가 건 보류는 MES LOT 화면(prd-lot)에서 풀 수 없다 — 근거별 해제.

### F4 설비 — 고장과 예방

- 고장: **고장 신고**(cms-breakdown, POP·알람 자동 신고도) REQ → **보전 작업지시**(cms-mwo) 접수 OPEN → 착수 WIP → 작업·예비품 기록 → 완료 DONE(예비품 WMS 출고 — 정책 `WMS_MRO_LINK`) → 확인 CLOSED.
- 예방: **점검표**(cms-chk-tmpl) → **예방보전 계획**(cms-pm-plan) → 매시 예정 생성 → **점검 실행**(cms-chk-run) 또는 PM 작업지시 → NG 면 후속 작업지시.
- 상태·성과: 설비 상태(cms-state) → **비가동 사유 검토**(cms-state-review) → **설비 KPI**(cms-kpi), 알람 이력(cms-alarm), 설비 이력 카드(cms-equip-card), 사용량 카운터(cms-counter·cms-equip-count).
- 대장: 설비 보안 대장(cms-equip-sec), 위험성평가(cms-risk → 결재함).

### F5 설계변경

**설계 변경 요청 ECR**(plm-ecr) 접수 → **ECO**(plm-eco) 대상 작성(BOM 일괄 대체 mst-bom-replace 등) → **4M 변경**(qms-change, ECO 1:1) → 상신·결재(sys-approval) → 고객 승인·PCN → [적용] = BOM·라우팅 리비전 확정 → 새 LOT 에 변경 표시(MES `ChangeMarker`) → **초품·셋업 확인**(qms-setup)·출하 때 미승인 변경 차단(wms-ship).

### F6 신제품 개발(APQP·PPAP)

**프로젝트 템플릿**(pms-template) → **프로젝트**(pms-project) → 작업·**작업 일지**(pms-worklog) → **산출물**(pms-deliverable)·**이슈**(pms-issue) → **게이트 심사**(pms-gate) → **AP 규칙표**(apqp-ap) → **DFMEA**(apqp-dfmea, 확정 BOM 1~2단계로 구조 시작 — 설계 쪽) → **PFMEA**(apqp-fmea) → **관리계획서**(apqp-cp) → **검사계획**(qms-insp-plan, 사람이 맞춰 만든다 — 관리계획서는 확인만) → **PPAP**(plm-eco 의 PPAP 구역 — ECO 하나에 PPAP 하나라서 신규 품목도 "신규 도입" ECO 가 필요) → **포트폴리오**(pms-home).

### F8 시스템 운영

### 11.2 그룹별 원문 메모

각 그룹 분석의 E 절 그대로(번호는 그룹 안 번호).


1. **휴일 달력 문구와 코드 어긋남** — 기존 `help.mst-work-cal` 은 "계획·점검 주기·일정 지연 계산이 이 달력을 읽고" 라고 하지만, `WorkCalendar` 를 쓰는 곳은 APS(`J/aps/ApsService.java:112`, `ShiftCalendar.java:27`)와 PMS(`J/pms/PmsDays.java:25` 외)뿐이다. CMS 예방점검 쪽에는 `WorkCalendar`·`mst_work_cal`·휴일 참조가 없다(grep 0건). C 부 helpWhy 는 코드에 맞춰 "생산계획과 프로젝트 일정" 만 적었다. 기존 문구 수정 여부는 정책 질의.
2. **금형 문구가 옛 단계 기준** — `help.mst-asset.lifeShots` "실적이 생기면(P2) 누적 타수와 비교" 인데, 지금은 CMS 사용량 카운터가 설치 이력으로 자동 누적한다(`M/cms/CmsCounterAutoMapper.xml:30`). 낡은 표현(기존 문구라 건드리지 않음).
3. **코드 매핑(`if_code_map`)을 읽는 곳이 없다** — 외부 시스템 화면의 [매핑 추가] 로 넣은 단위·품목 유형·창고 매핑은 master 밖에서 쓰는 mapper·java 가 없다(데모 시드·감사 보기만). ERP 업로드·출하 ERP 는 `mst_ext_id_map`(품목 외부 품번)만 쓴다(`M/production/ErpMapper.xml:7-13`, `M/wms/ShipErpMapper.xml:7`). 흐름이 끊긴 곳(엑셀 올리기·ERP 수신 때 쓸 예정으로 추정).
4. **용어 동의어도 소비처 없음** — `mst_term_alias` 를 읽는 모듈이 없다. 기존 help 가 "나중에" 라고 밝히고 있으니 의도된 상태.
5. **ERP_ITEM_SYNC_MODE=PULL 이면 품목을 만들 길이 없다(추정)** — PULL 이면 품목 신규가 `ERP_OWNED` 로 거부되는데(`J/master/item/ItemService.java:154-156`, 엑셀 올리기도 `ItemImportTemplate.java:100,151`), ERP 에서 품목을 당겨 오는 동기화 코드는 저장소에 없다(`ERP_ITEM_SYNC_MODE` 참조는 ItemService·ItemImportTemplate·Policies·HbErrorCode 뿐). docs/22 1장은 "품목 신규도 ERP 동기화로만". 정책을 PULL 로 켜면 F0-4 가 막힌다 — 정책 질의 또는 범위 밖.
6. **sys_prog 권한과 화면 버튼이 안 맞는 곳** — `mst-plant`·`mst-equip-hier` 는 actions 에 DELETE 가 있으나 삭제·사용 중지 버튼도 DELETE 권한 API 도 없다(사용 여부는 저장으로 바뀜, `J/master/equip/EquipApiController.java:64-111`). `mst-bom`·`mst-routing` 의 DELETE 는 [폐기](OBSOLETE) 에 매여 있다. 권한그룹에서 "삭제" 를 줘도 의미가 없는 화면이 있다는 기록.
7. **행 단위 버튼 다수가 `actions.contains('SAVE')` 로 숨겨지지 않음** — 행 추가·행 저장(BOM), 단계 추가·단계 저장(라우팅), 담당자·환산·속성·외부 품번(거래처·품목), 매핑 추가, 공정 추가, 동의어 추가, 새 품목 클래스·클래스 저장, 설치(금형), 배지·PIN·자격 추가(작업자), 클래스 관리·속성 저장(설비), 사용 중지(휴일 달력). 서버는 `@ProgAuth SAVE` 로 막으므로 보안 문제는 아니지만, 조회 권한만 있는 사용자에게 버튼이 보이고 누르면 403. 고칠 것(화면 일관성) 후보.
8. **저레벨 코드(LLC) API 소비처 없음** — `BomChangeService.llc()/llcOf()`(`J/master/bom/BomChangeService.java:311,323`)를 부르는 곳은 컨트롤러뿐. APS·MRP 가 쓰지 않는다(MRP 미구현으로 추정).
9. **master 화면끼리·다른 모듈로 가는 링크가 전혀 없다** — `static/js/views/master/*.js`·`templates/master/*.html` 에 `/page/` 링크 0건. 예: BOM 확정 뒤 전개 조회, 역전개 결과에서 일괄 대체, 라우팅에서 공정·장비 계층으로 가는 길이 메뉴뿐이다. D 부 JSON 으로 도움말 모달에 앞·뒤 링크를 붙이면 이 빈 곳이 메워진다.
10. **설계변경과 기준정보 확정의 이중 경로** — 기본(PLM_ECO_REQUIRED=N)은 BOM·라우팅 화면 [확정] 과 ECO 적용 둘 다 가능, Y 면 화면 [확정] 은 409 `PLM_ECO_REQUIRED`(`J/master/EcoReleaseGate.java:31-37`, DB 트리거 V069). 사용자는 정책 상태를 화면에서 알 수 없다(버튼은 APPROVE 권한만 본다). helpDo 에 "ECO 필수 정책이 켜진 회사는…" 을 넣어 두었다.
11. **작업지시 스냅샷 시점** — 스냅샷은 지시 "생성" 이 아니라 "발행" 때 만들어진다(`J/production/WoService.java:304-342`). docs/20 1장 파라미터 설명은 "작업지시 생성 때 단계와 함께 스냅샷" 이라고 적혀 있어 표현이 어긋난다(코드가 맞다고 보고 도움말은 "발행" 으로 씀). 생성~발행 사이에 라우팅이 새 리비전으로 바뀌면 발행 때 STALE_REV 로 막히고 지시를 다시 골라야 한다(`WoService.java:552-557`).
12. **확정 시작일 규칙의 사용자 영향** — BOM·라우팅 모두 확정 때 시작일 ≥ 오늘이라, 오늘 생산 중인 지시에 쓰인 리비전을 즉시 바꾸는 길은 없다(의도: "그때 BOM" 보존). 현장 질문이 나올 수 있는 지점이라 docs/46 에 "왜" 로 남길 만하다.

1. **F1 순서가 처음 가정과 다르다.** APS 는 지시를 만들지 않고 `PLANNED·RELEASED·IN_PROGRESS` 지시만 계산한다(M/aps/ApsMapper.xml:23, docs/38 1장 "지시 표는 건드리지 않는다"). 실제 순서 = 수주 → 지시 만들기(PLANNED) → APS 계산·반영 → 발행 → POP. docs/46 그림은 이 순서로 그려야 한다. docs/38 서문은 "A6 간이 생산계획(계획 행 → 지시 일괄 발행)" 이 생기면 그 앞을 채운다고만 적었고, 그 기능은 없다.
2. **수주 → 지시가 자동 연결되지 않는다.** 수주 화면에 "지시 만들기" 버튼이 없고, 지시 쪽에서 수주 행을 골라야 한다(`prd_wo.order_line_id`, 선택 칸). 수주 행 연결 없이 만든 지시도 정상이라, 수주별 생산 진척을 볼 화면이 없다.
3. **내시(sal-forecast)는 막다른 길.** `sal_forecast_*` 를 읽는 곳은 영업 화면·데모 시더뿐(grep: ForecastService·SalesMapper·DemoDataSeeder). APS·지시·구매 어디에도 안 들어간다. 문구에 "생산 계획에 자동으로 들어가지 않습니다" 로 적었다 — 앞으로 MRP·APS 가 읽게 되면 이 문구를 바꿔야 한다.
4. **POP 종료 ≠ 공정 완료.** POP [종료]는 READY 로 돌려놓을 뿐이고, DONE 은 사무 prd-wo [완료판정]만(J/pop/PopWorkService.java:161, docs/25 4.9 "POP 에서 완료판정 하지 않음"). 작업자는 "끝냈는데 지시가 안 끝난다" 고 느낄 수 있다 — POP 화면 쪽 안내 문구 후보.
5. **자재 LOT 입구가 둘.** prd-lot [자재 LOT 등록](간이, D2)과 WMS 자재 입고(wms-rcv). prd-lot 간이 등록이 재고 원장에 들어가는지는 코드로 확인 못 함(추정: LotStockPosting 이 자재 입고 src 만 재고 LOT 으로 봄 — J/wms/inv/LotStockMapper.java:35 주석 "자재 입고 src_id = LOT, 생산 입고 prd_receipt.lot_id … 아니면 재공(WIP)"). 간이 등록 LOT 을 POP 에서 투입하면 재고 차감이 어떻게 되는지 WMS 그룹과 맞춰 볼 것.
6. **POP 투입 → 재고 차감은 기본 꺼짐.** 공장 정책 `WMS_STOCK_LINK` 기본 N 이면 CONSUME 계보가 재고 원장에 안 간다(J/wms/link/LotStockLink.java 주석). 반면 생산 입고 → 재고(RCV_PRD)는 정책 없이 항상 붙는다(ProductionReceiptPosting). 기본 설정에서 "입고는 늘고 자재 투입은 안 줄어든다" 가 정상 동작 — 문서화 필요.
7. **ERP 경로가 정책 하나로 갈린다.** `ERP_SYSTEM` 이 어댑터(FAKE 등)이면 지시 완료·입고 때 아웃박스 자동 송신, EXCEL/NONE 이면 prd-erp-export 수동. 두 경로를 같이 쓰면 중복이 날 수 있는데 엑셀 쪽은 겹친 기간을 경고만 한다(J/production/erp/ErpPublisher.java:18-20, ErpExportService.java:111). 화면 도움말에 정책 이름은 넣지 않고 "ERP 연동이 켜져 있으면" 으로만 썼다.
8. **지시 완료와 입고 순서.** 입고는 IN_PROGRESS·DONE 모두 허용(J/production/ReceiptService.java:211), 마감(CLOSED)만 막는다. 그래서 "완료판정 → 지시 완료 → 입고 → 마감" 과 "입고 → 완료 → 마감" 둘 다 된다. ERP 실적 송신은 지시 완료 때 한 번 — 완료 뒤 입고한 수량은 입고 송신으로만 간다. A 부는 앞 순서로 적었다.
9. **수주 행 자동 완료는 출하에서만.** 생산 입고는 수주 행에 아무것도 남기지 않는다. 수주 행 DONE 은 WMS 출하 확정의 `OrderShipGate` 뿐(J/sales/SalesOrderShipGate.java:82-92).
10. **cms-state·cms-equip-count 는 module_cd PRD 지만 패키지는 cms.** sys_prog 의 module_cd(PRD)와 코드 위치(module/cms, templates/cms)가 다르다 — 메뉴 위치를 볼 때 헷갈림. 이상은 아님(설계 의도 추정: MES 6단계에서 만든 화면).
11. **prd-receipt 의 [입고] 폼·[정정]은 SAVE 권한일 때만**(T/production/receipt-mgt.html:57 th:if, JS CAN_SAVE). sys-terminal·cms-equip-count·prd-lot 의 위험 버튼도 같은 규칙 — 어긋난 곳 없음.
12. 기존 `help.prd-lot` 문구에 "창고 재고는 P4" 라는 옛 단계 표현이 남아 있다(P4 WMS 는 이미 붙음). 기존 문구는 고치지 않는다는 규칙대로 두었다.

1. **수불 원장 역분개가 다른 모듈 출처 행을 막지 않는다 (추정 — 코드 읽기 기준, 시험 안 함)**. 화면 역분개가 막는 출처는 `QMS_INSP`·`QMS_NCR` 뿐이다(wms/inv/InventoryService.java:221, js/trx.js:86). 그래서 SHIP(출처 SHIP_PICK)·피킹 MOVE 짝·RCV_PRD(PRD_RECEIPT)·ISSUE_WO(LOT_GEN)·ISSUE_MRO(CMS_PART) 행을 사람이 되돌릴 수 있다. 되돌릴 때 원래 모듈 쪽은 바뀌지 않는다: 출하 머리 SHIPPED·수주 shipped_qty·ERP 전표 그대로, 생산 입고·투입 계보 그대로. 원장 쪽 연동은 발주(PoReceiptGate)·반품(ReturnShipGate)만 있다(:262-275). **조용히 틀리는 경우** — 출하라면 `ShipQuery.shippedByLine` 대사로만 드러난다. 고칠 것 / 정책 질의 후보: 출처가 있는 행은 QMS 처럼 막고 "원래 화면에서 취소"로 안내.
2. `help.wms-move.itemCd`(messages.properties:3339) "LOT 관리 품목은 아직 이 화면에서 받지 않습니다" 가 낡았다. 지금은 LOT 을 받는다 — `help.wms-move.lotNo`(:6343)와 wms/inv/StockService.java:203, :237. 같은 화면 도움말 둘이 서로 다른 말을 한다.
3. `wmsRtn.save` en = "Confirm shipment" — 출하 화면 `wmsShip.confirm` 과 같은 말이다. ko 는 "출고 확정". en 은 "Confirm issue" 쪽이 맞아 보인다. C 의 en 문구는 지금 화면에 보이는 대로 "Confirm shipment" 를 썼다(문구를 고치면 같이 고칠 것).
4. 화면끼리 링크가 하나도 없다 — templates/wms·js/views/wms 에 `/page/` 이동이 없다. 홈 카드(`wms-count-open`·`wms-ship-open`·`wms-reconcile`)만 들어오는 길이다. D 의 앞·뒤 JSON 이 처음 생기는 연결이다.
5. PDA 창고(/pop/wh)에 **입고가 없다** — 이동·실사·피킹·반품만 있다(tpl/pda-home.html). 이유는 `LotService.receive` 가 로그인 사용자만 받기 때문(docs/44 1장). 현장 입고는 사무 화면 wms-rcv 로만 할 수 있다.
6. 실사 [확정] 버튼은 SAVE 권한이면 보인다. 그런데 한도를 넘는 줄이 있으면 서버가 APPROVE 를 요구한다(wms/count/CountService.java:415-418). 사용자는 누른 뒤 오류를 보고서야 안다(화면에서 미리 알려 주는지는 확인 안 함 — 추정). helpNote 에 적어 두었다.

5. **pms-gate 결정 경로**: 정책 PMS_GATE_APPROVAL=N 이면 [상신] 이 곧 결정이고 APPROVE 권한이 필요하다(J/pms/GateService.java:276-279). 같은 버튼 이름이 정책에 따라 다른 결과 — 버튼 이름 "상신" 이 N 정책에서는 오해 소지.
6. **APQP 화면 module_cd**: sys_prog 에서 apqp-fmea·apqp-ap·apqp-cp 의 module_cd 가 `PMS` 다(별도 APQP 모듈 코드 없음). 코드 패키지는 `module/apqp`. 메뉴·권한 묶음에서 PMS 로 보인다는 점만 기록.
7. **ECO 결재가 두 곳**: plm-eco 화면의 [승인] 은 전자서명 토큰을 넘기는 경로이고 공통 결재함(sys-approval)에서도 같은 결재를 처리한다(J/plm/EcoService.java:286-298). 정책 PLM_ESIGN_REQUIRED 이면 서명 필요.
8. **ECO 대상 리비전 준비**: ECO 는 작성 중 BOM·라우팅 리비전만 대상으로 받는다. 즉 mst-bom/mst-routing 의 [새 리비전] 이 ECO 앞 단계다(docs/39 4장). 정책 PLM_ECO_REQUIRED=Y 회사는 BOM·라우팅 화면에서 직접 확정할 수 없다(EcoReleaseGate, J/plm/EcoService.java:78).

1. **도움말 버튼이 없는 화면 3개** — `sys-my-info`·`sys-support`·`sys-usage` 템플릿에 `#hbHelpBtn`·`aside#hbHelp` 가 없다(hb.page.js:7 은 이게 있어야 동작). `my-info.html` 은 `body[data-prog]` 도 없다(T/platform/my-info.html:4). C 부 문구를 넣어도 모달이 안 뜬다 — 템플릿 머리를 다른 화면처럼 맞추는 작업이 따로 필요. → **이번에 붙였다(10장).**
2. **결재함 [문서 열기]가 APQP 2종만** — `ApprovalDocType.progCd()` 를 채운 것은 `CpApprovalDocType`·`FmeaApprovalDocType` 뿐. 발주·NCR·CAPA·관리문서·위험성평가·게이트·ECO 7종은 결재함에서 업무 화면으로 못 간다(버튼 숨김, J/platform/approval-box.js:155). 결재자가 문서 내용을 보려면 메뉴로 직접 찾아가야 한다 — 흐름이 끊긴 곳. C 부 helpDo 의 [문서 열기] 문장은 "열 수 있는 문서만" 이라는 단서 없이 썼으니 반영 전에 판단 필요.

5. **업데이트로 생긴 새 화면은 메뉴에 자동으로 안 들어감** — 기본 메뉴는 회사 생성 때 그 시점 `sys_prog` 를 복사할 뿐(P/ops/OpsConsoleService.java:126). 권한(관리자 그룹 admin_yn)은 D2 로 해결됐지만 메뉴는 같은 문제가 남아 있다. 관리자가 [화면 추가] 를 해야 함 — 업데이트 안내(릴리스 노트)에 "새 화면 메뉴 추가" 를 넣어야 할 것.
6. **위임 목록의 문서 유형 칸이 코드 그대로** — 선택지는 이름(`t.name`)인데 위임 표는 `docTypeLabel` 이 코드(예: QMS_NCR)를 그대로 보여 준다(J/platform/approval-box.js:242-244). 표시만의 문제.
7. **ECO 는 정책 없이 항상 결재** — 다른 8종은 정책으로 켜고 끄는데 `PLM_ECO` 만 상신이 유일 경로(M/plm/EcoService.java:717). 설계 의도(추정)지만 결재함 도움말·정책 화면에서 이 차이를 안내할 곳이 없다.

9. **POP 정정 승인은 결재함 밖** — POP 실적·파라미터 정정 승인(M/pop/PopWorkService.java:84-85)은 결재 엔진을 쓰지 않는다. 사용자가 "결재" 라는 말로 혼동할 수 있어 docs/46 에서 구분해 적을 것.

## 12. 업무 흐름 지도 화면 (home-flow-map, 2026-10-26)

계기(사용자): "업무흐름도도 화면으로 보여 주면 좋겠다." → 앱 안 화면 하나. 1장의 흐름 9개 중 하나를 고르면 화면 상자와 화살표로 그리고, 상자를 누르면 그 화면 탭이 열린다.

### 12.1 데이터 — 원본 하나

| 무엇 | 원본 | 왜 |
|---|---|---|
| 화살표(A → B) | `static/js/common/help-flow.json` 의 앞·뒤 화면 — **A.next 에 B 가 있거나 B.prev 에 A 가 있으면** 화살표 하나 | 도움말 대화상자(10장)와 같은 원본. 앞·뒤를 고치면 지도와 대화상자가 함께 바뀐다(어긋날 수 없음) |
| 흐름 소속·단계 | 새 파일 `static/js/common/flow-map.json` — 흐름마다 **단계 목록**(단계 = 화면 코드 배열) | help-flow.json 에는 "어느 흐름의 몇째 단계"가 없다. 그 파일에 칸을 더하면 화면 119개 항목을 모두 고치고 대화상자 가드 형식이 바뀐다 → 소속·순서만 따로 두고 **화살표는 넣지 않는다**(화살표 원본은 여전히 하나) |
| 화면 이름·열 수 있는지 | API `GET /api/home/flow-map/screens` — 사용 중 화면 전부의 번역된 이름 + 조회 권한(`canOpen`) | 권한 없는 화면도 회색으로 이름이 보여야 한다(내 메뉴에는 없는 화면). 판정은 서버(메뉴와 같은 `findSearchableProgs`) |
| 상자 한 줄 설명 | `help.{progCd}` 첫 문장 | 도움말 문구 그대로 |
| 흐름 이름·설명 | i18n `flowMap.f0`~`f8`(+ `.desc`) — 템플릿 `<option>` | 1장 제목 |

`flow-map.json` 모양: `{"F1": {"steps": [["sal-forecast"], ["sal-order"], ["prd-wo"], …]}}`. 한 흐름 안에서 화면은 한 번만, 흐름 사이에는 겹쳐도 된다(qms-insp 는 F1·F2·F3). 화살표 중 흐름 밖 화면을 가리키는 것은 그 흐름 지도에서 빠진다(대화상자에는 그대로). 가드(`ScreenHelpGuardTest`): 흐름 9개 F0~F8, 모든 코드가 실제 화면, 흐름 안 중복 없음.

### 12.2 배치 — 기본은 자동(층 = 단계), 사용자가 끌어서 바꾼다

- **기본 자리 = 층 = 단계**, 같은 단계는 위 → 아래(데이터 순서). 흐름 파일에 좌표는 없다 — 화면 이름·언어가 바뀌어도 손댈 곳이 없게.
- **한눈에(2026-10-26 사용자 피드백 "뭔가 한눈에 보이면 좋겠는데" — 1부 판은 F1 에서 상자 3개만 보이고 나머지는 가로 스크롤 밖)**: 상자를 이름 + 화면 코드만으로 줄이고(148×48 — 설명은 오른쪽 요약에), **뱀(ㄹ자) 배치** — 단계를 한 줄에 k 개씩 놓고 다음 줄은 오른쪽 → 왼쪽으로 되돌아온다(줄 끝 단계의 다음 단계가 바로 아래라 선이 짧다). k 는 1 ~ 단계 수 중 지금 그림판(창 아래까지 채운 높이)에 **가장 큰 배율로 들어가는 값**(`hbFlowMap.layout`, 같으면 줄이 적은 쪽). 그래도 넘치면 판 전체를 **화면에 맞춤** 배율로 줄이고(`fitScale`, 최소 35%) [−] [맞춤 n%] [+] 로 바꾼다(10% 씩, 최대 150%). 시험이 9개 흐름 모두 1366×768 그림판(약 1020×410)에 75% 이상, 1920 그림판(약 1600×800)에 100% 로 들어감을 확인한다(실측: 1366×641 에서 F1 100%·F4 87%, 스크롤 없음).
- **끌어서 옮기기**(2026-10-26 사용자 피드백 "내가 움직이면서 해 보는 게 낫겠다"): 상자를 마우스·펜으로 끌거나(4px 넘게 움직이면 끌기, 아니면 클릭), 키보드는 방향키 16px(Shift 64px). 선은 따라 움직인다.
- 자리는 **이 기기 localStorage**(흐름마다 `hb.flowMap.v2.pos.F1` — v2 = 작은 상자·뱀 배치, 옛 v1 자리는 쓰지 않음, 저장 자리가 있으면 창 폭이 바뀌어도 다시 배치하지 않고 배율만 맞춤, 읽을 때 이 흐름 화면·0~20000 숫자만 받음) + [자리 초기화]. 화면 설정 저장 `sys_grid_state` 는 서버가 열 설정 모양(cols·sort·pageSize)만 남기도록 다시 만드는 구조라, 자리 저장을 넣으려면 플랫폼 공통 서비스를 고쳐야 한다 → 셸 메뉴 접힘과 같은 기기 단위 보기 설정으로 둔다(다른 PC 에서는 처음 자리).
- 화살표 종류(순수 함수 `hbFlowMap.model`):

| 종류 | 조건 | 기본 보기 |
|---|---|---|
| 다음(next) | 다음 단계로 | **보임**(주 흐름) |
| 아래(down) | 같은 단계, 위 상자 → 아래 상자 | **보임**(주 흐름) |
| 건너뜀(skip) | 두 단계 이상 앞으로 | 숨김 — [보일 선]에서 켜거나 상자를 고를 때 |
| 되돌아감(back) | 앞 단계로, 또는 같은 단계 아래 → 위 | 숨김(점선) — 같음 |

- 처음 판(모든 화살표 + 위·아래 띠로 우회)은 F1 에서 띠에 5~6줄이 엉켜 "선이 너무 복잡하다"(사용자, 8090 확인) → 기본 보기를 주 흐름만으로 줄였다. 흐름 9개 모두 주 흐름만으로 단계가 끊기지 않게 단계를 맞췄다(시험이 확인 — F1 출하검사는 재고와 같은 단계, F5 결재는 ECO 앞 단계). 기본 선 수는 화살표 전부의 약 절반(F1 13/23, F4 14/29).
- 선 = 두 상자 사이 **짧은 직각 연결**(`hbFlowMap.route`): 옆에 있으면 오른쪽 면 → 왼쪽 면(가운데에서 꺾음), 끌어서 위아래로 겹치면 아래 면 → 위 면.

### 12.3 그리기·조작 — 자체 SVG + 진짜 버튼

- 라이브러리 없음. 상자 = HTML `<button>`(키보드·스크린리더가 그대로), 선 = 상자 뒤 SVG 한 장(`aria-hidden`). SVG 는 `createElementNS` + 속성만. 상자 자리는 CSSOM 사용자 속성 `--fm-x`·`--fm-y`(판 크기 `--fm-w`·`--fm-h`, 배율 `--fm-scale` → `transform: scale`, 그림판 높이 `--fm-avail-h`)를 CSS 가 쓴다 — 끌기 거리는 배율로 나눠 판 좌표로 — 인라인 `style` 속성·HTML 문자열 없음(CSP), 좁은 폭 CSS 는 이 값을 무시한다. 색은 `tokens.css` 의미 토큰만.
- **클릭(Enter·Space) = 고르기**: 그 상자의 들어오고 나가는 선을 종류와 상관없이 진하게(나머지는 옅게) + **요약 패널**(이름·코드·[화면 열기]·무엇을·왜·언제·주요 동작 = 도움말 문구, 이 흐름의 앞·다음 화면 버튼). 요약의 앞·다음 버튼은 그 상자를 고른다.
- **요약 = 그림판 아래 띠**(가로 전부, 높이 = 창 아래까지 남는 높이의 34%·170~280px, [요약 접기]로 머리 줄만). 2026-10-26 두 번 고쳤다: ① 처음 판은 요약이 오른쪽 300px 를 늘 차지("왼쪽 영역을 좀 더 키울 수 없을까") → ② 고를 때만 그림판 위에 겹쳐 펼침 → 8090 에서 "요약 패널이 상자를 가린다·아래가 비어 있다"(내시 수신을 고르면 오른쪽 열 상자를, LOT 추적을 고르면 수주 관리를 덮음) → ③ 지금 판: 띠 높이는 고르기와 상관없이 같아서 상자를 골라도 그림판 크기·배율이 바뀌지 않고(재배치 없음) 상자를 가리지 않는다. 그림판 높이 = 창 아래까지 − 띠 높이로 맞춤 배율을 계산하므로 아래 빈 공간도 띠가 쓴다. 띠 머리 = 이름·코드·[화면 열기]·[고르기 해제]·[요약 접기/펼치기](접어도 머리의 [화면 열기]는 그대로), 몸 = 무엇을·왜 | 언제 | 주요 동작 | 앞·다음 화면을 가로 칸으로(넘치면 띠 안에서만 스크롤). 접기·펼치기는 사용자가 누를 때만 그림판을 다시 맞추고, 상태는 이 기기에 기억. Esc = 고르기 해제(고른 상자로 포커스 복귀), 키보드로 고르면 요약 제목으로 포커스.
- **탭 열기는 요약의 [화면 열기] 버튼으로만**: 셸 안이면 `window.top.hbShell.open(progCd, 이름)`(이미 열렸으면 그 탭), 셸 밖이면 `/page/{progCd}`. 더블클릭·Enter 로 열던 것은 뺐다(2026-10-26 사용자 "더블클릭으로 탭 여는 것은 없애자. 실수로 여는 경우가 많아"). 권한 없는 화면은 버튼 비활성 + "권한 없음".
- 권한 없음 = 회색 점선 + "권한 없음" 배지, 고를 수는 있고 열기는 안내만(열어도 서버가 403). 셸에 열린 탭은 "열린 탭" 표시.
- 흐름 고르기 = `<select>`(9개 — 6~15개 결정표, docs/16 I5), 주소 `?q.flow=F3` 로 바로 열 수 있다. [보일 선] 켜고 끄기도 이 기기에 기억.

### 12.4 좁은 폭·접근성

- 작업 영역 900px 미만(page.css 구간과 같음)이면 **세로 목록**: 단계 제목("1단계") 아래 상자들, 상자마다 "다음: …" 글, 선·자리·끌기 없음, 요약 띠는 목록 아래(높이 자동, 고르면 보이게 내림). 넓을 때도 단계 제목과 "다음: …" 은 스크린리더용으로 남는다(`hb-fm-sr`).
- 단계 = `<section>` + 제목, 상자 = 토글 버튼(`aria-pressed` = 고름), `aria-describedby` = "다음: 화면 이름, …"(흐름 안 나가는 화살표 전부). 요약은 `aria-live`. Enter·Space = 고르기, 방향키 = 옮기기, 요약에서 Esc = 접기. Tab 순서 = 단계 순서(옮겨도 그대로).
