# 20. P1 5단계 — 공정·라우팅·파라미터 세트·표준 사이클타임 설계

사용자 지시: "5단계 라우팅 진행해"(2026-10-19). 레퍼런스 재분석은 요청받지 않았으므로 BOM(docs/18)에서 정한 리비전 규칙을 그대로 쓰고, 라우팅에만 있는 판단은 [추정] 으로 표시한다.

## 1. 결론 먼저

- **공정 마스터 `mst_proc`** = 재사용하는 작업 단위(ISA-95 Process Segment 축소): 코드·이름·공정 분류·외주 여부. 공장·설비와 무관 — "무엇을 하는가"만.
- **라우팅 머리 `mst_routing`** = **품목 × 공장 × 대체 번호 × 리비전**. 상태·적용 기간·불변·자동 마감은 BOM 과 같다(docs/18 B2·B3). BOM 과 달리 **공장이 키에 들어간다** — 작업장(라인·셀)이 공장 소속이고, 같은 품목을 두 공장에서 다른 공정으로 만든다(SAP 라우팅도 공장별)[추정 — 일반 ERP 관행].
- **공정 단계 `mst_routing_step`** = 공정 순번(10, 20, …) × 공정 × 작업장(LINE·CELL, 같은 공장) × **표준 사이클타임(초/사이클) · 사이클당 수량(캐비티) · 준비 시간(분)**. OEE 성능 분모 = 사이클타임 ÷ 사이클당 수량(이상적 1개 시간).
- **파라미터 세트 `mst_routing_param`** = 단계마다 온도·압력·전류 같은 숫자 설정값의 **목표·하한·상한**. 작업지시 생성 때 단계와 함께 스냅샷(P2) — ISA-88 Master Recipe → Control Recipe 를 이산 공정에 맞게 줄인 것(docs/02).
- 단계·파라미터는 **작성 중(DRAFT) 라우팅에서만** 바뀐다(트리거). 저장은 "라우팅 한 벌" 단위 — 머리 버전 하나로 동시 편집을 막는다.
- 진행: 한 번에 5단계(공정 관리 화면 + 라우팅 관리 화면). 엑셀 올리기·비교·다른 품목 복사는 하지 않는다(5장).

## 2. 확정(RELEASED) 조건

| 조건 | 오류 | 근거 |
|---|---|---|
| 단계 1개 이상 | `steps` NO_STEPS | |
| 품목 사용 중 | `itemCd` INACTIVE | BOM 과 같음 |
| 단계의 공정 사용 중 | 단계 `procCd` INACTIVE | 사용 중지 = 새 참조 금지(docs/17 2장) |
| 자체 공정은 작업장 필수, 작업장은 사용 중 | `nodeId` REQUIRED / INACTIVE | 외주 공정은 작업장 없음(협력사) |
| 자체 공정은 사이클타임 필수(> 0) | `stdCtSec` REQUIRED | docs/17 5단계 "사이클타임 > 0". 0 이하는 저장부터 거부(CHECK) |
| 시작일 ≥ 오늘(회사 시간대) | `validFrom` PAST | BOM 과 같음 — 이미 생산한 "그때 라우팅" 을 바꾸지 않게 |
| 같은 품목·공장·대체의 이전 확정본 | 새 시작일 전에 시작했으면 종료일 자동 마감, 같은 날 이후면 `ROUTING_PERIOD_OVERLAP` | BOM 과 같음 |

파라미터는 저장 때 검사로 충분(하한 ≤ 목표 ≤ 상한, 셋 중 하나 이상) — 확정 때 다시 보지 않는다.

## 3. 데이터 모델 (V022)

```text
mst_proc            proc_id, comp_cd, proc_cd(^[A-Z0-9][A-Z0-9_-]{0,19}$, 회사 안 유일), proc_nm, proc_cat(코드 PROC_CAT),
                    outsrc_yn, sort_no, use_yn, remark, row_ver, 감사
                    ※ 품목의 PROC_TYPE(자체·구매·외주 = 조달 구분)과 다른 것 — 이름이 겹치지 않게 PROC_CAT
mst_routing         routing_id, comp_cd, item_id, plant_cd, alt_no(1~99), rev, status, valid_from, valid_to,
                    change_no, change_reason, remark, released_at/by, row_ver, 감사
                    unique(comp, item, plant, alt, rev), 작성 중은 (comp, item, plant, alt) 하나,
                    EXCLUDE (comp =, item =, plant =, alt =, daterange &&) WHERE RELEASED
mst_routing_step    step_id, comp_cd, routing_id, op_seq(1~9999, 라우팅 안 유일·DEFERRABLE), proc_id, node_id(NULL 가능),
                    std_ct_sec numeric(12,3) NULL 또는 > 0, units_per_cycle int 1~999 기본 1, setup_min numeric(8,2) ≥ 0,
                    remark, row_ver, 감사
mst_routing_param   param_id, comp_cd, step_id, param_cd(^[A-Z0-9_]{1,30}$, 단계 안 유일), param_nm, unit_nm(공학 단위 글자 20자 — kA·ms·°C 는 재고 단위 코드 UNIT 에 없다),
                    target_val·lsl·usl numeric(18,6) NULL 가능(하나 이상, lsl ≤ target ≤ usl), sort_no, row_ver, 감사
```

트리거(직접 SQL 포함 최종 판정):
- 머리: 삭제 금지, 품목·공장·대체 번호 불변(상태 무관 — QA 3a #1 교훈), 상태 이동 DRAFT→RELEASED·OBSOLETE, RELEASED→OBSOLETE, 확정·폐기본 내용 불변(종료일 앞당기기·폐기만), 품목 같은 회사.
- 단계: 머리가 DRAFT 일 때만 추가·수정·삭제, 다른 라우팅으로 이동 금지, 공정 같은 회사, 작업장은 같은 회사·**머리와 같은 공장**·LINE/CELL.
- 파라미터: 단계의 머리가 DRAFT 일 때만, 다른 단계로 이동 금지.
- 장비 계층: **확정 라우팅이 쓰는 작업장은 사용 중지 거부**(`ck_mst_equip_hier_routing_use`) — 4b 의 "설비가 걸린 노드" 와 같은 규칙. 폐기된 라우팅은 막지 않는다.
- 새 공정·작업장 참조만 사용 중 검사(이미 들어 있는 단계는 확정 검사가 본다 — BOM 행과 같은 규칙).

## 4. 화면·API

| 화면 | 구성 |
|---|---|
| **공정 관리** `mst-proc` | 목록 + 상세(코드·이름·분류·외주·순서·사용). 공장 관리와 같은 단순 화면 |
| **라우팅 관리** `mst-routing` | BOM 관리와 같은 구조: 목록(품목·공장·리비전·상태·기간·단계 수·총 사이클타임) + 상세(머리 폼) + **단계 목록**(순번·공정·작업장·사이클타임·캐비티·준비 시간, 단계마다 "파라미터" 펼침 → 파라미터 행). 확정·폐기·새 리비전. **BOM 연결 점검**: 같은 품목의 지금 유효한 확정 BOM(대체 1) 행 중 공정 순번이 이 라우팅에 없는 행을 안내(저장·확정을 막지는 않음 — P2 작업지시가 첫 공정 투입으로 처리) |

API(`/api/master/routings`): 목록·열·엑셀·상세·생성·머리 수정·**구조 저장**(`PUT /{id}/steps?rowVer=` 단계 + 파라미터 전체 목록 → 서버가 id 기준으로 추가·수정·삭제 차이 계산)·확정(APPROVE)·폐기(DELETE)·새 리비전(SAVE, 단계·파라미터 복사)·찾기(품목·공정·작업장).

구조 저장을 "한 벌" 로 하는 이유: 라우팅 단계는 수~수십 개라 전체를 보내도 작고, 파라미터가 단계에 매달려 있어 행 단위 일괄 저장(created/updated/deleted 세 목록 × 2단)보다 화면·서버 모두 단순하다. 동시 편집은 머리 `row_ver` 하나로 막는다(BOM 행 저장도 머리를 touch 한다).

## 5. 하지 않을 것

| 제외 | 이유 |
|---|---|
| 엑셀 올리기·라우팅 비교·다른 품목 복사·일괄 대체 | BOM 에서 만든 엔진·패턴을 그대로 쓸 수 있으나 요청 범위 밖 — 이관 고객이 생기면 BOM 템플릿처럼 추가 |
| 문자형 파라미터(용접 프로그램 번호 등) | 숫자 목표·범위만. 문자 설정값은 비고. 특성·검사 항목과의 연결은 6단계 특성 마스터에서 다시 본다 |
| 병렬·대체 공정 순서(네트워크 라우팅) | 순번 순서 한 줄. 같은 품목의 다른 흐름은 대체 번호(alt_no)로 [추정 — 자동차 부품 이산 공정은 직렬이 대부분] |
| 단계별 필요 설비 클래스·자격·도구 | 작업장까지만. 자격 게이트는 P2(`mst_proc_qual_req`), 금형은 4b 설치 이력 |
| 외주 공정 리드타임·단가 | SRM(P4) |
| 작업지시 스냅샷 | P2 — 이 테이블들은 "마스터 레시피" 이고, 지시는 사본을 가진다 |

## 6. 검토 결과

2026-10-19 사용자: "5단계 라우팅 진행해" — 1장 결론으로 진행. 바꿀 점이 생기면 이 절에 날짜와 함께 적는다.

구현 중 바꾼 것 (2026-10-20):
- 파라미터 단위를 UNIT 코드 → **공학 단위 글자**(`unit_nm` 20자). UNIT 은 재고 수량 단위(EA·KG·ROLL)라 kA·ms·kN·°C 가 없고, 넣으면 재고 단위 선택지가 오염된다. 측정값 원장(P2 `prd_param_actual`)은 이 글자를 스냅샷한다.
- 공정 관리 화면은 엑셀 내보내기 없음(수십 건, 표 화면) — 권한 액션 SEARCH·SAVE.
- 오류 문구 `valid.INACTIVE` 를 "사용 중지된 항목입니다" 로 범용화(공정·작업장·노드 부모·설비 설치에서 "품목" 으로 읽히던 문제), 장비 계층 노드 사용 중지가 설비·확정 라우팅에 걸리면 칸 오류(`NODE_HAS_EQUIP`·`HAS_ROUTING`).
- 남은 것: 작업지시 스냅샷(P2)·문자형 파라미터·라우팅 엑셀 올리기/비교(요청 시). 4단계 QA 세션(`claude/equip-4-qa`) 결과는 따로 병합.

QA 5 수정(2026-10-20, docs/qa/bom-routing-3b-5.md):
- 새 참조 규칙을 "같은 품목·공장·대체의 다른 리비전이 이미 쓰는 공정·작업장은 사용 중지여도 들일 수 있다" 로 완화(V028).
  확정 라우팅의 공정을 사용 중지하면 새 리비전(단계 INSERT 복사)이 막혀 단종 공정을 바꾸는 개정판을 만들 수 없었다.
  사용 중지 참조가 남은 작성 중은 확정 검사가 그 단계에 알린다(BOM 의 사용 중지 자품목과 같은 흐름). 처음 들이는 사용 중지 참조는 종전대로 거부.
