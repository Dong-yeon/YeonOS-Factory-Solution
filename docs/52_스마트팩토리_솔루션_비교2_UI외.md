## 0. 요약

### 0.1 한 줄 결론

**업무 기능의 폭과 "데이터를 믿을 수 있게 남기는 규약"은 시장 상위 제품과 견줄 만하다. 반면 그것을 운영 환경에서 증명하는 층은 비어 있다.** 비어 있는 것은 네 가지다.

- 관측성: 지표·추적
- 규모 실측: 원장 1년치 기준
- 외부 표준 계약: OpenAPI·웹훅·ISA-95 매핑
- 사무 사용자 SSO

시장 제품은 이것들을 "엔터프라이즈 준비도"로 내세운다. 사례는 다음과 같다.

- Plex: 단일 인스턴스 멀티테넌트, 하루 80억 건 이상 처리
- SAP DM: 분기 릴리스, 품질 환경을 2주 먼저 올림
- Tulip: Part 11·SOC 2
- CM V12: 기준정보 변경 패키지 배포

YeonOS 는 격리·원장·전자서명·백업 복원 시험처럼 더 어려운 부분은 이미 만들었다. 그래서 남은 일은 **작고 설명하기 쉬운 것들**이다.

### 0.3 면접용 3줄

- 멀티테넌트 격리를 **DB 가 강제하고 기동할 때 검사한다**. RLS FORCE, 카탈로그 가드, 앱 계정이 소유자가 아님을 확인한다. Plex 는 "단일 인스턴스 멀티테넌트"라고만 공개하는데, YeonOS 는 격리 방식을 시험 코드로 보여 줄 수 있다.
- 원장은 **두 시각(`occurred_at`·`recorded_at`)·입력 방식·역분개 전용**이다. 트리거가 UPDATE/DELETE 를 막는다. 그래서 ALCOA+ 의 "원본·동시성·지속성"을 설정이 아니라 **스키마로** 보장한다(Y1).
- 백업은 pgBackRest + 복원 시험 스크립트로 하고, 관리자 화면이 **마지막 복원 시험일**까지 보인다. 업그레이드는 마이그레이션 전용 실행 + jar·스키마 버전 일치 가드다. 시장 제품이 계약서에만 적는 운영 약속을 코드로 남겼다.

## 4. 시장 흐름 4가지와 YeonOS 의 자리

1. **"엔터프라이즈 준비도"가 경쟁 요소가 됐다.** SAP 는 분기 릴리스 + 품질 환경 선행[A1][A2], Opcenter X 는 QA 환경 3개와 다운그레이드[S2], Tulip 은 LTS + 검증 문서[T2]를 내세운다. 기능보다 **"고객이 업그레이드를 믿고 할 수 있나"를 판다.** YeonOS 는 이미 `ProdStartupGuard`·마이그레이션 분리·복원 시험이 있다. 그래서 **Y6(업그레이드 리허설)** 하나로 이 이야기를 완성할 수 있다.
2. **표준 데이터 모델이 AI 의 전제가 됐다.** CM V12 는 AI 에이전트 발표에서 "Canonical Data Model" 을 맨 앞에 뒀다[CM2]. HighByte·UNS 는 ISA-95 계층을 토픽으로 쓴다[H1]. YeonOS 의 모델은 ISA-95 와 맞지만 **대응표가 없다** → **Y7**. 나중에 MCP(28 R7)를 열 때 도구 이름·스키마의 근거로도 쓴다.
3. **규제 검증은 "공급사 증빙 + 위험 기반"으로 바뀌었다.** FDA CSA 최종 지침(2025-09)은 공급사 증빙을 쓰고 시나리오 시험을 허용한다 (요약)[F1]. 1인 제품이 내놓을 수 있는 가장 강한 증빙은 **자동 시험과 대응표**다 → **Y1**. 자동차 부품(IATF)이 1차 업종이라 Part 11 의무는 없다. 하지만 2차 업종(반도체 부품)과 의료기기 협력사로 넓힐 때 같은 표를 쓴다.
4. **구성·기준정보를 패키지로 옮긴다.** CM V12 Global Data Orchestrator[CM2], Opcenter X Template Store[S2]가 그 사례다. 28 R10 과 같은 방향이다. 다시 제안하지 않지만, **우선순위를 "하"에서 "중"으로 올릴 근거**가 생겼다(Q8).

- **주의(시험으로 확인할 것)**:
  1. 파티션 자식도 각각 `ENABLE/FORCE RLS` + 정책이 필요하다(부모를 거치지 않는 직접 접근 대비). `TenantCatalogInspector` 는 부모(`relkind 'p'`)와 자식(`'r'`)을 둘 다 보므로 빠지면 기동이 막힌다 — 원하는 동작이다.

- **설계 판단**: 27 S2·28 X6 는 "TimescaleDB 대신 PG 파티션 + BRIN 까지"라는 **상한**만 정했다. 언제 할지는 정하지 않았다. 재지 않고 파티션부터 하면 FK·RLS·트리거 복잡도만 늘 수 있다. 실측 결과 자체가 포트폴리오 근거다("1년치 2,000만 행에서 SPC 조회 p95 n ms").

- POP·PDA(단말 활성화)와 협력사 포털은 바꾸지 않는다.
- **설계 판단**: 중견 공장의 IT 담당이 가장 먼저 묻는 것이 "AD 계정으로 되나요"다(추정이지만 일반적 요구). 퇴사자 계정 회수를 IdP 한 곳에서 할 수 있다는 것 자체가 보안 기능이다(05 의 "관리 권한 탈취" 경로 축소).
