### 1.1 `module_cd` 바로잡기 (V9990, 임시 번호)

메뉴 자리(docs/75)와 `module_cd` 가 어긋난 화면 7개 — 모듈을 끄면 **메뉴 폴더와 다른 기준으로 사라지게** 된다. `module_cd` 는 지금 권한그룹·메뉴 관리 화면의 묶음 표시에만 쓰이므로(코드 grep) 바꿔도 다른 동작은 그대로다.

| 화면 | 지금 | 바꿈 | 근거 |
|---|---|---|---|
| `apqp-fmea`·`apqp-dfmea`·`apqp-cp`·`apqp-ap` | PMS | QMS | 메뉴는 품질 > 개발 품질(docs/75 D8), 코드도 QMS 문서·검사계획에 기댐(`apqp → qms` import 13) |
| `cms-state`·`cms-equip-count` | PRD | CMS | 메뉴는 설비 > 상태·모니터링(docs/75 D9) — P2 6단계 때 생산 쪽에서 만들어진 흔적 |
| `sys-terminal` | PRD | SYS | POP·PDA 단말을 같이 등록 — 생산을 꺼도 창고 단말(PDA)은 등록할 수 있어야 한다 |

## 2. 모듈 사이 의존 — 코드에서 찾은 것

`module/*` 패키지 사이 import 를 세고(2026-11-16), 화면이 **다른 모듈이 만든 데이터 없이 성립하지 않는** 것만 "필수"로 했다. 나머지 import 는 대부분 선택 연계(`link.*` 포트 — 상대가 없으면 빈 값)라 "함께 쓰면 좋음" 안내만 한다.

| 켜려는 모듈 | 필수(저장 거부) | 근거(코드) | 함께 쓰면 좋음(안내만) |
|---|---|---|---|
| 모든 업무 모듈 | MST | 품목·공장·공정·거래처를 모두 `mst_*` 로 참조 | — |
| QMS | PRD, WMS | 검사·NCR·추적이 LOT 기준(`LotLookup`·`LotHoldPort`·`LotTraceQuery`), 출하 전 검수·재고 품질 상태가 창고 출하·재고에 기댐(`ShipConfirmCheck`·`ShipQuery`·`QualityStockLink`) | PLM(변경점 ECO 계약 ①~④) |
| APS | SAL, PRD | 수요 = 수주·내시(`OrderLineQuery`·`ForecastQuery`), 계획 결과 = 작업지시 생성(`WoService`) | SRM(MRP → 구매 요청 `PrService`) |
| SRM | WMS | 납품·입고가 창고 입고(`MaterialReceiptService`), 반품 출고(`ReturnShipGate` 반대편) | QMS(협력사 품질 NCR) |
| PLM | QMS | ECO 가 QMS 변경점·관리문서를 직접 만든다(`ChangeService`·`DocService`) | SAL(수주 영향) |
| PRD | — | | SAL(수주 연결), WMS(생산 입고 `ProductionReceiptPosting`) |
| WMS | — | | SRM(발주 입고 `PoReceiptGate`), QMS(수입검사) |
| CMS | — | | PRD(현장 단말 고장 신고·점검) |
| PMS | — | | QMS(CAPA 요청·문서), PLM(PPAP) |

- **저장 규칙**: 켜진 모듈 집합 S 에 대해 "S 안의 모듈이 필수로 요구하는 모듈 ⊂ S" 가 아니면 400 `MODULE_DEPENDENCY`(빠진 짝을 이름으로 알려 줌). 자동으로 함께 켜지 않는다 — 화면이 "QMS 를 켜려면 생산·창고도 켜야 합니다"를 보여 주고 사용자가 고른다(몰래 켜지면 조용히 다른 값 저장).
- 반대 방향(끄기)도 같은 규칙: PRD 를 끄려는데 QMS 가 켜져 있으면 거부.

## 3. 회사 설정 저장 — 회사별 테이블 `sys_comp_module`

| 안 | 판단 |
|---|---|
| **A. 회사별 테이블 `sys_comp_module(comp_cd, module_cd, use_yn)` — 채택** | 권한 판정 SQL 한 곳(`AuthMapper.findActions`·`findSearchableProgs`·`findHomeProg`)에 `not exists` 한 줄로 붙는다 → 메뉴·화면·API·홈·모바일이 같은 판정을 쓴다. RLS 로 회사 격리, `tg_audit` 로 누가 언제 껐는지 남음, 2장 의존 검사는 한 트랜잭션에서 집합으로. |
| B. 회사 정책(`PolicyService`) | 정책은 "공장 값 → 회사 값 → 기본값" 키 하나씩이다. 모듈은 회사 전체 단위(공장별 켜기는 뜻이 없음)이고, 모듈 9개 = 정책 9개를 서로 엮어 검사해야 해서 키 단위 검증(`sys_policy_def`)과 맞지 않는다. 권한 SQL 에서 읽으려면 정책 표를 조인해야 해 오히려 복잡. |

- **행이 없으면 켜짐** — 기존 회사는 데이터 옮기기 없이 그대로 다 켜짐(동작 변화 없음). 저장하면 모든 모듈 행을 Y/N 으로 적는다(설정한 회사 = 행이 있음).
- `SYS` 는 행을 둘 수 없다(CHECK). 코드 형식 CHECK `^[A-Z]{2,10}$`, 목록 밖 코드는 서비스가 400.
- 기존 데이터는 지우지 않는다 — 끄기 = 숨김. 다시 켜면 그대로(시험).

## 4. 막는 위치

| 곳 | 어떻게 | 화면 수만큼 고치나 |
|---|---|---|
| 권한 판정 | `AuthMapper.xml` 공통 조각 `moduleOn`(꺼진 모듈의 프로그램 제외)을 `findActions`·`findSearchableProgs`·`findHomeProg` 에 | 아니오 — SQL 3곳 |
| 사무 API | `ProgAuthAspect` 가 권한이 없을 때 그 프로그램 모듈이 꺼졌는지 보고 403 `MODULE_DISABLED`(그 밖은 그대로 `NO_PERMISSION`) | 아니오 — 한 곳 |
| `/page/{progCd}` | `PageController` 같은 판정 → 403 화면(`error/page-forbidden`, 문구 "이 회사에서 쓰지 않는 모듈") | 인터셉터 한 곳 + 화면 2개 |
| 메뉴 | `MenuService` 가 `findSearchableProgs` 결과로 이미 거른다 → 빈 폴더 자동 숨김. `DefaultMenuTree` 는 바꾸지 않는다(트리 한 벌 그대로, 보이는 것만 줄어듦) | 0 |
| 모바일 웹앱 `/m` | `PermissionService` 를 그대로 쓰므로 자동(탭·조각 숨김) | 0 |
| 현장 단말 POP·PDA | 단말은 사람 권한(`@ProgAuth`)을 안 탄다 → `ModuleGateInterceptor`(`/api/pop/**`, 단말 인증 뒤) 가 경로로 모듈을 정해 꺼졌으면 403 `MODULE_DISABLED`. 단말 화면 `/pop`(POP = PRD)·`/pop/wh`(WMS)는 그 컨트롤러가 안내 화면(403). 고장 신고·설비 점검·검사 단추는 세션·공정 응답 깃발로 숨김. 경로: `/pop/wh`·`/api/pop/wh/**` = WMS, `/api/pop/breakdown/**`·`/api/pop/pm/**` = CMS, `/api/pop/procs/*/insp/**` = QMS, 그 밖 POP 실적 경로(`PopSecurityConfig.POP_PATHS`) = PRD. 활성화·세션·배지·언어는 공통(막지 않음) | 인터셉터 한 곳 + 화면 2개 |
| 첨부 | `FileService` 가 대상 화면 권한(`PermissionService`)을 쓰므로 자동 | 0 |

막지 않는 것(그대로 둠, 이유): 외부 수집 API `/ext/v1/**`(설비 이벤트 — API 키, 꺼진 동안의 데이터도 다시 켰을 때 있어야 함), 아웃박스·스케줄러(이미 쌓인 일은 끝까지), 다른 모듈이 읽는 선택 연계 포트(필수 의존이 아니면 빈 값과 같음).

관리자 그룹(`admin_yn = Y`)도 꺼진 모듈은 못 본다 — 판정 SQL 이 관리자 분기 밖에서 모듈을 거르므로.

## 5. 관리 화면

- **사용 모듈 `sys-module`**(시스템 > 운영 설정, SEARCH·SAVE): 모듈 표(이름·사용 스위치·화면 수·필수 짝·함께 쓰면 좋음). 스위치를 바꾸면 화면이 2장 규칙으로 미리 검사해 빠진 짝을 안내, 저장은 서버가 다시 검사. `rowVer` 대신 회사 단위 advisory 잠금(동시 저장은 차례로, 마지막이 이김 — 둘 다 검사를 통과한 온전한 집합) + 요청 키 멱등(`claimRequestKey`). 저장 뒤 셸 메뉴 다시 읽기 안내.
- **운영 콘솔 새 회사**: 만들기 폼에 모듈 체크 목록(기본 전부 켬) → 같은 검사 후 `sys_comp_module` 행.
- **기본값**: 기존 회사 = 전부 켜짐(행 없음). 개발·데모 시드(`DevCompanySeed.ensureModules`, 회사에 행이 하나도 없을 때만) = MST·PRD·QMS·WMS·CMS·SRM 켬, SAL·APS·PMS·PLM 끔(6장 사용자 결정).
