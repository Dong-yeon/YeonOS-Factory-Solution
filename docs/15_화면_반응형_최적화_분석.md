## 0. 요약

### 0.1 한 줄 결론

지금 화면은 **"1920×1080 · 배율 100% 모니터" 한 가지에 맞춰져 있다.** 셸 메뉴 220px·상세 패널 420px·그리드 열 합 1170px 이 모두 고정이라, **그리드가 열을 다 보여 주는 건 CSS 폭 1870px 이상(=1920 @100%)뿐**이고 노트북·배율 125/150%·브라우저 확대에서는 가로 스크롤, 21:9 울트라와이드에서는 그리드 오른쪽에 **약 1580px 빈 공간**이 생긴다 [실측]. 미디어 쿼리는 로그인에만 있다 [코드].
해결은 큰 개편이 아니라 **① 레이아웃 크기를 토큰으로(docs/12 V1 tokens.css 에 함께) ② 셸 메뉴 접기 ③ 상세 패널 폭 유동화 + 좁으면 아래로/서랍으로 ④ 그리드 넓으면 채우고 좁으면 우선순위 낮은 열부터 양보 ⑤ 해상도 매트릭스 테스트** 다섯 가지다. 셸이 탭마다 iframe 이라 **업무 화면 안의 미디어 쿼리는 창이 아니라 "작업 영역" 폭에 반응한다** — 컨테이너 쿼리를 따로 쓰지 않아도 메뉴를 접으면 화면 배치가 저절로 따라온다는 이점이 있다 [코드·추정].

## 1. 대상 해상도 → 실제 CSS 화면 크기

브라우저는 **물리 픽셀이 아니라 CSS 픽셀**로 배치한다. CSS 폭 = 물리 폭 ÷ (Windows 배율 × 브라우저 확대). 높이는 브라우저 틀(탭·주소창·북마크 ≈ 85~130px, Windows 작업 표시줄 40~48px)을 빼야 한다 [지식]. 아래 높이는 Chrome 최대화 + 작업 표시줄 기준 어림값이다.

| # | 장비 | 물리 해상도 | 배율 | CSS 화면(폭×높이 어림) | 비고 |
|---|---|---|---|---|---|
| R1 | 구형·보급 노트북 | 1366×768 | 100% | **1366×641** | 사무실 노트북에서 아직 흔함 [추정] |
| R2 | 13~14" 노트북 | 1440×900 | 100% | 1440×773 | |
| R3 | 15.6" FHD 노트북(Windows 기본 125%) | 1920×1080 | 125% | **1536×737** | 과제 문서의 "1536×864" 는 이 장비의 CSS 화면 크기다(물리 1536×864 장비는 드묾) |
| R4 | 24" FHD 모니터 | 1920×1080 | 100% | **1920×953** | 현재 화면이 맞춰진 유일한 크기 |
| R5 | FHD 노트북 150% | 1920×1080 | 150% | **1280×593** | 13" FHD 노트북 기본값 [지식] |

### 2.2 셸 + 거래처관리 실측 [실측]

그리드가 보여 주는 폭 ≈ **CSS 폭 − 700px**(메뉴 220 + 화면 여백 32 + 상세 420 + 간격 24 + 테두리). 열 합 1170px 을 다 보려면 CSS 폭 ≥ 약 1870px.

| 화면 | CSS 크기 | 그리드 보이는 폭 | 안 보이는 열 폭 | 보이는 행 | 상세 패널 | 판정 |
|---|---|---|---|---|---|---|
| Z1 1366 + 150% | 911×475¹ | **210px** | 960px | **3** | 420(그리드의 2배) | ✗ 사실상 못 씀 |
| R8 세로 FHD | 1080×1793 | 394px | 776px | 30+² | 420 | ✗ 그리드가 패널보다 좁음 |
| 1024×640 | 1024×640 | 323px | 847px | 11 | 420 | ✗ |
| R5 FHD 150% | 1280×593 | 579px | 591px | 9 | 420 | △ 거래처코드·명·구분·사업자번호까지 |
| R1 1366×768 | 1366×641 | **666px** | 504px | **11** | 420 | △ |
| R2 1440×900 | 1440×773 | 739px | 431px | 15 | 420 | △ |
| R3 FHD 125% | 1536×737 | 835px | 335px | 14 | 420 | △ 대표자·전화까지 |
| R4 FHD 100% | 1920×953 | 1219px | 0 | 22 | 420 | ○ (빈 폭 49px) |
| R6 QHD | 2560×1313 | 1874px | 0 | 30+² | 420 | △ **빈 폭 704px** |
| R7 21:9 | 3440×1313 | 2754px | 0 | 30+² | 420 | ✗ **빈 폭 1584px**, 상세가 그리드 내용에서 2000px 떨어짐 |

¹ 브라우저 확대는 브라우저 틀을 키우지 않으므로 실제 높이는 ≈427 로 더 낮다. ² 모형 데이터가 30행이라 30 에서 멈춤 — 실제로는 R6·R7 ≈ 37행, R8 ≈ 54행(페이지 크기 50).

- 조회 조건 줄은 폭 911 에서 두 줄로 접혀 69 → 126px 가 된다(그리드 높이를 더 깎음).
- 몸통 가로 넘침(`body.scrollWidth > clientWidth`)은 어느 크기에서도 0 — 가로 스크롤은 그리드 안에서만 생긴다. WCAG 1.4.10 리플로는 **표처럼 2차원 배치가 필요한 부분의 가로 스크롤을 예외로 허용**하므로 그리드 자체 스크롤은 위반이 아니다 [검색 W1]. 다만 **화면 나머지(조회 조건·상세 폼)는 좁은 폭에서도 세로로만 흘러야** 한다 — 상세 패널 420px 고정은 이 점에서 약하다.

### 2.4 그 밖 화면 [코드]

- **내 정보·오류 화면**(`hb-page`): 본문 `max-width: 520px` 구간 위주 — 넓은 화면에서 왼쪽에 몰리지만 읽기엔 적절. 
- **활용 현황·지원 허락**(`hb-page-scroll`): `.hb-table width:100%` 라 울트라와이드에서 줄이 너무 길어진다(숫자 열이 오른쪽 끝으로 멀어짐).
- **운영자 콘솔**(`hb-ops`): 같은 표 규칙. 운영자 화면은 주로 모니터에서 쓰므로 읽기 폭 상한이 더 중요 [추정].
- **편집 그리드 PoC**(`dev/grid-poc.html`): 개발용이라 대상 아님.
- **고DPI**: 래스터 이미지 없음(SVG 만) — 선명도 문제 없음. 125%·150% 에서 1px 선은 1.25·1.5 물리 픽셀이 되어 두께가 줄마다 달라 보일 수 있다 [지식]. 그리드 선 색(#eef2f7)이 매우 옅어 150% 노트북에서 행 구분이 흐려질 수 있음 — docs/12 의 `--hb-border-subtle` 대비 검토 때 같이 본다.

### 3.2 밀도

- **Fiori**: 마우스·키보드 데스크톱 = **compact**, 터치 = cozy(44px), 표 전용 **condensed** 는 더 낮은 행. 글자 크기는 compact 에서도 그대로, 컨트롤·간격만 줄인다 [검색 S2]. 하이브리드 기기는 사용자 설정 "터치 입력에 최적화" [검색 S2].
- docs/12 1.4·5.3 결론과 같다(compact 13px 기본 + normal). **밀도는 해상도로 자동 전환하지 않는다** — 화면이 작다고 compact 를 강제하면 터치 노트북 사용자가 손해 [추정]. 해상도 구간은 **배치**만, 밀도는 **사용자·단말 설정**으로 분리한다(4.1).

### 3.3 넓은 화면 — 상한(letterbox)이냐 꽉 채우기냐

- **Fiori 레터박싱**: 앱을 1280px 로 묶고 양옆을 비우는 방식이 SAPUI5 기본이었으나 Fiori 2.0 부터 선택 사항. "내용이 적거나 늘리면 사용성이 나빠질 때" 상한, **데이터가 많은 앱은 전체 폭**. 자주 오가는 화면끼리 방식을 섞지 말 것 [검색 S4].
- **Carbon**: 1584(max) 이후 열 수는 그대로, 여백만 늘어남 [검색 C1].
- 결론 [추정]: **그리드·목록 화면 = 꽉 채움**, **폼·문서형(내 정보·설정·운영 콘솔 보고) = 읽기 폭 상한**. 단 같은 화면 안에서는 섞지 않는다.

### 3.4 표·그리드

- **Fiori 반응형 표**: 열마다 `importance`(High/Medium/Low) — 좁아지면 Low 부터 행 아래 "팝인"으로 내리거나 숨김, High 최대 3개는 항상 보임, 최소 1열은 팝인 금지. 표가 화면 전체 폭이 아니면 `contextualWidth` 로 **표가 놓인 공간 폭**을 기준으로 삼는다 [검색 S1].
- 반면 Fiori **그리드 표(sap.ui.table)** 는 열을 숨기지 않고 가로 스크롤 + 고정 열 — 데이터 집약 업무용 [검색 S1·지식]. MES 사무 화면은 이쪽에 가깝다.
- **AG Grid**: `sizeColumnsToFit`(넓으면 늘림, 좁으면 줄임, 열별 `suppressSizeToFit`·min/max), 그리드 폭 변화 때 최소 폭 합으로 넘치는 열을 숨기는 예제 [검색 G1].
- **Wijmo FlexGrid**: 좁은 화면에서 **고정 열이 보이는 영역을 너무 많이 차지하면 고정을 푼다** [검색 G2].
- **WCAG 1.4.10**: 표의 2차원 스크롤은 예외, 단 셀 내용·표 밖 내용은 리플로 대상 [검색 W1].

### 3.5 사이드 메뉴

- **Carbon UI Shell**: 1056(lg) 이상 상시 펼침, 미만·약 175% 확대 이상은 햄버거 뒤로. 아이콘만 남기는 **rail** 변형. 알려진 함정: 펼침/접힘 상태를 기억하지 못함, 레일이 페이지를 덮어 배치에 영향 없음, Esc 로 닫기 누락, 헤더와 사이드 메뉴의 브레이크포인트 불일치 [검색 C2].
- 결론 [추정]: **접힘 상태 기억 + 같은 브레이크포인트 한 곳 정의 + Esc 닫기 + 포커스 관리**를 처음부터 넣는다.

### 4.1 두 축: "배치 구간"과 "밀도"는 따로

| 축 | 정하는 것 | 결정 주체 | 바뀌는 것 |
|---|---|---|---|
| **배치 구간**(이 문서) | 메뉴 펼침/접힘, 상세 패널 위치·폭, 폼 열 수, 그리드 채우기/양보 | **사용 가능한 폭·높이**(미디어·컨테이너 쿼리) | 레이아웃 토큰(`--hb-layout-*`)과 배치 규칙 |

### 4.3 레이아웃 토큰 (docs/12 tokens.css 에 추가)

docs/12 5.3 의 간격·글꼴 토큰 옆에 **레이아웃 층**을 둔다. 값은 이 파일에만, 다른 CSS 는 `var()` 로만(docs/12 V1 가드와 같은 원칙).

```css
/* tokens.css — 레이아웃 (밀도와 독립) */
:root {
  --hb-layout-header-h: 44px;
  --hb-layout-menu-w: 220px;
  --hb-layout-menu-rail-w: 56px;
  --hb-layout-page-pad: 12px 16px;
  --hb-layout-split-gap: 12px;
  --hb-layout-side-w: clamp(380px, 30%, 480px);
  --hb-layout-read-max: 72rem;          /* 문서형 화면 읽기 폭 상한(≈1152px) */
  --hb-layout-drawer-w: min(100%, 480px);
}
@media (min-width: 1920px) { :root { --hb-layout-menu-w: 240px; } }
```

- CSS 변수는 `@media` 조건 자리에 쓸 수 없다 → **브레이크포인트 숫자는 tokens.css 주석 표 + 이 문서 4.2 가 원본**, 각 CSS 의 `@media` 는 그 숫자를 그대로 쓴다. 가드 테스트로 "허용 목록(1024·1366·1920·900·1280·1800 등) 밖의 `@media` 폭 숫자 금지"를 걸면 산발을 막는다 [추정].
- 화면 안 `@media` 가 iframe 기준이라는 점을 skill `checklists.md` §2 에 적어 둔다(새 화면 작성자가 창 기준으로 착각하지 않게).

### 4.4 셸 규칙

1. **메뉴 접기**: `.hb-body[data-menu="rail|open|overlay"]` 같은 **속성**으로 상태 표현 → CSS 속성 선택자로 폭 전환(CSP 무관, 인라인 style 없음). 상태는 `localStorage`(기기별, 값 검증 — 이상한 값이면 기본). 회사·사용자 서버 저장은 불필요 [추정].
2. 레일 모드: 폴더 아이콘(Lucide, docs/12 V7) + 툴팁(`title` 대신 `aria-label` + 포커스 시 보이는 라벨), 폴더 클릭 시 덮개로 하위 메뉴.
3. 덮개 모드: `dialog` 또는 `aria-modal` 패널, Esc 닫기, 열 때 첫 항목에 포커스, 닫으면 메뉴 버튼으로 복귀(Carbon 의 알려진 결함 회피 [검색 C2]).
4. 메뉴 상태 변경 → iframe 폭이 바뀜 → 각 화면의 `@media`·`ResizeObserver` 가 알아서 반응(셸이 화면에 알릴 필요 없음).
5. 탭 줄: 지금처럼 가로 스크롤 유지 + 탭이 넘칠 때 오른쪽에 "열린 탭 목록" 버튼(선택, P1 후반).
6. **모듈 묶음 접기·펼치기**(사용자 요청 2026-10-22, 시스템관리): 메뉴의 묶음(폴더)은 `<button aria-expanded aria-controls>` — 누르면 그 묶음 `<ul>` 만 접고 편다(Enter·Space 는 버튼 기본 동작), 화살표 ▸/▾ 는 CSS `::before`(인라인 스타일 없음). 접은 묶음은 이 기기 `localStorage` `hb.shell.folders` 에 menuId 목록(JSON) — 메뉴에 있는 묶음 id 만 받아들이고 모르는 값·형식은 버린다(기본 = 모두 펼침). **지금 연 화면(탭)이 든 묶음은 조상까지 자동으로 편다**(접어 둔 것도). 메뉴 위 "모두 접기 / 모두 펼치기" 버튼 하나(모두 접어도 지금 화면 묶음은 보인다). 전체 메뉴 ☰ 접기(1)·덮개(3)와 독립 — 덮개 안에서도 같은 버튼. 계산(저장 값 검증·자동 펼침 경로)은 `shell.menufold.js` 로 나눠 `node --test` 로 시험(`src/test/js/shell.menufold.test.js`).
7. **메뉴 검색**(사용자 요청 2026-10-22, 시스템관리): 메뉴 맨 위 `<input type=search>`(숨은 label, 자리표시 "메뉴 찾기 ( / )"). 메뉴 이름 + 화면 코드 부분 일치 — 대소문자·공백 무시, 한글 그대로(초성 검색 없음). 맞는 화면이 든 묶음은 **접힘과 상관없이** 펼쳐 보이고 맞는 글자는 `<mark class="hb-menu-hit">`(textContent 로 조립, 인라인 스타일 없음). 검색어를 지우면 원래 접힘으로 돌아간다(접힘 기억 localStorage 는 건드리지 않음, 검색 중 "모두 접기" 는 잠근다). 0건 문구, Enter = 첫 결과 열기, ↑↓ = 결과 이동(맨 위에서 ↑ = 검색 칸), Esc = 검색어 지우기(덮개 닫기보다 먼저), 입력 칸이 아닌 곳에서 `/` = 검색 칸(접힌 메뉴·좁은 화면은 메뉴를 열고). 화면 iframe 안의 `/` 는 셸에 오지 않는다(화면 입력과 겹치지 않음). 계산은 `shell.menufold.js` 의 `search`·`highlight`.
   - 함께 고친 것(2026-10-22 보고 "모두 접기" 가 `js.shell.foldAll` 로 보임): local 프로필은 화면 JS 를 `src/` 에서 바로 읽고 문구는 빌드된 classpath 에서 읽어, git 으로 받은 뒤 리소스를 다시 빌드하기 전에는 새 JS 가 새 키를 못 찾았다. local 만 `happyboot.dev.messages-dir: src/main/resources` 로 JS 문구(`js.*`·`help.*`)도 src 에서 읽는다(jar 운영은 둘이 함께 묶여 해당 없음).

### 4.5 마스터-디테일·폼 규칙

1. `.hb-split-side { flex: 0 0 var(--hb-layout-side-w); }` — 고정 420 제거.
2. `area-s`: `.hb-split` 을 세로로, 상세는 서랍(`.hb-split-side[data-open]`). 선택 행이 바뀌면 열리고, **미저장(`hb.dirty`)이면 닫기 전 확인** — 기존 `beforeSelect` 흐름 재사용.
3. 상세 패널에 `container-type: inline-size; container-name: detail;` → 
   `@container detail (min-width: 560px) { .hb-form { grid-template-columns: repeat(3, 1fr); } }` / `(max-width: 340px)` 1열. 담당자 행(`.hb-row`)은 `(max-width: 420px)` 에서 두 줄 배치(이름·구분·전화 / 메일·대표·삭제).
4. 조회 조건은 `repeat(auto-fit, minmax(10rem, max-content))` 대신 지금의 flex-wrap 유지 + `area-s` 에서 접기. 조건 수가 많은 P1 화면(품목 등)은 "자주 쓰는 조건 1줄 + 더보기" 규칙 [추정].
5. 도움말 패널(`.hb-help`): `area-s` 에서는 하단 시트(폭 100%, 높이 40%), 그 외엔 지금처럼 오른쪽 아래. 그리드 위를 덮는다는 점은 그대로 두되 닫기 단축키(Esc) 추가.
6. 문서형 화면(`hb-page`, `hb-page-scroll`, `hb-ops`): 본문 `max-width: var(--hb-layout-read-max)` + 왼쪽 정렬(가운데 정렬은 셸의 왼쪽 메뉴와 시선이 멀어짐) [추정]. 표는 그 폭 안에서 100%.

### 4.6 그리드(hb.grid) 규칙

| 상황 | 규칙 | 구현 메모 |
|---|---|---|
| **넓을 때**(열 합 < 보이는 폭) | 남는 폭을 열에 나눠 채운다. 기본은 `flex` 지정 열(예: 거래처명·주소·비고)만, 없으면 전체 비례 | 가장 싼 방법: `table.style.width` 를 열 합으로 고정하지 말고 `table.style.minWidth = 열 합` + CSS `.hbg-table { width: 100%; }` → `table-layout: fixed` 가 남는 폭을 열 비율대로 나눔. 열별 `maxWidth` 가 필요해지면 JS 계산으로 |
| **좁을 때** | 기본은 **가로 스크롤 + 첫 열 고정**(MES 사용자는 열이 사라지는 것보다 스크롤을 선호 [추정], Fiori 그리드 표 방식). | 지금과 같음 |
| 고정 열이 과함 | 고정 열 합이 보이는 폭의 40% 초과면 고정 해제(Wijmo 방식 [검색 G2]) | `ResizeObserver` 로 `.hbg-locked` 클래스 토글 |
| **열 맞춤**(사용자 선택) | 그리드 메뉴 "열 맞춤": `priority` 3 → 2 순으로 숨겨 보이는 폭에 맞춤, 다시 누르면 원래대로. 숨긴 열 수를 바닥줄에 "열 3개 숨김" 으로 표시 | Fiori `importance` + AG Grid 숨김 예제 [검색 S1·G1] |
| 열 정의 | `ColumnSpec` 에 `priority`(1 항상·2·3, 기본 2), `minWidth`, `flex`(bool) 추가. 거래처관리: 코드·명 = 1, 구분·사용·전화 = 2, 대표자·사업자번호·담당자 수·수정일시·수정자 = 3 | 서버 열 정의 API 에 필드 추가(하위 호환) |
| 열 폭 저장 | 저장은 지금처럼 px, **적용 시 보이는 폭보다 열 합이 크면 `flex` 열부터 기본 폭으로 되돌림**, 또는 저장 키에 폭 구간(`area-l`/`area-xl`) 포함 | 다른 기기 문제(2.1) 해결. 단순한 쪽(되돌림) 권고 |
| 행 높이 | docs/12 밀도 토큰 `--hbg-row-h` 그대로 | 해상도로 바꾸지 않음 |
| 페이지 크기 | 기본 50 유지, `tall` 에서 100 제안(사용자 저장값 우선) | |
| 엑셀 열 폭 | 화면 폭과 무관(지금처럼 `ColumnSpec.width`) | |

- CSP: 폭·위치는 지금처럼 **CSSOM(`el.style.width`)** 으로만 — 템플릿의 `style` 속성·`<style>` 블록이 아니므로 `TemplateSecurityGuardTest` 와 `style-src 'self'` 를 그대로 지킨다 [코드].

### 4.7 글자 크기·`clamp()` 쓰는 곳 / 안 쓰는 곳

- **업무 본문·그리드 글자에는 `clamp()`·`vw` 를 쓰지 않는다.** 화면 폭에 따라 13px 이 14.3px 이 되면 밀도 예측이 깨지고, OS 배율·브라우저 확대가 이미 크기를 조정한다 [추정]. 크기 선택은 밀도 설정(13/14)으로.
- `clamp()` 를 쓰는 곳: 레이아웃 폭(상세 패널·서랍), 로그인 제목·브랜드 슬로건, 대시보드 KPI 숫자, 안돈(docs/12 2.2 거리 공식과 함께).
- 단위: 레이아웃 토큰은 px(4의 배수 — 125/150% 에서 정수 물리 픽셀 [검색 M2]), 읽기 폭은 `rem`, 입력 최소 폭은 `ch`.
- **rem 전환 검토**(5.5): 글꼴 토큰을 px → rem(13px = 0.8125rem)으로 바꾸면 브라우저 "글꼴 크기" 설정까지 따른다. docs/12 토큰 도입 때 한 번에 바꾸는 게 가장 싸다.

### 4.8 `dvh`

- 셸 `html, body { height: 100% }` 와 업무 화면 `height: 100vh`(iframe 안)는 데스크톱에선 문제 없다.
- 태블릿 브라우저(결재·현장 조회)와 POP 에서는 주소창이 생겼다 사라지며 `100vh` 가 실제보다 크다 → `height: 100vh; height: 100dvh;` 두 줄(앞이 대체값)로 쓴다. 로그인 `min-height: 100vh` 도 같은 방식 [지식].

## 5. 세부 메모

### 5.1 왜 컨테이너 쿼리보다 iframe `@media` 가 먼저인가
탭마다 iframe 이라 업무 화면 문서의 뷰포트 = 작업 영역이다. 따라서 `page.css` 의 `@media (max-width: 900px)` 는 "작업 영역이 900 미만" 을 뜻하고, 메뉴를 접거나 펼치면 자동 재평가된다 [코드]. 컨테이너 쿼리는 **화면 안의 부품**(상세 패널 속 폼, 대시보드 카드)에만 쓰면 된다. 나중에 iframe 을 버리고 SPA 식 셸로 바꾸면 그때 `@media` → `@container` 로 옮겨야 한다 — 그 비용을 줄이려면 구간 이름(`area-*`)을 주석으로 붙여 둔다 [추정].

### 5.2 1366 노트북 개선 전후 어림 [계산]
그리드 보이는 폭 = 1366 − 메뉴 − 여백 32 − 상세 − 간격·테두리 24.
- 지금: 1366 − 220 − 32 − 420 − 24 ≈ **666**(실측과 일치)
- 메뉴 레일 + 상세 clamp(380, 30%, 480): 작업 영역 1310 → 상세 393 → 1366 − 56 − 32 − 393 − 24 ≈ **861**
- `area-m` 규칙(1310 은 area-l 이므로 해당 없음). 열 합 1170 대비 74% 표시 — 거래처코드·명·구분·사업자번호·대표자·전화까지 보임.
- `short` 압축으로 행 11 → 약 12~13.

### 5.3 울트라와이드 [실측·추정]
3440 에서 그리드 2754px·열 합 1170px. 채우기 적용 시 열이 2.35배로 늘어 거래처명 열이 500px 를 넘는다 — 너무 늘어나는 것도 읽기에 나쁘므로 `flex` 열만 늘리고 **그 외 열은 `maxWidth`(기본 폭의 1.5배)** 에서 멈춘 뒤 남는 폭은 상세 패널 상한(640)과 폼 3열로 쓴다. 그래도 남으면 그리드 오른쪽 여백을 허용(빈 셀보다 낫다). 3열 FCL(목록-상세-하위 상세)은 P1 BOM·라우팅처럼 3단 구조 화면이 생길 때 검토 [추정, 검색 S3].

### 5.4 세로 모니터
작업 영역 860×1712. `area-s` 이지만 세로가 넉넉하므로 아래 쌓기(그리드 위 55%·상세 아래 45%). 공장 사무실의 세로 모니터는 주로 문서·도면 보기용이라 우선순위는 낮다 [추정].

### 5.5 글꼴 크기 설정과 px
브라우저 확대(Ctrl +)는 px 도 키우므로 WCAG 1.4.4(200% 확대)는 지금도 충족 가능하다. 다만 브라우저 설정의 "글꼴 크기"(기본 16px 변경)는 px 글꼴을 바꾸지 못한다. 업무 화면에서 이 설정을 쓰는 사용자는 드물지만 비용이 토큰 도입 때 거의 0 이므로 rem 권고 [추정]. Windows "텍스트 크기"(접근성) 설정이 Chromium 웹 내용에도 반영되는지는 확인하지 못했다 — T9 수동 점검 때 함께 본다.

### 5.6 로그인 보정 (메인 세션 입력용)
1. `@media (max-height: 640px) and (min-width: 901px)` → 기준을 **720px** 로 올리고 그림 높이에 `max-height: 38vh` 를 주면 1366×641 에서 브랜드 패널 잘림이 사라진다.
2. 낮은 화면(`max-height: 520px`)에서 `.login-logo` 숨김·`h1` 22px·부제 여백 축소 → 911×427 에서 버튼을 첫 화면에 넣을 수 있다(현재 516 → 약 400 어림).
3. 900px 미만 머리띠: 패널 높이가 내용보다 작아 슬로건이 잘림 — `overflow: hidden` 을 머리띠 모드에서 풀거나 슬로건을 한 줄 말줄임.
4. 울트라와이드: `grid-template-columns` 에 브랜드 패널 상한(예: `minmax(0, min(1.15fr, 960px))`)을 두거나 그대로 두어도 기능 문제는 없음(선택).
5. `min-height: 100vh` 뒤에 `min-height: 100dvh`.

## 7. 하지 않을 것

- **모바일 폰 대응**(320~480px): 사무 화면은 대상 밖. 폰은 P2 POP·조회 전용 화면으로 따로 [추정]. 단 WCAG 리플로 때문에 그리드 밖 요소가 320 에서 깨지지 않는 정도는 지킨다.
- **화면 폭 비례 글자(`vw`)**: 4.7.
- **해상도별 별도 템플릿**(적응형 레이아웃 파일 분리): CSS 구간으로 충분.
- **CSS 프레임워크 그리드 도입**(Bootstrap 등): 자체 CSS + 토큰으로 충분, 의존성·CSP 검토 비용만 늘어남.
- **Fiori 식 팝인(행 아래로 열 내리기)**: 편집·정렬·엑셀과 충돌이 커서 hb.grid 에는 "열 맞춤(숨김)" 까지만.
