## 고객 반품 동시 넘침 시험 흔들림 (2026-11-03, 브랜치 claude/wms-custrtn-race)

증상: main 6ccc6c74 전체 check(3,058건) 중 한 번 `CustRtnTest#넘침_같은_요청_다른_내용_동시_두_건` 이 [200, 409] 대신 [200, 200]. 단독 실행은 통과.

원인(근본 레이어 = **시험 도우미**, 제품 결함 아님): `req()` = `"crt-" + (++seq) + "-" + System.nanoTime()` 을 두 작업 스레드가 동시에 불렀다. `++seq` 는 원자 연산이 아니고 Windows `nanoTime` 해상도는 약 100ns 라 두 스레드가 **같은 요청 id** 를 받을 수 있다(같은 식을 래치로 동시에 2만 번 → 0회·3회 충돌). 그러면 두 번째 요청은 잠금 뒤 `findByReq` 가 첫 요청(같은 출하 행·LOT·수량 3·칸·사유)을 찾아 "같은 요청 다시 = 처음 결과" 200 을 돌려준다 — 반품은 실제로 한 건(합 4)이고 출하량을 넘지 않았다. 서버 경로 근거: `CustRtnService.receive` 출하 머리 `lockShipShare`(FOR SHARE) → `lockShipLine`(트랜잭션 advisory) → `findByReq` → `source` 를 **새 문장으로** 다시 읽어 `open_qty` 비교(READ COMMITTED — 잠금을 기다린 뒤 시작한 문장은 앞 트랜잭션의 커밋을 본다. SKILL §2 "FOR UPDATE 와 같은 문장 안의 집계" 함정에 해당하지 않음), `source`·`findByReq` 는 `flushCache="true"`.

고친 것: `seq` → `AtomicInteger`, 동시 시험의 요청 id 는 시작 스레드에서 만들고 서로 다름을 먼저 확인.
