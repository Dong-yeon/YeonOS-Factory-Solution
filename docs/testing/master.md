**고칠 것**

1. **숫자 칸 화면 검사를 저장 전에 하지 않는 화면** — 자격(`validMonths`)·금형/게이지(`calibCycleDays`) 등 `data-hb="number"` 칸이 범위 밖이면 값이 `null` 로 나가 "만료 없음/주기 없음"으로 **조용히 저장**. 품목 화면처럼 저장 전에 `hbNumber.validate()` 실패면 보내지 않게(공통으로 `hb.form` 수준에서 막는 편이 재발 방지). 같은 패턴 화면을 grep 해서 함께.
2. **저장 성공 알림이 상세 다시 읽기보다 먼저** — 라우팅(단계 저장·헤더 저장)·특성 저장은 `reloadAndShow`/`reload(false,id)` 뒤 그리드 `onSelect` 의 상세 읽기를 기다리지 않는다. 그 사이 [신규]를 누르면 늦게 온 상세가 신규 폼을 덮고 `current` 가 되돌아가 다음 저장이 이전 행 PUT. 제안: 알림을 상세 읽기 뒤로(품목·거래처처럼) + [신규]가 `hb.latest('detail')` 를 무효화.
3. **확정본만 있는 모품목에 BOM 엑셀 올리기** — 빈 작성 중 리비전에 파일 줄만 넣는다. 사용자는 "한 줄 추가"로 생각하기 쉽고, 확정하면 기존 구성이 사라진다. 제안(정책 결정): 확정본을 복사한 새 리비전에 반영하거나, 검증 결과에 "확정본 A0(3줄)과 별개로 새 리비전이 파일 줄만으로 만들어집니다" 경고 + 확정 확인창에 이전 확정본과 줄 수 차이 표시.

**정책 질의·관찰**: O1 이름 칸 보이지 않는 문자, O2 같은 사업자번호, O3 라우팅 PUT 이 품목 변경을 조용히 무시, O4 사용 중 공정·품목 중지 때 사용처 안내, O5 하위 BOM 미확정 상태의 상위 확정·구매품 BOM, O6 전개 화면 오류 칸 표시, O7 약한 PIN·로그인 중복 연결, O8 설비 클래스 필수 표시·미래 설치일·시리얼 중복, O9 DB 장애 시 스택 노출(로컬).

**J 입력 부담 기준선(손 조작 기준, 최소)**: 거래처 신규 = 신규 → 코드·이름 → 저장 (클릭 2 + 입력 2). 품목 신규 = 신규 → 코드·이름·유형·단위·조달 → 저장 (클릭 2 + 입력 5). BOM 3줄 확정 = 신규 → 모품목 → 저장 → [행 추가 → 코드 → 수량]×3 → 행 저장 → 확정 → 확인 (약 16동작, 화면 1). 라우팅 3단계 확정 = 신규 → 품목·공장 → 저장 → [단계 추가 → 공정 → 작업장 → CT]×3 → 단계 저장 → 확정 → 확인 (약 20동작, 화면 1 — 작업장이 확정 때만 필수라 저장 뒤에야 알게 됨).
